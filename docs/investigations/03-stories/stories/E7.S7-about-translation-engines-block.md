# Story E7.S7: About tab — the "Translation engines" block

Status: **done**

_Epic E7 (G) — Degraded-mode UX · increment 6 · **Release B.2** · the owner's Phase-4 go was given 2026-09-06
(`README.md` § Phase 4)._

> **The layout decision is already made, and it is a "no": no settings window, no sixth tab.** §4.1: *"Everything
> stays in the About tab … the tab order is fixed by `project-context.md` and referenced by
> `MainTabs_SelectionChanged`."* The existing heading **"Better translations (optional)"**
> (`MainWindow.xaml:611`) becomes **"Translation engines"** with three blocks: *what is being used* (read-only),
> *your keys*, *offline engine*.
>
> **And principle 2 governs the whole story:** *"Many users will never open it — which is exactly why nothing in
> the degraded-mode flows may **require** it."* AC 4 states it as an acceptance criterion. This tab is where the
> chip's glyph gets explained **in full**, not where anything gets fixed.
>
> **It is also the story that finally makes `UpdateEngineStatusUi()` earn its name.** E6.S3 creates it as a
> two-line refresh at exactly the place `UpdateOcrFilterUi` is called from `ApplySettings`; E6.S4 adds the
> opt-in's side effect; this story grows it into the "In use now" + "Chain" pair. **Three stories, one method,
> one call site** — which is the shape that keeps I12's "apply UI side effects explicitly" testable.

## Story

As a curious player,
I want one place that says which engine is being used and what the order is,
So that the chip's glyph has somewhere to be explained in full.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E7.S7. Do not weaken._

1. **Given** UX-DR15 and §4.1
   **When** the About tab is restructured
   **Then** **everything stays in the About tab** — no settings window, no sixth tab; the tab order fixed by
   `project-context.md` and referenced by `MainTabs_SelectionChanged` is unchanged; the existing "Better
   translations (optional)" heading becomes **"Translation engines"** with three blocks: *what is being used*
   (read-only), *your keys*, *offline engine*.
2. **Given** the mockup of §4.2
   **When** the block renders
   **Then** it shows an `In use now` line (chip + reason) and a read-only `Chain` line
   (`Google → Edge → Google (old) → Offline (not installed)`), both refreshed by `UpdateEngineStatusUi()`.

   **Then** it reads *"By default everything runs on free engines — no key, no signup, nothing to set up."* and
   the keys block states *"Keys are stored only on your PC."*
4. **Given** principle 2
   **When** any degraded-mode flow runs
   **Then** **none of them requires the user to open this tab** — many users never will.

### Repo traps

- **`MainTabs_SelectionChanged` must filter `e.Source is TabControl`** — `project-context.md` calls it out, and
  T2's "only while the About tab is selected" rule makes this the first story in a while that reads the
  selection. **Do not remove or bypass the filter**; a `TabControl`'s `SelectionChanged` bubbles from every
  `ComboBox` inside it, and the region combo E6.S3 added is inside this very tab.
- **`s.LastTab` is persisted and restored** (`MainWindow.xaml.cs:229-230`, `AppSettings.LastTab`). A user whose
  last tab was About lands here at startup — so anything expensive on tab-selection runs on their launch path.
  Keep it to a text compose.
- **The dark `ToolTip` style in `Theme.xaml` is load-bearing** — if the Chain line grows a tooltip, plain text
  only.
- **The About tab is one long `StackPanel` inside a `ScrollViewer`.** Adding blocks pushes "Something went
  wrong?" (`:628`) and "Made by Kizotis" (`:640`) down. That is fine — but the error-report button is a support
  path and should not end up below the fold on a small window. Check at 800×600.
- **`GhostButton` + `Padding` is the button idiom here** (`:622-623`, `:636-637`).
- No `.sln`; `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact.
