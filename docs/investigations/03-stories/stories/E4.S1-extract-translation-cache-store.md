# Story E4.S1: Extract the LRU into `TranslationCacheStore`

Status: **done**

_Epic E4 (D) — Shared persistent cache · increment 3 · **Release A.2 (E4 + E5)** · the owner's Phase-4 go was
given 2026-09-06 (`README.md` § Phase 4)._

> **This story changes no behaviour at all, and that is its acceptance criterion.** It moves a data structure out
> of a decorator so that E4.S2 can persist it and E4.S4 can share it. The proof that it moved cleanly is that
> `CachingTranslatorTests`' seven cases pass with **zero edits** — the DoD is literally "green with zero edits".
>
> Read `Services/CachingTranslator.cs` in full before writing anything. It is 127 lines, it is the oldest
> unbroken thing on the translation path, and every one of its comments is a bug that was paid for once.

## Story

As the maintainer,
I want the cache data structure to live outside the decorator,
So that two decorators can share one, without changing what a decorator means.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E4.S1. Do not weaken._

1. **Given** the LRU currently lives inside `Services/CachingTranslator.cs:15-29,103-126`
   **When** it moves into `Services/TranslationCacheStore.cs`
   **Then** the key stays **unchanged** — `source + "|" + target + "|" + text.Trim()` (`CachingTranslator.cs:73-78`)
   — and the capacity becomes 2000 (was 500, memory only).
2. **Given** I4
   **When** a value starting with `(` is offered
   **Then** it is not stored, and **the `(`-prefix rule stays in `CachingTranslator`**, not in the store (§3.1
   responsibility table).
3. **Given** `CachingTranslator` keeps its existing constructor and gains a store-taking one
   **When** the change lands
   **Then** `tests/PWRUHelper.Tests/CachingTranslatorTests.cs` (7 cases, `:45,57,69,83,97-109,112`) passes
   **unchanged**.

## The one decision AC 1 and AC 3 look like they contradict

AC 1 says "the capacity becomes 2000". AC 3 says the existing constructor keeps working and its seven tests pass
unchanged — and one of those tests (`Least_recently_used_entry_is_evicted_first`, `:112`) drives the **default**
capacity, while `TranslationPolicyTests.The_call_sites_that_now_read_the_policy_still_behave_identically`
(`:111-123`) asserts by reflection that the single `CachingTranslator` constructor's `capacity` parameter still
defaults to **500**.

They do not contradict. **2000 is the STORE's capacity, not the decorator parameter's default.**

| | Capacity | Who sets it |
|---|---|---|
| `new CachingTranslator(inner)` — the legacy ctor | `TranslationPolicy.CacheCapacityToday` (500), its own private store | unchanged, kept for the 7 tests and for any call site that has no store |
| `new CachingTranslator(inner, store)` — the new ctor | whatever the store was built with; `new TranslationCacheStore()` = `TranslationPolicy.CacheCapacity` (2000) | E4.S4's shared instance |

Do **not** raise the legacy default to 2000: that reflection assert would fail, and the `capacity` parameter would
then be a second, disagreeing source of truth for a number §8.2 puts in one place.

## Dev Notes

### Invariants this story must keep

- **I4 — only successes are cached.** The rule stays in the decorator (AC 2). The store is deliberately dumb: it
  will store whatever it is handed, which is exactly why the guard may not move into it — E4.S4 gives three
  decorators one store, and a rule that lives in one place upstream of all three cannot be forgotten by one.
- **I2** — `Services/` stays UI-free. The store takes a capacity and, in E4.S2, a path. Nothing else.
- **I1** — `ITranslator` is untouched. This story does not go near it.
- **I10** — nothing new at startup. This story adds **no** I/O at all: the store is a `Dictionary` and a
  `LinkedList` until E4.S2 gives it a file. Keep it that way; a `Directory.CreateDirectory` sneaked in here would
  be an I10 violation two stories before anybody is looking for one.

### Rulings that apply

- **§3.1 responsibility table** — key construction and the `(`-prefix rule belong to `CachingTranslator`; storage,
  eviction and (from E4.S2) persistence belong to `TranslationCacheStore`.
- **IS-2** (test-plan §2) — the store must take an **explicit path**. That is E4.S2's; this story only has to not
  design a shape that makes it awkward. A ctor that already takes `(int capacity)` takes
  `(int capacity, string? path)` next without a breaking change.

### Repo traps

- **`TranslationPolicyTests` reads `TranslationPolicy.cs` as TEXT** (`:53-80`). A new constant with no grade, or
  with two grade words in its comment block, fails a test that has nothing to do with the cache. One grade,
  exactly.
- **The reflection assert on the ctor.** `TranslationPolicyTests.cs:120-122` does
  `typeof(CachingTranslator).GetConstructors().Single()` — **`.Single()`**. Adding the store-taking public ctor
  makes that throw `InvalidOperationException` ("sequence contains more than one element"), and the failure
  message will say nothing about the cache. Two ways out, and the story picks the first:
  1. make the new ctor `internal` — `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) means the tests
     and E4.S4's call sites can still reach it, and `GetConstructors()` (public-only by default) still returns
     one; **or**
  2. change the assert to select the ctor by parameter count. That is a deliberate edit of a pin and needs a
     comment saying why.
  Option 1 keeps every existing test file byte-identical, which is what AC 3 is really asking for. Take it, and
  leave a comment on the new ctor saying it is `internal` *because* of that assert.
- **`CachingTranslator` is `public`** (`:15`) and so is its existing ctor. It is used from `MainWindow.*` — that
  is not `Services/`, so `internal` on the *class* is not an option here.
- **`_order.AddFirst` / `_order.Last`** — front is MRU, back is LRU. Invert it and every eviction test still
  passes on a fresh store while a long session evicts the wrong half of the cache.
- No `.sln`; `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact.
