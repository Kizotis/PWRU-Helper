_Epic E8 (H) — Offline fallback prototype · increment 7 · **Release C** · prototype branch, merges only on a go._

> **Nothing else in this epic is worth building before this story's numbers exist.** E8's definition of done says
> both outcomes are successes: a merged opt-in fallback with four published measurements, **or** a closed branch
> with a documented no-go. This is the story that produces the numbers either verdict is written from.
>
> **Why it is `blocked-owner` and not `ready-for-dev`.** It does three things an agent may not decide alone:
> (1) it adds `BergamotTranslatorSharp` — the **only** new NuGet this whole design permits, and only on a branch
> (NFR6); (2) it **downloads ~22 MB of model** from Mozilla's registry onto a real machine; (3) it publishes the
> app two ways to look at `%TEMP%`. Ground rule 2 (`docs/investigations/README.md`) and the Phase-1 incident both
> say the same thing: an agent does not start pulling binaries down a connection the owner has not designated.
>
> **What the owner has to say, in one line:** *"go on the E8 prototype branch — pull the NuGet, download the
> `tiny` ru→en model on my box, and run the harness."* Nothing else about this story is open.
>
> **This is not `blocked-dep`.** E3 shipped; the chain exists. The only gate is the owner's.

## Story

As the owner,
I want the offline engine measured on a real machine before anybody writes a provider for it,
So that a feature that could add 127–310 MiB to a "must not lag the game" app is decided by numbers and not by
how good the idea sounded.

1. `[DERIVED — architecture-cible.md §15.1 U6, benchmark §10]` **Given** a harness under `PWRU_SPIKE=1` only
   **When** it initialises Bergamot `tiny` ru→en from a model downloaded into a temp directory on demand
   **Then** it reports, as a median of ≥ 5 timed runs after a discarded warm-up: **init time**, **per-line
   latency on ~40-character lines**, **throughput in lines/s**, the **working-set and USS delta while the engine
   is resident**, and the **delta after unload**. It reports; it never asserts on a duration (CI-3's TP-START-03
   carve-out).

2. `[DERIVED — I6, benchmark §10's slang table]` **Given** ≥ 20 real PW-RU chat lines
   **When** each is translated **twice** — once raw, once after `SlangGlossary.Expand`
   **Then** both outputs are printed side by side in the harness output, so the expansion's contribution is
   visible rather than asserted. The raw column is expected to be unusable (`данж` → "dangling", `хил` → "heel",
   `спс` → "ps"); the expanded column is what the owner judges in E8.S7.

3. **Verbatim, `epics.md` § E8.S1.** **Given** U7 and §7.6 constraint 4 — bundling the native DLL re-arms
   `IncludeNativeLibrariesForSelfExtract` extraction to `%TEMP%\.net\…`, the exact mechanism implicated in P1
   **When** the prototype is published **both ways** (bundled, and beside the exe)
   **Then** `tools/diagnostics/Measure-Startup.ps1` is run on both, on a personal Defender-only machine,
   reporting run #0 (fresh hash) and warm runs per `mesures-protocole.md`.
   _In this story that is scoped to the **first look**: the file count and total size of
   `%TEMP%\.net\PWRUHelper\<id>` after each first launch, against the **5 WPF native DLLs, 8.2 MB** baseline.
   The full both-layouts cold-start comparison is **E8.S6**, which owns the packaging decision._

4. `[DERIVED — I10, G6]` **Given** the harness
   **When** it runs
   **Then** it proves **0 MB at rest**: with the model on disk and the engine never asked for a translation, the
   process's working set is indistinguishable from a run with no model at all. A number that is only true while
   translating is not the claim this feature is being sold on.

5. **Verbatim, `epics.md` § E8.S4, as the reference figures this harness is compared against.**
   **Given** the reference figures **Then** they are stated for comparison: `tiny` ru→en init 103–119 ms,
   6.5–12.1 ms/line, 64–80 lines/s, **+127 MiB USS and not tunable**; COMET-22 ru→en 0.8497 vs Google 0.8785.

**Exit criterion (measurable).** Five figures, on the dev box, with a machine sheet: init ms · ms/line ·
lines/s · resident delta while active · resident delta after unload. Plus the `%TEMP%` file count and size for
each of the two publish layouts, and the 20-line quality table.

**Go / no-go — the gate the whole epic hangs on.** All five must hold, or the branch closes here:

| # | Criterion | Threshold | Source |
|---|---|---|---|
| 1 | Init on first fallback use | **≤ 500 ms** | derived from §7.6's 103–119 ms with a 4× slow-machine allowance; a longer wait is a visible stall on the first offline line |
| 2 | Per-line latency | **≤ 15 ms/line** | derived from the 6.5–12.1 ms measured; the app needs ~2 lines/s, so this is still a 30× margin |
| 3 | Resident delta while active | **≤ 150 MiB** for the single ru→en configuration | **TP-BRG-02**, `plan-migration.md` increment 7 "Go criteria" |
| 4 | Resident delta at rest / after unload | **≈ 0 MiB** — back to the pre-load baseline | G6, A-1(b) |
| 5 | Exe growth | **≤ 25 MB bundled, or 0 MB with download-on-demand** | §7.6 constraint 4; E8.S6 chooses which |

**Any one failing ⇒ no-go**, and the branch is closed with its numbers recorded in
`docs/investigations/03-stories/spikes/`. **Both outcomes are successes** (`plan-migration.md` increment 7 DoD).

### Two contradictions in the source documents. Both are flagged, neither is resolved by an agent

- **`E8-a` — the RAM ceiling is written twice, at two different numbers.** `plan-migration.md` increment 7's go
  criteria and **TP-BRG-02** both say **≤ 150 MiB while active**. Amendment **A-1(c)** (README, owner, 2026-09-06)
  accepts **+127–310 MiB**, and `architecture-cible.md` §7.6 repeats it. They are not the same gate.
  **Proposed resolution, for Winston:** the **150 MiB** figure binds the **shipping configuration**, which is one
  model (`tiny` ru→en, measured +127 MiB USS) — it passes. The **310 MiB** figure is A-1(c)'s **hard ceiling**,
  which only a RU↔FR pivot (two models resident, two decodes) could approach, and a pivot is **out of scope for
  the prototype**. So: measure `tiny` against 150 MiB; if a language pair is ever added, 310 MiB is the wall it
  may not cross. Until Winston rules, **the harness reports against both** and neither is quietly dropped.
- **`E8-b` — the model directory is written twice, in two different roots.** `ux-mode-degrade.md` §3.6 and §4.2
  and `epics.md` § E8.S3's AC say `%AppData%\PWRUHelper\models` (Roaming — where `settings.json`,
  `provider-state.json`, `translation-cache.json` and the log all live:
  `SettingsService.cs:115`, `ProviderGates.cs:85`, `TranslationCacheStore.cs:112`, `Logging.cs:19`).
  **Winston's Release-C direction says `%LocalAppData%\PWRUHelper\models\` — not Roaming.**
  **Recommendation: LocalAppData, and it is not a preference.** 22 MB of DLL plus 22–37 MB per model is
  machine-local binary data; on a roaming or synced profile it is copied at every logon, which is precisely the
  class of cause this project spent Phase 1 hunting for P1. The consent copy in §3.6 then has to say
  `%LocalAppData%\PWRUHelper\models` — **a copy change, and it belongs to E8.S3 with Sally's sign-off.**
  This story writes to `%TEMP%` and is unaffected; it flags the divergence so E8.S3 does not have to discover it.

### Repo traps

- **`Data/slang.json` is an EmbeddedResource *and* a copy next to the exe** (`PWRUHelper.csproj:45-48`). A test
  reading "the glossary" must read the one the app reads, or the slang column measures a file nobody ships.
- **Do not add `ReadyToRun` and do not re-add single-file compression** to make a startup number look better.
  Both are recorded deliberate non-features (`project-context.md`; `pwru-startup-perf`); compression cost
  ~118 MB of RAM and was removed on purpose in v0.14.0.
- **A measurement on the dev box alone answers half the question**, and this project has a memory note about
  exactly that failure mode (`verify-against-prior-releases`: "measured once, on the fast machine, declared
  fine"). This story is deliberately named "dev-box half"; **E8.S7 is the other half and it is not optional**.
- **`Process.WorkingSet64` alone will mislead you.** Marian allocates its fixed pool on the **first translate**.
  Sampling after `initialize` and calling it "the RAM cost" understates it by most of the number.
- **The dev box is a corporate machine.** Clearing the standby list needs elevation and a reboot is not agent
  work — E4.S3 hit this and carried the cold number to the owner. Do the same rather than inventing a cold
  measurement from a warm one.

## How to verify manually

1. `dotnet test tests/PWRUHelper.Tests` — the suite count and runtime are **unchanged**, and zero cases are
   discovered in `BergamotSpike`.
2. `set PWRU_SPIKE=1 && dotnet test tests/PWRUHelper.Tests --filter Category=Spike --logger "console;verbosity=detailed"`
   — the model downloads once, the five numbers print, and `%AppData%\PWRUHelper\` is untouched.
3. Read the resident delta **after the first translate**, not after init. Compare against +127 MiB.
4. Dispose, collect, re-read: the working set returns to its pre-load value. If it does not, stop — E8.S4 is
   unbuildable and that is the finding.
