# Story E7.S3: The provider chip and its tooltip

Status: **done**

_Epic E7 (G) — Degraded-mode UX · increment 6 · **Release B.2** · the owner's Phase-4 go was given 2026-09-06
(`README.md` § Phase 4)._

> **One `TextBlock`, three placements, eight states — and it is the only always-on indicator in the app.**
> §2.2's first reading rule: *"The chip is the only always-on indicator. The status lines carry a sentence **only
> when the state changes**, and the sentence is then left in place until the next change — no per-message
> repaint."* That is why the chip is worth a story: it lets every other surface go quiet.
>
> **Both seams it needs already ship, and both were built for it by name.**
> `ChainTranslator.LastOutcome` (ruling **R-3**, `ChainTranslator.cs:101-104,117`) —
> `{ProviderId, Skipped: [(ProviderId, Reason)], RetryAt?, Kind?}`, immutable, `Volatile`-read, set after every
> call — its doc comment says *"Nothing reads this yet — E7.S1 / E7.S3 do. It is written now so E7 does not have
> to reopen this file."* And `ProviderGate.Snapshot()` (rulings **OQ-c / R-2**, `ProviderGate.cs:75-84`) —
> `{State, BlockedUntil, Strikes, LastKind}`, *"side-effect free by contract"*, whose comment says *"the status
> chip polls this at 1 Hz from the countdown timer the UX already requires, in E7.S2/E7.S3."*
>
> **So this story writes no `Services/` code.** It reads two records, maps them to a glyph + a word + an optional
> clock, and puts that string in three `TextBlock`s.

## Story

As a player,
I want one small always-on indicator of which engine is serving me,
So that I never have to open a tab to find out whether anything is wrong.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E7.S3. Do not weaken._

1. **Given** UX-DR3
   **When** the chip is added
   **Then** it is **one `TextBlock`** — glyph + name + optional countdown, no border, no background, no
   animation — in three existing containers: the write path at `MainWindow.xaml:270-279` (right of
   `TranslateStatus`), the read path at `MainWindow.xaml:296-302` (left of `LiveIndicator`), and as a prefix of
   `OverlayStatus` (`CompactOverlay.xaml:44`) shown **only when not healthy**.
2. **Given** the vocabulary of §2.3
   **Then** `●` means "this engine is serving you" (`TealBrush` `Theme.xaml:22`, or `GoldBrush` `:23` when it is a
   **backup**), `○` means paused/not sending (`TextMutedBrush` `:25`), `⚠` means the user may need to act
   (`AccentBrush` `:20`) — all glyphs already ship, so there is no font risk.
3. **Given** NFR11
   **When** any state renders
   **Then** the glyph **and** the word carry the information; colour is never the only signal — `○ Google paused
   0:58` must read correctly with the palette stripped out.
4. **Given** UX-DR4
   **When** the chip is hovered
   **Then** the tooltip lists the whole chain, one line per provider, aligned, no jargon, no HTTP codes, in the
   shape of §2.3 — and it **reuses the dark `ToolTip` style in `Theme.xaml`** (load-bearing; do not restyle).
5. **Given** NFR11
   **Then** the chip carries `AutomationProperties.Name = "Translation engine status"`, matching the icon-only
   buttons (`MainWindow.xaml:259-261`, `CompactOverlay.xaml:31-38`).

## The eight states → the eight chips (§2.1, §2.2)

| # | State | Chip |
|---|---|---|
| **S1** | Healthy | `● Google` teal |
| **S2** | Degraded — fallback active | `● Edge · backup` gold |
| **S3** | Paused until | `○ Google paused 0:58` muted |
| **S4** | Offline model active | `● Offline engine` teal |
| **S5** | All paused | `○ All paused 4 min` gold |
| **S6** | No network | `⚠ No internet` red |
| **S7** | Key invalid | `⚠ DeepL key refused` red |
| **S8** | Quota out | `● Google · Azure quota out` gold |

The tooltip (§2.3), one line per provider, aligned:

```
Google        ○ paused — retries in 0:58   (asked us to slow down)
Edge          ● in use
Google (old)  ● ready
Offline       — not installed
Your keys     DeepL ● ready · Azure — not set
```

## Tasks / Subtasks

- [x] **T1 — The state function, pure and L1-testable (AC 2, AC 3).** A `static` method on `MainWindow` (or a
      small `internal static` type beside it) taking **values, not controls**:
      `(ChainTranslator.Outcome? outcome, IReadOnlyDictionary<string, GateSnapshot> gates, DateTimeOffset now, string? countdown) → (string Glyph, string Text, string BrushKey)`.
  - [x] **Values in, string out.** That is what makes the eight-state test L1 (the epic asks for *"a unit test
        that each of the eight states produces a distinct glyph+word pair"*). A function that reads
        `_readChain` and writes `ChipText.Text` is not testable without a window.
  - [x] **The brush is a resource KEY**, not a `Brush`: the surfaces use
        `SetResourceReference(TextBlock.ForegroundProperty, "TextMutedBrush")` already
        (`MainWindow.Translate.cs:109,180-181`). Returning a key keeps the function UI-free and keeps
        `Theme.xaml` the single palette (UX-DR18: **no new brush, font, image or colour**).
  - [x] **Provider names come from E7.S1's `UserMessages.Name(providerId)`** (OQ-2). One table, one spelling —
        the chip may not grow a second.
- [x] **T2 — Deriving each state (AC 2).** The inputs, and where they come from:
  - [x] **Who answered** — `LastOutcome.ProviderId`. Non-null ⇒ someone served the last call.
  - [x] **Whether it was a fallback (S2)** — `LastOutcome.Skipped` is non-empty **and** `ProviderId` is not the
        chain's first tier. `Skipped` carries `(ProviderId, Reason)` pairs, which is also the tooltip's
        parenthetical.
  - [x] **Paused (S3/S5)** — a tier is paused iff **`BlockedUntil > Now()`**, ruling **E3-a**, *never*
        `State == Open`: that state deliberately outlives the window, and *"a `State`-based skip ships R-01
        silently."* All tiers paused ⇒ S5, and `ChainTranslator.PauseNow()` (`:305`) already computes exactly
        that, including the **earliest** `RetryAt` and its own `Now` — use it rather than re-deriving.
  - [x] **No network (S6)** — every provider's `LastKind == Network`. **Ruling GAP-3: the full pause is
        universal.** S6 behaves like S3/S5 (no capture, no OCR, countdown / "no network" status). `ux` flow
        (e).3's *"LIVE keeps reading the screen"* is **amended** — do not implement it.
  - [x] **Key invalid (S7) / quota out (S8)** — `LastKind` on the `deepl` / `azure` gates. `AuthFailed` has **no
        honest countdown** (the `MaxValue` sentinel); S7's chip says `⚠ DeepL key refused`, full stop.
  - [x] **Offline (S4)** — `ProviderIds.Bergamot`. **E8 has not shipped**, so the tier never exists and S4 is
        unreachable today. Implement the mapping (the function must be total over `ProviderIds.All`) and test it
        with a synthetic outcome; do not build UI that assumes a provider that is not there.
  - [x] **Healthy (S1)** — none of the above.
- [x] **T3 — Three placements, three `TextBlock`s (AC 1).**
  - [x] **Write path** — `MainWindow.xaml`, the button row at `:269-280`, **right of `TranslateStatus`**
        (`:278-279`). Same `VerticalAlignment="Center"`, same margin idiom.
  - [x] **Read path** — the "From screen" header at `:293-304`, **left of `LiveIndicator`** (`:299-300`).
        Visible whether or not LIVE is running — that is why it is there and not inside the LIVE controls.
  - [x] **Compact overlay** — a **prefix of `OverlayStatus`** (`CompactOverlay.xaml:45`), *"shown only when not
        healthy"* — the overlay is 360 px wide and healthy needs no words. Simplest shape that keeps
        `SetStatus`' one-line contract: `MainWindow` composes `"{chip}  {status}"` and passes it to
        `SetStatus` (`CompactOverlay.xaml.cs:67-72`), which already collapses on empty. **`MainWindow` formats;
        the overlay renders** — the same split E7.S2 establishes for the countdown.
  - [x] **One `TextBlock`. No border, no background, no animation** (UX-DR3). Resist the `Border`.
- [x] **T4 — The tooltip (AC 4).**
  - [x] `chip.ToolTip = <the composed string>`, **plain text**, so the **dark `ToolTip` style in `Theme.xaml`**
        (`:45-56+`) applies untouched. `project-context.md` calls that style **load-bearing**; the epic's DoD
        repeats it. **Do not add a `ToolTip` `Style`, a `ContentTemplate`, or a `StackPanel` inside it.**
  - [x] Alignment is **spaces in a monospaced-enough layout** or a fixed-width pad computed from the longest
        provider name (`Google (old)`, 12 chars). Pad in the composer, not with a `Grid`.
  - [x] One line per provider **in chain order** — `ProviderIds.All` (`ProviderGates.cs:29-32`) is already *"every
        id, in the chain order of §8.1 — for the E7 status list"*. Use it. It is the list this story was named in.
  - [x] **No jargon, no HTTP codes** — the parenthetical comes from the `Kind`, rendered through
        `UserMessages`, not from a status code.
  - [x] Tiers that are **not configured** render `— not set` / `— not installed`, not an error.
- [x] **T5 — The 1 Hz refresh (OQ-c / R-2).** The chip is repainted **from E7.S2's single countdown timer**, and
      **only while something is paused**. When nothing is paused, the chip is repainted on the events that
      already exist (a translation completing, LIVE starting/stopping, a key save) — **not** on a timer.
      *"Polling a breaker every 250 ms is exactly the cost we are removing"* (`ux` OQ-4).
  - [x] Every assignment goes through E7.S2's `SetIfChanged` (AC 3 of that story).
  - [x] **`ProviderGates.All()` is one dictionary allocation per tick.** At 1 Hz, while paused, that is
        acceptable and it is the shape R-2 ruled. Do not "optimise" it into a cached field that goes stale.
- [x] **T6 — `AutomationProperties.Name` (AC 5).** `"Translation engine status"` on all three, matching
      `MainWindow.xaml:259-261` and `CompactOverlay.xaml:31-38`'s icon-only buttons.
- [x] **T7 — TP-START-02 stays green.** The chip needs gate state, and the code-behind **may not name
      `ProviderGates`** — `ProviderStateStoreTests.No_startup_path_mentions_ProviderGates` (`:837-866`) asserts
      the exact allow-list. **Route the snapshot read through `Services/`**, the way E3-c routed chain
      composition: add `TranslationChains.GateSnapshots()` (a one-line facade over `ProviderGates.All()`)
      or hang it off the `ChainTranslator` the code-behind already holds (`_readChain`). **The second is
      better** — `PauseNow()` already proves the pattern, the chain knows its own tiers, and it keeps the
      allow-list at the two entries E6.S3 leaves it with.
- [x] **T8 — Tests (TP-RENDER-03 + the eight-state unit).**
- [x] **T9 — `dotnet test tests/PWRUHelper.Tests`.** Green, headless, nothing sleeps.

### Review Findings

_Code review (Amelia CR, 2026-09-07) against commit `8febff4`. Two patched, five recorded._

- [x] **[Review][Patch] S3 spoke for a pause the player could not feel** [`MainWindow.xaml.cs` — `ChipFor`]
      — the arm took `readLines.FirstOrDefault(l => l.State == Paused)`, i.e. the first paused tier in *chain
      order*, so a window standing on `google-gtx` while `google-dict` was answering rendered
      `○ Google (backup) paused 0:58` in muted grey over a perfectly healthy path. Three consequences, not
      one: §2.1's **S1** is told wrong; the chip stops being `IsHealthy`, so the compact overlay gains a prefix
      §2.3 says it may only have "when not healthy"; and `_chipWasDegraded` latches, so the next elapse writes
      §3.5's `Back on Google.` for a recovery from nothing. It is the ordinary way round — the backup keeps its
      own window after the preferred tier's has elapsed. §2.1 defines S3 as *"the **preferred** provider is
      gated"*, so `PreferredPause` now takes the topmost paused tier that does not sit **below** the serving
      one (the serving tier itself still counts — a gate the write path closed under it is a pause the player
      is about to feel), and an unknown `Serving` falls back to the whole chain rather than hiding a state.
      Pinned by `ProviderChipTests.A_pause_below_the_engine_that_is_answering_is_not_the_chips_business`;
      mutation-verified against the old expression.
- [x] **[Review][Patch] I10 had no behavioural pin, only "checking…"**
      [`tests/PWRUHelper.Tests/TemplateRenderTests.cs`] — `A_window_that_has_not_warmed_…` asserts the chip
      *says* `○ checking…`, which is a statement about `_gateStateKnown` and stays true whether or not the
      constructor read the file. The new `RefreshEngineChip()` in the constructor is the first code-behind
      path into gate state, so the regression to guard is a well-meant "make the tooltip honest" change that
      reaches `ProviderGates.EnsureLoaded` from `TranslationChains.EngineStatus`.
      `A_new_window_has_not_read_the_gate_state_file_when_it_paints_the_chip` builds a real `MainWindow` over a
      redirected `provider-state.json` holding a live pause and asserts the **tooltip** still renders Google
      `● ready` (the discriminating surface — the chip would read `checking…` either way) and that no countdown
      is running. Mutation-verified by adding `EnsureLoaded()` to `EngineStatus`.
- [x] **[Review][Defer] The tooltip's columns do not actually align** — `PadRight` is space padding in the
      theme's proportional font, and a long paused row (`Google … ○ paused — retries in about 4 min   (asked
      us to slow down)`) exceeds the `ToolTip` style's `MaxWidth="360"` and wraps. T4 asked for "spaces in a
      monospaced-enough layout"; the layout is not one. Not fixed here because every fix restyles the
      `ToolTip` (a `FontFamily`, a wider `MaxWidth`) and that style is load-bearing.
- [x] **[Review][Defer] A paused WRITE-only tier's tooltip countdown goes stale** — `NeedsTick` asks only
      about `ReadTiers` (correctly: the chip renders no clock for DeepL/Azure), so with only a keyed tier
      paused nothing repaints and the tooltip keeps last repaint's `retries in 0:58` until another event.
      Running the timer for a tooltip nobody is hovering is the cost NFR7 exists to refuse.
- [x] **[Review][Defer] `ChipFor` allocates per tick** — `new[] { DeepL, Azure }` in `KeyedPause` plus two
      LINQ chains, on top of the `ProviderGates.All()` dictionary T5 already accepted. At 1 Hz while paused it
      is noise; left alone to keep the reviewed file's diff to the defect.
- [x] **[Review][Dismiss-as-by-design] The two chips are indistinguishable from each other** — same label,
      same `AutomationProperties.Name` (AC 5 fixes the name verbatim). They are never co-visible: `WriteChip`
      is on the Translator tab and `ReadChip` on Screen OCR, and they deliberately say the same thing.
- [x] **[Review][Defer] `Back on {P}.` surface** — written to `TranslateStatus`, which the next translation
      overwrites. Already recorded by the developer; §3.5's other two lines are E7.S4/E7.S5's, and the

## Dev Notes

### Invariants this story must keep

- **NFR11 — never colour alone.** AC 3, and the test is Sally's: *"`○ Google paused 0:58` says everything with
  the palette stripped out."* Assert on the **text**, with no reference to the brush, that the eight states are
  distinguishable. A chip whose only difference between S2 and S8 is gold-vs-gold is a failure even if it looks
  fine.
- **NFR7 / principle 5 — repaint budget.** One 1 Hz timer (E7.S2's), stopped when idle, `SetIfChanged` on every
  assignment, **no animation**.
- **I2** — the countdown text is formatted by `MainWindow` (E7.S2) and handed in; `Services/` supplies
  `BlockedUntil` and seconds.
- **I1** — `ITranslator` unchanged. `LastOutcome` is on `ChainTranslator`, which is *why* it exists (R-3).
- **I15** — if the chip is ever expressed as a `Run` inside a `TextBlock` with a binding, it is `Mode=OneWay`
  **and** gains an STA case. **Prefer a plain `TextBlock.Text` assignment** — no binding, no trap.
- **I10 / TP-START-02** — T7. And note the honest limit E7.S2 records: `ProviderGates` loads
  `provider-state.json` on the **first `TryEnter`**, so at literal first paint the chip has no persisted pause to
  show. **TP-START-04 is satisfied on the first tick after the first request** — flagged there for Winston.

### Rulings that apply

- **R-3** — `ChainTranslator.LastOutcome` is the "who answered / why a higher tier was skipped" carrier, added
  precisely so `ITranslator` did not have to change. **Already shipped.**
- **OQ-c / R-2** — poll at 1 Hz from the countdown timer; `ProviderGate.Snapshot()` is the immutable record; no
  events leave `Services/`.
- **E3-a** — paused means `BlockedUntil > Now()`, never `State == Open`.
- **E3-b** — `TranslationException.NotSent` (set by `HttpProviderCore.Paused()`) is how the chain tells
  *"skipped"* from *"tried and failed"*; `LastOutcome.Skipped`'s reasons come from it. That distinction is
  **S2 vs S3** — two different chips and two different sentences.
- **GAP-3** — the full pause is universal; S6 behaves like S3/S5. Sally's S6 text is amended in the stories.
- **OQ-2** — the stable provider names; E7.S1's `UserMessages.Name`.
- **E3-d** — **Edge is not shipped** (U2 owner-blocked). The tooltip's `Edge` line must render honestly for a
  provider that is not in the chain, or be omitted. **Prefer rendering `— not available` over silently dropping
  it**: §2.3's mockup shows Edge, and a chain line that quietly disagrees with the About tab's is worse than a
  line that says why.

### Repo traps

- **The dark `ToolTip` style in `Theme.xaml` is load-bearing** (`project-context.md`, and the epic's DoD).
  Plain-text `ToolTip` content only.
- **`MainTabs_SelectionChanged` must keep its `e.Source is TabControl` filter** — untouched here, restated
  because it is an epic-level DoD.
- **`SetResourceReference`, not `FindResource`,** for a foreground that must follow the theme — the two existing
  status writes do it (`MainWindow.Translate.cs:109,180-181`).
- **`OverlayStatus` collapses on empty** (`CompactOverlay.xaml.cs:69-70`). A chip prefix on an empty status must
  not resurrect an empty line — compose only when there is something to say, which is also AC 1's *"shown only
  when not healthy"*.
- **`LiveIndicator` is `Collapsed` unless LIVE is running** (`MainWindow.xaml:300`). The read-path chip is
  **not** — it sits beside it and is visible either way. Do not put it inside the collapsed subtree.
- **`LastOutcome` is `Volatile`-read for a reason** (`ChainTranslator.cs:113-117`): the code-behind reads it from
  the dispatcher while a second call is in flight on a pool thread. Read it **once** into a local per repaint;
  reading it twice in one repaint can mix two calls' accounts.
- **`ChainTranslator.Outcome.Skipped` is `IReadOnlyList<(string, string)>`** — a tuple list, not a dictionary.
- No `.sln`; `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact.

## Testing

- **TP-IDs landed:** **TP-RENDER-03** — *"the chip `TextBlock`/`Run` in each of its three placements renders in
  every S1–S8 state with no binding error"* (L3, STA, `BindingErrorListener` + text; maps `ux` §2.3, S1–S8) —
  plus the epic's *"unit test that each of the eight states produces a distinct glyph+word pair"* (L1).
- **The eight-state unit is the important one and it is pure**: eight synthetic `(Outcome, gates, now)` inputs →
  eight `(glyph, text)` pairs, asserted **distinct**, asserted to contain the right glyph from §2.3's three, and
  asserted **readable with no colour** (NFR11: the assertion touches no brush).
- **The three STA placements** go through `StaTestHost` and the `WPF` collection — **CI-4**: the collection is
  serialised on one STA thread and its budget is **< 15 s** total. Three placements × eight states is 24
  renders; do them as **three** renders with a state loop, not 24 window constructions.
- **The tooltip:** assert it is a **string** (not a `FrameworkElement`), that it has one line per
  `ProviderIds.All` member, and that it contains **no digit-triplet status code** and none of the raw provider
  ids — the same house-rule scan E7.S1 writes for the deck.
- **AC 5:** `AutomationProperties.GetName(chip) == "Translation engine status"` on all three.
- **TP-START-02:** `ProviderStateStoreTests`' allow-list must be **unchanged by this story** (E6.S3 already added
  its one deliberate entry). If it fails, T7 was skipped.
- **Isolation:** IS-6 (injected clock) for anything reading `BlockedUntil`; IS-5/IS-4 only if a case touches the
  real registry — prefer **local** `ProviderGate`s, as `ReadOnceStatusTests` does. **CI-3: nothing sleeps.**
- **Must keep passing unchanged:** `TemplateRenderTests` (TP-RENDER-05 — the two existing cases pass unchanged
  and read-once rows stay framed more heavily), `TranslatorOutputRenderTests`, `LivePauseTests`,
  `ProviderStateStoreTests`.

## How to verify manually

1. `dotnet test tests/PWRUHelper.Tests` — green.
2. **S1.** Healthy app: `● Google`, teal, on both main-window placements; the overlay shows **no** chip.
3. **S3.** Force a Google 429: the chip becomes `○ Google paused 0:58` and counts at 1 Hz; the feed keeps
   filling from the next tier and **no error text appears anywhere** (AC 4 of E7.S1).
4. **S5.** Block every tier: `○ All paused 4 min`, gold, on all three surfaces including the overlay's status
   prefix.
5. **S7.** Save a wrong DeepL key and translate: `⚠ DeepL key refused` — **no countdown**, because there is no
   honest one.
6. **The tooltip.** Hover the chip: one line per provider, aligned, in chain order, dark background (the
   `Theme.xaml` style), no HTTP codes, `Edge` and `Offline` rendered honestly as not available / not installed.
7. **NFR11.** Screenshot the chip in S2 and S8 and convert to greyscale: the two are still distinguishable —
   `● Edge · backup` vs `● Google · Azure quota out`.
8. **The budget.** Healthy app: the countdown timer is stopped, the chip is not repainting, and the only thing
   moving on screen is the 600 ms heartbeat.

**Two things this story was asked to do beyond its own ACs, both from Winston's brief.**

1. **Ruling E6-a is implemented** (`TranslationChains.EnsureGateStateLoaded(chain)` → the chain's own
   `EnsureStateLoaded()`, the seam E5.S1 added), called from `OnWindowLoaded` **on a pool thread, behind every

   behavioural test green while putting a file read in front of the first paint.
2. **E7.S2's countdown stop rule is widened, exactly as its code note asked.** It was `!AllPaused` alone, with
   `if (_liveCts == null) return;` returning **without** stopping. The chip is the second start site E7.S2
   predicted, and it needs the tick with LIVE off. `CountdownTick` now repaints the chip first, stops when
   **both** the chip and LIVE have nothing left to paint, and reaches the `_liveCts` guard only after that
   decision. `NeedsTick` deliberately **excludes** the `AuthFailed` `MaxValue` sentinel, which is half of
   E7.S2's recorded "paint-free 1 Hz tick": a chip-only pause on a refused key no longer keeps a timer alive.

**Deviations, all deliberate, all for the reviewer.**

1. **`○ checking…`, not `◌ checking…`.** The brief suggested `◌`; §6 says "no new fonts, images or colours —
   every glyph above already ships (`● ○ ⚠ ✓ ✕ ▶ ■ 🔴`)", and `◌` is not in that list. The more restrictive
   option was taken and the state still reads correctly with the palette stripped out (NFR11).
2. **The tooltip has six rows, one per `ProviderIds.All`, and no combined `Your keys` row.** §2.3's mockup
   shows five rows with DeepL and Azure sharing one; the story's own Testing section asks for "one line per
   `ProviderIds.All` member", and per-provider rows are what let a key's pause carry its own parenthetical.
3. **`statusLineOwnsTheClock`.** E7.S2's T4 says "the countdown lives on the chip whenever the chip is
   visible, and on the status line otherwise. Never both" — but E7.S2 shipped a LIVE paused line that steps
   its own clock, and the read chip sits on the same tab. So the chip **drops its number** (keeping glyph and
   word) while `_liveCts != null && AllReadTiersPaused`. The overlay applies the same rule by not prefixing a
   chip that carries a clock. This is the only cross-surface fact the pure function is told.
4. **The overlay prefix is composed in `SetScreenStatus`, not in `CountdownTick`.** Prefixing the tick's
   overlay line would put two clocks on the overlay's one line. `CompactOverlay.xaml.cs` and
   `MainWindow.Compact.cs` therefore needed **no change at all** — the planning File List expected one.
5. **`CountdownTick` gained a two-argument overload** (`pause`, `chipNeedsIt`). The one-argument form the
   timer calls is a forwarder whose argument *is* the chip repaint. It exists so AC 1's lifetime can be pinned
   headlessly: driving a stop rule that depends on the chip would otherwise mean paused process-global gates
   from inside the `WPF` collection, which is the cross-collection hazard `GatesCollection` exists to prevent.
   `CountdownTests`' body scan was re-pointed at the overload that actually paints.
6. **`Serving` falls back to the first ready read tier when nothing has been translated yet**, so a freshly
   warmed healthy app reads `● Google` rather than blank. No name is invented (§3.0 rule 1) — the id comes
   from the built chain — but §2.1's S1 is worded "the first provider of the path **answered**", and strictly
   nothing has. Flagged as a copy question, not a defect.
