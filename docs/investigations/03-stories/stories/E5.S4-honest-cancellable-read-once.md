# Story E5.S4: Make read-once report the truth, and make it cancellable

Status: **done**

_Epic E5 (E) — Honest live translation · increment 4 · **Release A.2 (E4 + E5)** · the owner's Phase-4 go was
given 2026-09-06 (`README.md` § Phase 4)._

> **Two defects in one method, and one of them is an amplifier.** `TranslateSentencesInto` swallows the failure
> and returns (`MainWindow.Ocr.cs:300-304`), so `ReadRegionOnceAsync` prints `Done — N line(s) translated.`
> (`:244`) over a total failure. A user who is told "Done" over an empty result presses the button again — and
> again — which is **amplifier A7**: the false success feeds the block it was caused by.
>
> The second defect is quieter and worse to sit through: `TranslateBodiesAsync(..., default)` (`:299`) passes
> **no cancellation token**, so today's worst case is **≈ 36.9 s of uncancellable UI** with `_readingOnce` true
> and both read-once buttons greyed.
>
> **E3.S7 already did part of this story's work**: read-once got its own `Interactive` chain (`_readOnceTranslator`)
> because a person is waiting on it. What is left is the truth and the token.

## Story

As a player who pressed "read the screen once",
I want to be told when nothing was translated,
So that I stop retrying a button that already told me it was Done.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E5.S4. Do not weaken._

1. **Given** `TranslateSentencesInto` swallows the failure and returns (`MainWindow.Ocr.cs:296-299`) and
   `ReadRegionOnceAsync` then writes `Done — N line(s) translated` unconditionally (`:243-244`)
   **When** the fix lands
   **Then** the method returns `(int Translated, TranslationException? Error)` and the caller writes
   `Done — N of M …` on partial success and the `Friendly(error)` text otherwise. **"Done" is unreachable when any
   line lacks a translation.**
2. **Given** `TranslateBodiesAsync(..., default)` at `MainWindow.Ocr.cs:295` passes no cancellation token —
   today's worst case is ≈36.9 s of uncancellable UI
   **When** the fix lands
   **Then** a per-read `CancellationTokenSource` capped at `ReadOnceBudgetSeconds` (30) is used, cancelled by
   `StopLive`, by a second read-once and by window close; `_readingOnce` (`:212,219,254`) stays the re-entrancy
   guard.
3. **Given** every read tier is gate-open
   **When** read-once is pressed
   **Then** it issues **no request**, reports the pause and the countdown, and **creates no rows at all** —
   nothing invites a manual retry more effectively than a false "Done" (amplifier A7).

## The three status shapes (§3.3), and the one rule that governs them

| Outcome | String (`ux-mode-degrade.md` §3.3) |
|---|---|
| all lines translated | `Done — {n} line(s) translated.` (unchanged) |
| some translated | `Read {n} line(s) — {k} translated, {m} could not be. {reason}` |
| none translated | `Read {n} line(s) — none could be translated. {reason}` |
| none translated, everything paused | `Read {n} line(s) — all engines are paused. They will fill in when one is back.` |
| OCR itself failed | `Could not read the screen: {reason}` (today's `OCR failed:` prefix is developer-speak) |

**`{reason}` is the §3.1 sentence, lower-cased at the join.** And the one rule, which is UX acceptance **hint 4**
and **TP-ONCE-02**: **"Done" may only ever appear when every line has a translation.** Write the negative
assertion, not only the positive ones — a test that checks the partial string is not the same as a test that
checks `Done` is *absent*.

**Note the fourth row's promise and check it against AC 3.** *"They will fill in when one is back"* describes rows
that exist. AC 3 says read-once under a full pause **creates no rows at all**. The two are reconciled by AC 3
winning — no rows, so nothing fills in — and the sentence needs its tail trimmed. **Flag it for E7.S1 and for
Sally**: either the copy loses "They will fill in when one is back", or read-once under a pause is expected to
enqueue into E5.S3's `_pendingRetry` (which AC 3 forbids). The story ships AC 3's behaviour and provisional copy
without the promise; the final wording is E7.S1's.

## Dev Notes

### Invariants this story must keep

- **I3 — the OCE trap, in its purest form.** This story *introduces* cancellation into a path that had none, and
  it introduces a **timeout** that arrives as an `OperationCanceledException`. Every catch must filter on the
  token's actual state, and a `TaskCanceledException` from an `HttpClient` timeout with the caller's token **not**
  cancelled must be treated as a failure, not a cancel. `project-context.md` calls this the trap that cost three
  releases; `TranslationBackendTests.cs:84,98` and `ChainTranslator.RunAsync:196-198` are the two existing
  examples to copy.
- **I8** — read-once translates through `_readOnceTranslator`, a **read** chain: DeepL is structurally absent.
  Unchanged by this story; do not "reuse `_writeTranslator` since a user is waiting".
- **I9** — one gate per provider, shared by every chain. That is why `_readChain.PauseNow()` answers for the
  read-once path too, and why a second pause query would be redundant, not safer.
- **I6 / I7** — the drain and the read both go through `TranslateBodiesAsync`; slang expansion and per-message
  source selection are unchanged.
- **I15** — no new `Run.Text`; `TemplateRenderTests` unchanged (but must stay green).

## How to verify manually

1. `dotnet test tests/PWRUHelper.Tests` — green.
2. **The headline.** Disconnect the network. Press "Select area & read once" over a chat region:
   the status is **not** `Done`. It names the reason, in a sentence with no HTTP code and no provider internal.
3. **Partial.** Make one line fail (a very long line that chunks, with the network flapping): the status reads
   `Read {n} line(s) — {k} translated, {m} could not be. {reason}` and the word `Done` appears nowhere.
4. **Paused.** Block every read provider in `provider-state.json` 10 minutes out. Press read-once: **no new rows
   appear at all**, the status says the engines are paused with a time, the log shows **zero** `tr` lines, and the
   buttons come straight back (not greyed).
5. **Cancellable.** With a slow connection, press read-once and then **Ctrl+Alt+R** — that is the only gesture
   that reaches a cancel today; see the `[Review][Decision]` above, ■ Stop is not on screen while a read runs
   and both read-once buttons are greyed. It returns immediately, the status reads `Read cancelled.` and the
   rows say `(not translated — read cancelled)` rather than sitting on "…". Press read-once and close the
   window: no hang.
6. **Budget.** Point the app at an endpoint that never answers: the read gives up at ~30 s with a failure
   sentence — not at 36.9 s, and not never.
