# Story E2.S1: `ProviderGate` — circuit breaker with strikes, cap and half-open probe

Status: **done**

_Epic E2 (B) — Provider gate · increment 1 · **Release A.1: E2 and E3 are separate PRs but ONE release** · ⛔ no
production code until the owner's explicit go._

> **Release rule, non-negotiable.** This epic must not reach users without Epic 3. A circuit breaker in front of
> `client=gtx` — which 429s on request #1 from an affected connection — is an app that is correctly paused all the
> time (`architecture-cible.md` R7, owner's decision 2). It is stated in four places; this is the fifth.

## Story

As a player behind a shared ISP address,
I want the app to stop asking after it has been told to stop,
So that the block Google put on my connection actually expires.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E2.S1. Do not weaken._

1. **Given** the state machine of `architecture-cible.md` §5.2 and the `Kind` table of §5.3
   **When** `ReportFailure(RateLimited)` or `ReportFailure(Blocked)` arrives
   **Then** `strikes` increments and `blockedUntil = now + OpenBaseSeconds × 2^(strikes−1)`, clamped at
   `OpenCapMinutes` (60 s → 2 min → 4 min … 30 min).
2. **Given** an open gate
   **When** `TryEnter` is called before `blockedUntil`
   **Then** it returns `Open(retryAt)` and **no HTTP request is made**; when it is called at or after
   `blockedUntil`, **exactly one** caller receives `Probe` and every concurrent caller receives
   `Open(now + probeTimeout)`.
3. **Given** a half-open probe
   **When** it succeeds
   **Then** the gate closes, `strikes = 0`, `blockedUntil = null`; when it fails with an opening kind, `strikes`
   increments and the window doubles.
4. **Given** `QuotaExhausted`
   **When** it is reported
   **Then** the gate opens for `QuotaOpenMinutes` (60) with **no** strike escalation; given `AuthFailed`, it opens
   with `blockedUntil = DateTimeOffset.MaxValue` until `ProviderGates.ClearAuthBlock(id)` is called.
5. **Given** `Unavailable`, `Timeout`, `Network` or `Unknown`
   **Then** the gate takes **no strike** and applies a `SoftCooldownSecs` (5) cooldown — without it, a DNS blip
   means the next LIVE tick re-hits the same dead provider 700 ms later.
6. **Given** `BadResponse`
   **Then** three **consecutive** occurrences open the gate for `OpenBaseSeconds`.
7. **Given** `Cancelled`
   **Then** the gate is **never** touched.
8. **Given** `CleanResetMinutes` (10) of clean operation
   **When** the next failure arrives
   **Then** it opens for 60 s, not for the escalated window.

## Dev Notes

### Invariants this story must keep

- **I2** — `ProviderGate` lives in `Services/`, is UI-free and unit-testable headless. No WPF type, no
  `DispatcherTimer`, no event out of `Services/`.
- **I3** — `Cancelled` never touches the gate. A timeout (`TaskCanceledException` with the token **not** cancelled)
  is a `Timeout` — a soft cooldown — not a cancel. The mapper (E1.S3) already draws that line; the gate must not
  redraw it.
- **I9** — gate state is process-global and persisted. Instances are handed out by `ProviderGates` (**E2.S2**) and
  persisted by `ProviderStateStore` (**E2.S4**). This class itself holds no static state and does **no I/O**.
- **I10** — nothing here touches disk or network. The gate is pure arithmetic over an injected clock; the file
  loads lazily on the first `TryEnter` **of the registry**, off the UI thread (E2.S4).
- **I11** — no user text, no URL, no key in anything this class produces. Gate lines are provider id + timings only
  (E2.S6).
- **I16** — the LIVE loop is not touched in this epic.

### Rulings and decisions that apply

- **R-2 / OQ-c (binding): poll, do not notify.** `ProviderGate.Snapshot()` returns
  `{State, BlockedUntil, Strikes, LastKind}`; the UI polls it at 1 Hz from the countdown timer. **No events out of
  `Services/`.** This overrides `readiness-report.md` R-2's proposed `ProviderGates.StateChanged`, which explicitly
  asked for it to be added to this story's scope. **Winston: `Snapshot()` is not yet in the §16 glossary.**
- **OQ-b (binding):** a half-open probe consumes a rate-ceiling token.
- **OQ-a (binding):** read-once is `Interactive` — it is a user click. That matters to **E2.S3** and **E5.S4**;
  the enum is defined here.
- **R-3 (binding, but E3.S3's):** `ChainTranslator.LastOutcome` carries which provider answered and why a higher
  tier was skipped. **`ITranslator` (I1) does not change** — and neither does this class's surface to accommodate it.
- **U9 / E2.S7:** every constant in §5.6 is [ASSUMED]. They ship instrumented and are tuned from ≥ 3 field reports
  after the A.1 release. Write the tests to assert **relationships** (the window doubles; the cap holds), not
  literals, so a tuned constant does not rewrite the suite. Where a literal is unavoidable, say so in a comment so
  E2.S7 updates it deliberately.

_Code review (Amelia CR, 2026-09-06) on `caa2e7a` vs `5e98f9a` — three layers (Blind Hunter, Edge Case Hunter,
Acceptance Auditor) plus Winston's R-01 brief. Fix commit: `fix(review): E2.S1 …`. **463 → 470 tests, 0 failed,

**Patched (all five are R-01 or its mirror — the breaker silently switching itself off).**

- [x] `[Review][Patch]` **An escalating failure could lift the two blocks only the user can lift**
      [`Services/ProviderGate.cs:276`] — the `Escalate` arm assigned `_blockedUntil` unconditionally, so a stale
      in-flight 429 landing a second after `AuthFailed` replaced `MaxValue` with 60 s (**verbatim AC 4
      violation**), and replaced a 60-minute `QuotaExhausted` window with 60 s (§15 R9: one request an hour, not
      one a minute). Now "extend, never shorten" like the other rows — except with an explicit `Retry-After`,
      which still assigns (§5.5 keeps the last word). Doubling always extends its own window, so the normal
      escalation path is unchanged. Pinned by `An_escalating_failure_in_flight_cannot_lift_the_two_blocks…` and
      `An_escalating_failure_still_obeys_an_explicit_hint_over_a_standing_block`.
- [x] `[Review][Patch]` **A failed probe could leave the gate with an already-elapsed window**
      [`Services/ProviderGate.cs:305`] — `BadResponse` is the one row that can fail a probe without opening
      anything (one is not three). `blockedUntil` stayed where it was — in the past, because that is how the
      probe was granted — so the gate read `Open` to the UI while handing a fresh probe to every caller in turn
      with no cooldown between them: the breaker off in the one state it exists to manage. §5.2 has one arrow out
      of `HalfOpen` on a failure and it lands on `Open`; a failed probe now always leaves a future block, floored
      at `SoftCooldownSecs`. Pinned by `A_probe_that_fails_without_setting_a_window_still_re_opens_the_gate`.
- [x] `[Review][Patch]` **A stale success started a clean run inside a block and erased the escalation ladder**
      [`Services/ProviderGate.cs:245`] — both chains share one gate (I9), so a request dispatched before the gate
      closed can report 200 a second after it opened. That set `cleanSince` at the start of a 16- or 30-minute
      window; `CleanResetMinutes` later the probe's own failure ran `DecayStrikes` first and re-opened at strike 1
      for 60 s. One late 200 undid five strikes. A clean run now cannot start while `blockedUntil` stands. Pinned
      by `A_success_from_a_request_that_predates_the_block_does_not_forgive_the_ladder`.
- [x] `[Review][Patch]` **`GatePolicy.Parse` could throw** [`Services/ProviderGate.cs:117`] — `catch
      (JsonException)` is not the whole contract: `JsonDocument.Parse(string)` transcodes to UTF-8 first and
      raises **`ArgumentException`** on invalid UTF-16 (a lone surrogate in a hand-edited settings value). IS-12 /
      the L1 half of TP-SET-11 say *never throws*. Now catches everything, with the reason stated. Pinned by
      `GatePolicy_Parse_does_not_throw_on_a_string_that_is_not_valid_UTF_16` — built at runtime, not as
      `InlineData`, because xUnit's data serializer rewrites the character and the case would stop testing
      anything.
- [x] `[Review][Patch]` **`Snapshot()` reported `HalfOpen` for ever after an abandoned probe**
      [`Services/ProviderGate.cs:345`] — D4's re-arm needs a `TryEnter`, and a paused app makes none: LIVE off,
      user away, only the 1 Hz status poll running. The chip would read "checking…" for the life of the process.
      `Snapshot` now applies the same `ProbeTimeout` test `TryEnter` applies, without taking anything. Pinned by
      `An_abandoned_probe_stops_reading_HalfOpen_even_if_nobody_calls_TryEnter_again`.

**Recorded, not patched — for the architect and the named stories.**

- [x] `[Review][Defer]` **No probe identity: any caller's report resolves the probe latch** — `ReportSuccess` /
      `ReportFailure` have no notion of *which* request they belong to, and `SoftCooldownSecs` (5 s) is shorter
      than `RequestTimeoutSeconds` (12 s), so a request dispatched before the block is routinely still in flight
      when the probe is taken. Both directions are wrong: a stale success closes the gate mid-probe (a burst at
      the worst moment), and a stale failure steals the latch so the real probe's success no longer closes
      anything. The fix is a probe token on `GateDecision` that the caller hands back — that is **E2.S5**'s API
      (`HttpProviderCore` is the only caller), so it is recorded rather than invented here. **The single most
      important item for E2.S2/E2.S5.**
- [x] `[Review][Defer]` **`ProviderErrorMapper.cs:104` maps 401 → `AuthFailed` unconditionally**, unlike rows 7/8
      which correctly guard on `keyWasSent`. A keyless provider (the free Google endpoint) that meets one 401 —
      captive portal, proxy, hiccup — gets `blockedUntil = MaxValue` with **no key-save handler and therefore no
      reachable `ClearAuthBlock` caller**. Ruling E2-a bounds it (never persisted in A.1 ⇒ a restart clears it),
      but "restart the app" is the weakest row in the R-01 exit table. Fix belongs in E1.S3's file (guard 401 on
      `keyWasSent`) or in E2.S5's wiring; it is outside this story's File List.
- [x] `[Review][Defer]` **A backwards clock jump extends every time-based block by the jump** — blocks are stored
      as absolute instants against the injected clock (UTC does not shift for DST, but NTP corrections and manual
      clock sets do). TP-GATE-21's clamp is **E2.S4**'s and applies on load only; it should apply to live state
      too, or the state machine needs a monotonic component.
- [x] `[Review][Defer]` **`GatePolicy.Parse` validates only the low end** (`v > 0`) — `{"OpenCapMinutes":100000}`
      or `{"QuotaOpenMinutes":2147483647}` reintroduce R-01 from a value that *persists* in settings.json with no
      UI showing it. Each field needs a plausible ceiling when `AppSettings.ProviderGateOverrides` lands
      (**E6.S3**, tuned by **E2.S7**).
- [x] `[Review][Defer]` **§5.3 vs §5.5 conflict, architect's ruling needed** — the `Retry-After` clamp ceiling
      (`OpenCapMinutes`, 30) is *below* the `QuotaExhausted` window (`QuotaOpenMinutes`, 60), so a hint makes a
      quota block **shorter** than the table's own row. Deliberately pinned today by
      `A_hint_bounds_the_soft_cooldown_and_the_quota_window_too`.
- [x] `[Review][Defer]` **`Retry-After` as written can defeat the breaker, also an architect's call** — §5.5's
      floor is 1 s and the hint overrides the computed window every time, so a server answering `Retry-After: 1`
      buys a 1-second pause while the strike ladder climbs with no effect; and the HTTP-date form is resolved
      against the *client* clock (`ProviderErrorMapper.cs:307` hands over `header.Date`), so a PC running five
      minutes fast collapses every date hint to that same 1-second floor. Candidates: floor the hint at
      `SoftCooldownSecs`, or never let a hint shorten the window the strike ladder computed. §5.5 as written says
      otherwise, so this is a ruling and not a patch.
- [x] `[Review][Defer]` **Probe preference for `Interactive` (§5.4) is owned by no story** — the story defers it
      to E2.S3, but E2.S3 is the *rate ceiling*; granting the probe is the breaker's. During any outage the LIVE
      loop (700 ms ticks) beats the user's single click to every probe, so the one request the user is watching is
      the least likely to be tried. Pinned as today's behaviour by `Priority_does_not_change_the_breakers_answer_yet`.
- [x] `[Review][Defer]` **The UI must special-case two `BlockedUntil` values** (E7.S2/E7.S3): `MaxValue` is not a
      duration to count down (≈7973 years), and while `HalfOpen` the field is the *pre-probe* instant and is
      already in the past. `GateOutcome.Wait` and `RetryAt = default` (year 1 on `Allow`/`Probe`) are the same
      hazard for E2.S5's log line — switch on `Outcome` first.
- [x] `[Review][Defer]` **`ClearAuthBlock()` clears more than its name says** (D7, accepted) — a user re-pasting a
      DeepL key also wipes a standing 30-minute abuse block and the whole strike ladder; done three times while
      fiddling, the breaker never holds. If that is not intended, it should grant one probe rather than reset the
      machine. Related: `_lastKind` survives the clear and is overwritten by any later kind while an auth block
      stands, so the chip can name the wrong reason for a permanent pause.
- [x] `[Review][Defer]` **`DecayStrikes` is unreachable through the public surface today** — every route back to
      `Closed` runs through a probe success, which already zeroes the strikes, and this review's `cleanSince` fix
      narrows it further. TP-GATE-07 asserts AC 8's observable outcome, which that reset produces; the method
      earns its keep only from **E2.S4**'s restored `cleanSince`. The dev notes already say so; recorded because
      the acceptance layer flagged the test as weak w.r.t. the mechanism.
- [x] `[Review][Defer]` **TP-GATE-14 cannot discriminate the HTTP-date form at this layer** — by D1 the parameter
      is already absolute, so the case is TP-GATE-13 with a different number. Record it as deferred to **TP-RET-\***
      (E2.S5) rather than as landed here.
- [x] `[Review][Defer]` **`FakeClock.Now` is unsynchronised across the 64-thread `Parallel.For`** — benign today
      only because the clock is never advanced inside the parallel section; a flake generator the moment E2.S3's

- [x] `[Review][Defer]` **`_lastAt` is written and never read** — E2.S4's persistence field, with nothing pinning
      its meaning until then.

### Repo traps

- **R4 / R-08 — static state and xUnit.** This class has none, but the registry (E2.S2) does. Do not introduce a
  `static` field here "for convenience"; it would leak across parallel collections.
- Footprint is a product requirement: `TryEnter` is on the hot path of every request. No allocation per call beyond
  the decision value, no logging from `TryEnter` (E2.S6 logs **transitions**, never skipped requests — otherwise a
  30-minute open window fills the 1 MB log).
- `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) and the `tests\**` `DefaultItemExcludes` (`:18`)
  intact. **No `.sln`.** `dotnet test tests/PWRUHelper.Tests` green, headless, under ~30 s.
- Nothing in this story is wired to a caller yet. Providers report to gates through **`HttpProviderCore`**
  (**E2.S5**, §7.0: `gate.TryEnter(priority)` before the request, `ReportSuccess`/`ReportFailure(kind, retryAfter)`
  after it). **A provider never touches a gate directly.**

**Deviations, all deliberate — the reviewer's list.**

- **D1 — `ReportFailure(kind, DateTimeOffset? retryAt)`, not `TimeSpan? retryAfter`.** That is the type the value
  actually travels in (`TranslationException.RetryAt`, produced by `ProviderErrorMapper.RetryAfter` at
  `Services/ProviderErrorMapper.cs:303`, which resolves both header forms to an absolute instant). Passing a
  delta would make the caller subtract a "now" the gate did not supply — two clocks where IS-6 exists to have
  one. TP-GATE-13 (delta-seconds) and TP-GATE-14 (HTTP-date) both pass through the same parameter, which is the
  point.
- **D2 — the `[1 s, OpenCapMinutes]` clamp landed here.** E1.S3 deferred it to "whoever first reads `RetryAt`";
  that is `ProviderGate.Honour` (`:375`). An already-elapsed HTTP date opens for 1 s; a 24-hour hint opens for
  30 minutes. **E1.S3's deferred finding can be closed.**
- **D3 — the probe timeout is `TranslationPolicy.RequestTimeoutSeconds` (12 s), not a new constant.** AC 2 needs
  a `probeTimeout` that §5.6 does not define. A probe is one request and cannot outlive the request timeout, so
  the existing `[CONFIRMED]` number is used rather than inventing a seventh ungraded one.
- **D4 — an abandoned probe is re-armed after that timeout** (`:207`, test
  `An_abandoned_probe_is_re_armed_once_it_could_no_longer_be_running`). Not in the story: a caller that takes the
  probe and never reports — a cancel mid-flight (which by I3 must not touch the gate), or a crash — would
  otherwise leave the gate half-open, admitting nobody, for the life of the process. That is R-01 with no way
  out, so it is closed here rather than left to the field.
- **D5 — a non-escalating failure never shortens a standing block** (`BlockUntil`, `:368`, test
  `A_soft_failure_in_flight_cannot_shorten_a_block_that_already_stands`). Two requests share the gate (I9); the
  429 opens 30 minutes and the second request times out a second later. A plain assignment would replace those
  30 minutes with the 5-second cooldown and hand a blocked provider a request every 5 seconds. Escalating rows
  still assign, because their window *is* the policy and §5.5 gives a server's `Retry-After` the last word.
- **D6 — concurrent callers get `Open(probeStartedAt + probeTimeout)`,** which for the concurrent callers AC 2
  describes (same instant) is exactly `now + probeTimeout`; a caller arriving later is simply not told to wait a
  full timeout again.
- **D7 — `ClearAuthBlock()` closes the gate whatever opened it.** §5.3 has the key-save clear both the
  `AuthFailed` block and the `QuotaExhausted` window, and re-saving a provider's key is the user's explicit "try
  this provider now" — it is also the only escape from a wrong `MaxValue`. Narrowing it to "only if `lastKind`
  was one of those two" was considered and rejected as unobservable subtlety.
- **D8 — the IS-12 parser lives in `Services/ProviderGate.cs`, not in `TranslationPolicy.cs`.** It has to:
  `TranslationPolicyTests.The_type_is_a_static_internal_table_with_no_behaviour` asserts that type declares
  **zero** methods and properties. The story permits "the parser or its home"; the constants went to
  `TranslationPolicy`, the parsing to the file that reads it.

**Two things a reader should know, neither a deviation.**

- **The clean-reset is a safety net, not the usual path.** §5.2 states both transitions and both are
  implemented, but every route back to `Closed` runs through a successful probe, which already zeroes the
  strikes — a strike always opens the gate, and only a probe (or `ClearAuthBlock`) closes it. `DecayStrikes`
  (`:398`) is kept because §5.2 says so, because it ages the consecutive-`BadResponse` count when no success has
  landed, and because E2.S4 restores a `cleanSince` this process never observed. It is commented as such at the
  method rather than left to look like dead code. TP-GATE-07 asserts the AC's observable outcome.
- **`GateOutcome.Wait` is declared and never returned.** The token bucket is E2.S3; `TryEnter` returns `Allow`
  where the bucket will answer (`:222`), and the half-open probe is the seam that must charge a token there
  (ruling OQ-b). `RequestPriority` is likewise accepted and unread today — pinned by
  `Priority_does_not_change_the_breakers_answer_yet`, so the day it starts mattering is E2.S3's case to write.

**Tests.** `tests/PWRUHelper.Tests/ProviderGateTests.cs`, 58 cases from 33 facts and theories (one of them the
whole §5.3 table). Every window, escalation, cooldown, clean-reset and probe assertion drives the injected clock; the
one concurrency case uses `Parallel.For` over 64 callers and asserts a **count**, never a timing. Windows are
asserted as relationships to `TranslationPolicy` (doubling, cap, cooldown) so E2.S7's tuning does not rewrite
