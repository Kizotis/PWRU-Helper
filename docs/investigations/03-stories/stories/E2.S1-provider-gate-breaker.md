# Story E2.S1: `ProviderGate` — circuit breaker with strikes, cap and half-open probe

Status: **ready-for-dev (Phase 4 — owner's go required)**

_Epic E2 (B) — Provider gate · increment 1 · **Release A.1: E2 and E3 are separate PRs but ONE release** · ⛔ no
production code until the owner's explicit go._

> **Release rule, non-negotiable.** This epic must not reach users without Epic 3. A circuit breaker in front of
> `client=gtx` — which 429s on request #1 from an affected connection — is an app that is correctly paused all the
> time (`architecture-cible.md` R7, owner's decision 2). It is stated in four places; this is the fifth.

## Story

As a player behind a shared ISP address,
I want the app to stop asking after it has been told to stop,
So that the block Google put on my connection actually expires.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E2.S1. Do not weaken._

1. **Given** the state machine of `architecture-cible.md` §5.2 and the `Kind` table of §5.3
   **When** `ReportFailure(RateLimited)` or `ReportFailure(Blocked)` arrives
   **Then** `strikes` increments and `blockedUntil = now + OpenBaseSeconds × 2^(strikes−1)`, clamped at
   `OpenCapMinutes` (60 s → 2 min → 4 min … 30 min).
2. **Given** an open gate
   **When** `TryEnter` is called before `blockedUntil`
   **Then** it returns `Open(retryAt)` and **no HTTP request is made**; when it is called at or after
   `blockedUntil`, **exactly one** caller receives `Probe` and every concurrent caller receives
   `Open(now + probeTimeout)`.
3. **Given** a half-open probe
   **When** it succeeds
   **Then** the gate closes, `strikes = 0`, `blockedUntil = null`; when it fails with an opening kind, `strikes`
   increments and the window doubles.
4. **Given** `QuotaExhausted`
   **When** it is reported
   **Then** the gate opens for `QuotaOpenMinutes` (60) with **no** strike escalation; given `AuthFailed`, it opens
   with `blockedUntil = DateTimeOffset.MaxValue` until `ProviderGates.ClearAuthBlock(id)` is called.
5. **Given** `Unavailable`, `Timeout`, `Network` or `Unknown`
   **Then** the gate takes **no strike** and applies a `SoftCooldownSecs` (5) cooldown — without it, a DNS blip
   means the next LIVE tick re-hits the same dead provider 700 ms later.
6. **Given** `BadResponse`
   **Then** three **consecutive** occurrences open the gate for `OpenBaseSeconds`.
7. **Given** `Cancelled`
   **Then** the gate is **never** touched.
8. **Given** `CleanResetMinutes` (10) of clean operation
   **When** the next failure arrives
   **Then** it opens for 60 s, not for the escalated window.

## Tasks / Subtasks

- [ ] **T1 — Create `Services/ProviderGate.cs`** (AC: 1–8) — the glossary §16 target file
  - [ ] `internal sealed class ProviderGate` with `TryEnter(RequestPriority)`, `ReportSuccess()`,
        `ReportFailure(TranslationErrorKind kind, TimeSpan? retryAfter = null)`.
  - [ ] `internal enum RequestPriority { Interactive, Background }` and
        `GateDecision { Allow | Wait(TimeSpan) | Open(DateTimeOffset retryAt) | Probe }` in the same file
        (glossary §16 puts all three there). A readonly record struct or a small class hierarchy — pick one and
        keep it allocation-light; this is consulted before every request.
  - [ ] **Injectable clock**: `Func<DateTimeOffset>` (IS-6), defaulting to `() => DateTimeOffset.UtcNow`.
        `ProviderGates` must share the **same** clock (E2.S2) or a persisted `blockedUntil` gets compared against a
        different "now".
  - [ ] State: `strikes`, `blockedUntil`, `lastKind`, `lastAt`, `cleanSince`, the consecutive-`BadResponse` count,
        and the half-open latch. Thread-safe — both chains and the LIVE loop call it (a single `lock`, like
        `CachingTranslator.cs:20`, is the house pattern; do not build a lock-free scheme).
- [ ] **T2 — The escalation arithmetic** (AC: 1, 3, 8)
  - [ ] `blockedUntil = now + OpenBaseSeconds × 2^(strikes−1)`, clamped at `OpenCapMinutes`: 60 s → 2 → 4 → 8 →
        16 → **30 min (clamped)**.
  - [ ] A probe that fails with an opening kind ⇒ `strikes++` and the window doubles; a probe that succeeds ⇒
        `Closed`, `strikes = 0`, `blockedUntil = null`.
  - [ ] `CleanResetMinutes` (10) of clean operation resets `strikes`, so the **next** failure opens for 60 s and
        not for the escalated window. Track it with `cleanSince`, refreshed by `ReportSuccess`.
- [ ] **T3 — The half-open probe** (AC: 2)
  - [ ] At or after `blockedUntil`, **exactly one** caller gets `Probe`; every concurrent caller gets
        `Open(now + probeTimeout)`. Prove it with two concurrent `TryEnter` calls on a fake clock, not with a sleep.
  - [ ] While a probe is outstanding, the gate is neither open nor closed: it admits nobody else until the probe
        reports.
  - [ ] **Ruling OQ-b (binding):** a half-open probe **does** consume a rate-ceiling token — *"it is a real
        request; one rule, no special case"*. The bucket itself is **E2.S3**; leave the seam so E2.S3 wires it
        without re-opening this file's design.
- [ ] **T4 — The §5.3 `Kind` table, every row** (AC: 4–7)
  - [ ] `RateLimited`, `Blocked` ⇒ strike + open (the escalating window).
  - [ ] `QuotaExhausted` ⇒ open for `QuotaOpenMinutes` (60), **no** strike escalation; cleared when the key is
        re-saved (the clear entry point is `ProviderGates.ClearAuthBlock(id)`, E2.S2).
  - [ ] `AuthFailed` ⇒ `blockedUntil = DateTimeOffset.MaxValue` until `ClearAuthBlock(id)`.
  - [ ] `Unavailable`, `Timeout`, `Network`, `Unknown` ⇒ **no strike**, `SoftCooldownSecs` (5).
  - [ ] `BadResponse` ⇒ soft strike; **3 consecutive** ⇒ open for `OpenBaseSeconds`. A success in between resets
        the soft count.
  - [ ] `AllProvidersPaused` ⇒ **never reported to a gate** — it is the chain's own outcome (E3.S3). Guard it.
  - [ ] `Cancelled` ⇒ **the gate is never touched**: `strikes`, `blockedUntil` and `cleanSince` are unchanged
        (assert on a whole-state snapshot, TP-GATE-12).
- [ ] **T5 — `Snapshot()` for the UI — and NO event** (ruling R-2/OQ-c)
  - [ ] Add `internal GateSnapshot Snapshot()` returning an **immutable record**
        `{ State, BlockedUntil, Strikes, LastKind }`. It is read-only, allocation-cheap and side-effect free: it
        must **not** advance the clock, take the probe, or consume a token.
  - [ ] **Do not add `StateChanged`, or any event, delegate or `INotifyPropertyChanged`.** `readiness-report.md`
        R-2 proposes exactly that; the architect's ruling in `README.md` overrides it: *"Poll at 1 Hz from the
        countdown timer Sally already requires (≤ 1 Hz repaint). No event, `Services/` stays passive."* The UI side
        lands in **E7.S2/E7.S3**. (Sprint-plan note 1.)
- [ ] **T6 — The policy numbers and the IS-12 override hatch**
  - [ ] Add the §5.6 breaker constants to `Services/TranslationPolicy.cs` (created in E1.S7), each graded
        **[ASSUMED] — calibrated to a REPORTED range, never measured; instrument first, tune from field logs
        (U9)**: `OpenBaseSeconds = 60`, `OpenCapMinutes = 30`, `CleanResetMinutes = 10`, `QuotaOpenMinutes = 60`,
        `SoftCooldownSecs = 5`, `BadResponseStrikesToOpen = 3`.
  - [ ] **IS-12** — a **pure, `internal`** parser turning an optional overrides JSON string into the effective
        numbers, so a test (and later a field experiment) can drive short windows without waiting 30 real minutes.
        Unparseable ⇒ ignored, `TranslationPolicy` defaults used, **never throws** (the L1 half of TP-SET-11).
  - [ ] **Sprint-plan note 6:** the `AppSettings.ProviderGateOverrides` field this parser will read is created in
        **E6.S3** (increment 5, §12) and used as a field hatch by **E2.S7**. This story lands the parser only, with
        no settings dependency. If John/Winston prefer the field to move forward into E2, say so and this story
        gains one `AppSettings` property.
- [ ] **T7 — Tests, all on the fake clock** (AC: 1–8)
  - [ ] **TP-GATE-01** opens on `RateLimited`, window = 60 s · **TP-GATE-02** stays open, `retryAt` preserved ·
        **TP-GATE-03** (**T1**) half-opens **exactly once** under two concurrent callers · **TP-GATE-04** probe
        success closes and resets strikes · **TP-GATE-05** probe failure re-opens at 120 s ·
        **TP-GATE-06** (**T2**) escalation 60 s / 2 / 4 / 8 / 16 / **30 min clamped** ·
        **TP-GATE-07** (**T3**) clean reset ⇒ the next failure opens for 60 s ·
        **TP-GATE-08** `QuotaExhausted` ⇒ 60 min, strikes not escalated ·
        **TP-GATE-09** `AuthFailed` ⇒ `MaxValue`, cleared by `ClearAuthBlock` ·
        **TP-GATE-10** the four soft-cooldown kinds ⇒ 5 s, no strike ·
        **TP-GATE-11** `BadResponse` needs 3 consecutive; a success in between resets ·
        **TP-GATE-12** `Cancelled` never touches the gate (whole-state snapshot equality) ·
        **TP-GATE-13/14/15** `Retry-After` delta-seconds and HTTP-date **override** the computed window and are
        clamped to `[1 s, OpenCapMinutes]` — the gate applies the value; **parsing it from the response is
        E2.S5's** (T8/TP-RET-*).
  - [ ] **No `Task.Delay` in a gate test, ever** (CI-3). Every window, escalation, cooldown and clean-reset
        assertion drives the injected clock.
  - [ ] The whole §5.3 table must have a case — that is the DoD.
  - [ ] Put the cases in the non-parallel `Gates` collection that **E2.S2** defines (IS-5). If E2.S2 has not landed

## Dev Notes

### Invariants this story must keep

- **I2** — `ProviderGate` lives in `Services/`, is UI-free and unit-testable headless. No WPF type, no
  `DispatcherTimer`, no event out of `Services/`.
- **I3** — `Cancelled` never touches the gate. A timeout (`TaskCanceledException` with the token **not** cancelled)
  is a `Timeout` — a soft cooldown — not a cancel. The mapper (E1.S3) already draws that line; the gate must not
  redraw it.
- **I9** — gate state is process-global and persisted. Instances are handed out by `ProviderGates` (**E2.S2**) and
  persisted by `ProviderStateStore` (**E2.S4**). This class itself holds no static state and does **no I/O**.
- **I10** — nothing here touches disk or network. The gate is pure arithmetic over an injected clock; the file
  loads lazily on the first `TryEnter` **of the registry**, off the UI thread (E2.S4).
- **I11** — no user text, no URL, no key in anything this class produces. Gate lines are provider id + timings only
  (E2.S6).
- **I16** — the LIVE loop is not touched in this epic.

### Rulings and decisions that apply

- **R-2 / OQ-c (binding): poll, do not notify.** `ProviderGate.Snapshot()` returns
  `{State, BlockedUntil, Strikes, LastKind}`; the UI polls it at 1 Hz from the countdown timer. **No events out of
  `Services/`.** This overrides `readiness-report.md` R-2's proposed `ProviderGates.StateChanged`, which explicitly
  asked for it to be added to this story's scope. **Winston: `Snapshot()` is not yet in the §16 glossary.**
- **OQ-b (binding):** a half-open probe consumes a rate-ceiling token.
- **OQ-a (binding):** read-once is `Interactive` — it is a user click. That matters to **E2.S3** and **E5.S4**;
  the enum is defined here.
- **R-3 (binding, but E3.S3's):** `ChainTranslator.LastOutcome` carries which provider answered and why a higher
  tier was skipped. **`ITranslator` (I1) does not change** — and neither does this class's surface to accommodate it.
- **U9 / E2.S7:** every constant in §5.6 is [ASSUMED]. They ship instrumented and are tuned from ≥ 3 field reports
  after the A.1 release. Write the tests to assert **relationships** (the window doubles; the cap holds), not
  literals, so a tuned constant does not rewrite the suite. Where a literal is unavoidable, say so in a comment so
  E2.S7 updates it deliberately.

### Repo traps

- **R4 / R-08 — static state and xUnit.** This class has none, but the registry (E2.S2) does. Do not introduce a
  `static` field here "for convenience"; it would leak across parallel collections.
- Footprint is a product requirement: `TryEnter` is on the hot path of every request. No allocation per call beyond
  the decision value, no logging from `TryEnter` (E2.S6 logs **transitions**, never skipped requests — otherwise a
  30-minute open window fills the 1 MB log).
- `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) and the `tests\**` `DefaultItemExcludes` (`:18`)
  intact. **No `.sln`.** `dotnet test tests/PWRUHelper.Tests` green, headless, under ~30 s.
- Nothing in this story is wired to a caller yet. Providers report to gates through **`HttpProviderCore`**
  (**E2.S5**, §7.0: `gate.TryEnter(priority)` before the request, `ReportSuccess`/`ReportFailure(kind, retryAfter)`
  after it). **A provider never touches a gate directly.**
