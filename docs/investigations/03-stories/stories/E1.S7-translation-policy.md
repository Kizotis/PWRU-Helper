# Story E1.S7: Create `TranslationPolicy` holding today's numbers

Status: **ready-for-dev (Phase 4 — owner's go required)**

_Epic E1 (A) — Diagnosable translation pipeline · increment 0 · Release A.0 · ⛔ no production code until the
owner's explicit go._

**Scheduling note.** `epics.md` lists this story seventh; it has **no dependencies** and **E1.S4 depends on it**,
so the sprint plan pulls it forward to third in the implementation order (S1 → S2 → **S7** → S3 → S4 → S5 → S6).

## Story

As the maintainer,
I want every tunable number in one file before anything tunes one,
So that the constants that will be argued about in the field are already in the place the argument can be settled.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E1.S7. Do not weaken._

1. **Given** `Services/TranslationPolicy.cs` does not exist
   **When** it is created per `architecture-cible.md` §5.6
   **Then** it is `internal static`, every member is `const` or `static readonly`, and **every member carries a
   comment with its evidence grade** ([ASSUMED], [MEASURED], [CONFIRMED]).
2. **Given** this increment must be behaviour-neutral
   **When** the file is created
   **Then** it holds **today's** values where a value already exists in code (12 s timeout, 3 attempts, 300/600 ms
   spacing, cache capacity 500) and the §5.6 target values are **not** yet wired to anything.
3. **Given** the HTML markers of §4.3
   **When** they are needed by E1.S4
   **Then** they live here as `RateLimitMarkers` and `BlockMarkers`.

## Tasks / Subtasks

- [ ] **T1 — Create `Services/TranslationPolicy.cs`** (AC: 1) — the glossary §16 target file
  - [ ] `internal static class TranslationPolicy`. Every member `const` or `static readonly`. No methods, no state,
        no I/O — it is a table of numbers with their provenance.
  - [ ] Every member carries an evidence grade in a trailing comment. Grades come from the source documents, not
        from the author's opinion: `[MEASURED]` = a number this project measured (cite where);
        `[CONFIRMED]` = read in code/config at the baseline; `[ASSUMED]` = calibrated to a reported range, never
        measured (say so, and say what will settle it).
- [ ] **T2 — Today's values, wired to nothing new** (AC: 2)
  - [ ] `RequestTimeoutSeconds = 12` — [CONFIRMED] `TranslationService.cs:39`, `DeepLTranslator.cs:16`.
  - [ ] `MaxAttemptsToday = 3` — [CONFIRMED] `TranslationService.cs:126`. **Named so it cannot be confused with
        §5.6's target `MaxAttempts = 2`, which E2.S5 introduces.**
  - [ ] `RetrySpacingBaseMs = 300` — [CONFIRMED] `TranslationService.cs:153` (`300 * (attempt + 1)` ⇒ 300/600 ms).
  - [ ] `CacheCapacityToday = 500` — [CONFIRMED] `CachingTranslator.cs:24` (the ctor default).
  - [ ] `MaxQueryBytes = 1500` — [CONFIRMED] `TranslationService.cs:35`.
  - [ ] **Do not** add the §5.6 target numbers (`OpenBaseSeconds`, `MinSpacingMs`, `PerLineCap`, `CacheCapacity`
        2000 …) in this story. They arrive with the code that reads them: E2.S1/E2.S3/E2.S5 (gate + retry),
        E3.S8 (`PerLineCap`), E4 (cache), E5 (LIVE). Adding an unused constant now is a constant nobody grades.
  - [ ] Where a value already exists in code, decide per member whether to **reference the constant from the call
        site now** (preferred — it is behaviour-identical) or leave the literal and let the later story move it.
        If you reference it, the produced IL must be equivalent; verify the pins in E1.S1 still pass.
- [ ] **T3 — The HTML abuse-page markers** (AC: 3)
  - [ ] `public static readonly string[] RateLimitMarkers = { "automated queries", "unusual traffic" };`
        — [MEASURED] `benchmark-fournisseurs.md` §3.1, the body this app actually received on 2026-09-06:
        *"Sorry... We're sorry... but your computer or network may be sending automated queries."*
  - [ ] `public static readonly string[] BlockMarkers = { "we're sorry", "captcha", "recaptcha" };` — [ASSUMED],
        from §4.3.
  - [ ] Both are matched **lower-cased against de-tagged text** (E1.S4 does the de-tagging); keep the literals
        lower-case so no call site has to remember.
  - [ ] Order matters at the call site, not here: E1.S4 checks `RateLimitMarkers` **before** `BlockMarkers`
        (§4.3 step 3).
- [ ] **T4 — Nothing else** (AC: 2)
  - [ ] No test of its own (the file has no behaviour). It is consumed by E1.S4's markers and, later, by the gate.
  - [ ] Confirm the suite is green and that no user-visible string and no number changed.

## Dev Notes

### Invariants this story must keep

- **I2** — `Services/` stays UI-free. This file has no dependency on anything, not even `Logging`.
- Behaviour neutrality is the whole point: **if a single number changes value, this story is wrong.**

### Rulings and decisions that apply

- This story is **not** in `plan-migration.md`'s 39-title story cut. It is increment 0's scope item (e) and was
  added by John as **R-11** in the readiness report. That is why it carries an `S#` higher than the stories it
  precedes.
- **E2.S7 (spike U9)** is the story that later *tunes* these numbers, and `AppSettings.ProviderGateOverrides` (§12)
  is the runtime hatch used to trial a value with a volunteer before committing it. Neither exists yet. The pure
  parser for that hatch lands in **E2.S1** (sprint-plan note 6); the `AppSettings` field lands in **E6.S3**.
- Every constant that will be argued about in the field must arrive **already graded**. A number with no grade is
  the thing this file exists to prevent.

### Repo traps

- Match the surrounding style: short "why" comments, PascalCase file name, one class per concern, no linter
  (`project-context.md`). The file is documentation as much as code.
- `internal static` + `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) means the suite can read it;
  keep both intact, and keep the `tests\**` `DefaultItemExcludes` (`:18`). **No `.sln`.**
- `dotnet test tests/PWRUHelper.Tests` stays green and headless.
