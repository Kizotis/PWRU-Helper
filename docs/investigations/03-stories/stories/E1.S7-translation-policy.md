# Story E1.S7: Create `TranslationPolicy` holding today's numbers

Status: **review**

_Epic E1 (A) — Diagnosable translation pipeline · increment 0 · Release A.0 · ⛔ no production code until the
owner's explicit go._

**Scheduling note.** `epics.md` lists this story seventh; it has **no dependencies** and **E1.S4 depends on it**,
so the sprint plan pulls it forward to third in the implementation order (S1 → S2 → **S7** → S3 → S4 → S5 → S6).

## Story

As the maintainer,
I want every tunable number in one file before anything tunes one,
So that the constants that will be argued about in the field are already in the place the argument can be settled.

### Completion Notes List

- **T1/T2** — `Services/TranslationPolicy.cs`: `internal static`, five `const int` + two `static readonly
  string[]`, no methods, no properties, no constructor, no `using` at all (I2 — it depends on nothing, not even
  `Logging`). Every member carries exactly one evidence grade, and the grade cites the `file:line` that holds the
  value **at this commit**, not at the pre-E1.S1 baseline the story quotes (`TranslationService.cs` shifted when
  the handler seam and the typed errors landed).
- **T2, the "reference it now" decision, taken per member.** Referenced from the call site now, because each is a
  single unambiguous definition site and the substitution is a compile-time constant — behaviour-identical:
  `RequestTimeoutSeconds` (`TranslationService.cs:57`, `DeepLTranslator.cs:48`), `MaxQueryBytes` (the `private
  const` is gone; the three uses read the policy), `CacheCapacityToday` (the ctor default at
  `CachingTranslator.cs:24` — a `const` is legal as a default parameter value). **Left as literals:**
  `MaxAttemptsToday` and `RetrySpacingBaseMs`. In the retry loop the number 3 appears in four coupled forms
  (`attempt < 3`, two `attempt == 2` branches, `when (attempt < 2)`) and 300 inside `300 * (attempt + 1)`;
  rewriting them as `MaxAttemptsToday - 1` would trade a readable loop for an arithmetic puzzle in the exact
  method **E1.S3 rewrites next and E2.S5 replaces**. Both constants say so in their own comment.
- **T3** — the markers are §4.3's strings, lower-case, in §4.3's order. `RateLimitMarkers` is `[MEASURED]` (the
  body of 2026-09-06 11:29:02 GMT, `benchmark-fournisseurs.md` §3.1); `BlockMarkers` is `[ASSUMED]` and says what
  would settle it. The class comment records why the call-site order matters (the "automated queries" page also
  contains "we're sorry", so a `BlockMarkers`-first check would misclassify a throttle as a block).
- **T4 — one deviation, deliberate.** The story says "no test of its own"; the DS brief for increment 0 asks for
  the policy object **and its tests**, so six guard cases were added in
  `tests/PWRUHelper.Tests/TranslationPolicyTests.cs`. They assert no behaviour — only the three things that can
  go wrong silently in a file like this: an ungraded member (a source scan, mutation-checked: deleting one grade
  turns it red), a number drifting from what the code does, and a marker that is not lower-case. They also pin
  the three call sites that now read the policy, so a wrong reference cannot hide behind a right constant. No
  clock or random is injected because the policy computes nothing — it is a table; the injectable-clock rule
  applies to E2.S5's back-off, not here.
- **Behaviour neutrality, checked mechanically, not by eye:** the sorted set of string literals in each of the
  three modified files is byte-identical to `3c754ae`; the diff is 6 insertions / 9 deletions, all of them a
  literal swapped for a constant of the same value or the moved `MaxQueryBytes` comment; no user-visible string
  and no number changed; the E1.S1 retry pins (3 requests on 429 and on 503) and `CachingTranslatorTests`
  (capacity 500) pass unchanged.
- **No §5.6 target number was added** (`OpenBaseSeconds`, `MinSpacingMs`, `MaxAttempts = 2`, `PerLineCap`,
  `CacheCapacity = 2000` …). The class comment names them and names the story each one arrives with.
- TP-MAP-17 stays green: the new production file does not name `TranslationErrorKind.Cancelled` and imports
  nothing statically. `InternalsVisibleTo` / `DefaultItemExcludes` intact, no new NuGet package, no `.sln`.
