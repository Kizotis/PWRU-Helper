# Story E2.S4: Persist gate state to `provider-state.json`, lazily and atomically

Status: **review**

_Epic E2 (B) — Provider gate · increment 1 · **Release A.1: E2 and E3 are separate PRs but ONE release** · the
owner's Phase-4 go was given 2026-09-06 (`README.md` § Phase 4)._

> **Release rule, non-negotiable.** This epic must not reach users without Epic 3. Persisting an open gate in
> front of `client=gtx` — which 429s on request #1 from an affected connection — is an app that starts up already
> paused (`architecture-cible.md` R7, owner's decision 2). This story is the one that makes R-01 (a permanently
> paused app) survive a restart, so every guard in it is load-bearing.

## Story

As a player who restarted the app because it seemed stuck,
I want the pause to survive the restart,
So that the app does not immediately re-earn the block I was waiting out — the owner's own evidence is that
restarting does not clear it.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E2.S4. Do not weaken._

1. **Given** the schema of §5.7
   **When** a transition occurs (open, half-open → closed, strike reset)
   **Then** the state is written to `%AppData%\PWRUHelper\provider-state.json` with the atomic pattern of
   `SettingsService.Save` (`SettingsService.cs:186-197`: temp file, `File.Replace`, the whole method inside
   `try { } catch { }`), debounced by 1 s and coalesced, plus once on `OnClosing`.
2. **Given** I10
   **When** the app starts
   **Then** the file is **not** read: it loads lazily on the **first `TryEnter` of the process**, off the UI
   thread — verified by the absence of `ProviderGates` from any startup path.
3. **Given** a missing, corrupt, or future-`version` file
   **When** it is loaded
   **Then** the registry is empty, no exception is raised and the app is not blocked.
4. **Given** a `blockedUntil` more than `OpenCapMinutes` in the future (a machine whose clock jumped)
   **When** the file is loaded
   **Then** the value is clamped to the cap.
5. **Given** an unknown provider id in the file (a downgrade)
   **When** the file is rewritten
   **Then** that entry is preserved.

## Tasks / Subtasks

- [x] **T1 — Create `Services/ProviderStateStore.cs`** (AC: 1, 3, 5) — the glossary §16 target file
  - [x] `internal static class ProviderStateStore` (or a small instance class the registry owns — state the
        choice in the PR): **atomic, best-effort read/write of `provider-state.json`, and nothing else.** No
        clock, no gate, no policy decision. `ProviderGates` owns *when*; this owns *how*.
  - [x] The §5.7 shape, verbatim:
        ```json
        { "version": 1,
          "providers": {
            "google-dict": { "blockedUntil": "2026-09-06T13:45:12.4Z", "strikes": 2,
                             "lastKind": "RateLimited", "lastAt": "2026-09-06T13:41:12.4Z",
                             "cleanSince": null } } }
        ```
        `blockedUntil`, `lastAt`, `cleanSince` are absolute **UTC** and nullable; `strikes` is an int; `lastKind`
        is the `TranslationErrorKind` **member name**. Round-trip it as a name and not as an ordinal —
        `TranslationErrorsTests` pins the enum order today, and a file written by one version must still read on
        another. An unknown `lastKind` string parses to `Unknown`, never throws.
  - [x] **Save = the exact pattern of `SettingsService.Save`** (`Services/SettingsService.cs:184-196` in this
        worktree — `epics.md` and §5.7 both cite `:186-197`, which drifted; sprint-plan note 8 already recorded
        it): `Directory.CreateDirectory` on the parent, write `path + ".tmp"`, `File.Replace(tmp, path, null)`
        when the target exists else `File.Move(tmp, path)`, **the whole method inside one `try { } catch { }`**
        so a read-only disk costs nothing. Do not invent a variant.
  - [x] **Load never throws.** Missing file, truncated JSON, wrong root type, `"version": 99`, a `blockedUntil`
        that is not a date — every one of them yields an empty result and no exception (AC 3). One
        `try { } catch { }` around the whole read, exactly like `SettingsService.Load`.
  - [x] **`version` is a forward guard, not a migration.** `version != 1` ⇒ empty. There is no `Migrate` here and
        there must not be one: unlike settings, gate state is disposable — losing it costs one extra request.
  - [x] **Unknown provider ids are preserved (AC 5).** Keep the raw parsed entries for ids that are not in
        `ProviderIds` and re-emit them unchanged on the next write. A user who downgrades after trying a build
        that knows `edge` must not lose that gate's state when the older build rewrites the file. Preserve them
        **verbatim**, do not re-serialise through the typed record — a field the older build does not know about
        would be dropped. A `JsonElement` (or the raw JSON text) kept per unknown id is the cheap way.
  - [x] `internal static string? PathOverride` was declared by **E2.S2** on `ProviderGates` (IS-1). The store
        must read it through the registry (or take an explicit path) so **no test can reach the real
        `%AppData%`**. Whichever way, the path is decided in one place.
- [x] **T2 — Lazy load on the first `TryEnter` of the process** (AC: 2) — this is I10, and it is the AC most
      easily satisfied on paper and broken in fact
  - [x] **The trigger cannot be `ProviderGates.For(id)`.** The read chain is a **field initializer**
        (`MainWindow.xaml.cs:43`), which runs inside the constructor, **before** first paint; E3.S7 builds the
        chains there, so `For(id)` will be called at construction time. If `For` loads the file, I10 is broken
        and TP-START-01 fails. The trigger must be `ProviderGate.TryEnter`, which cannot run before a
        translation request.
  - [x] Mechanism: `ProviderGates` hands each `ProviderGate` it creates an `Action ensureLoaded` (or the gate
        holds a reference to the registry's loader). At the top of `TryEnter`, one `Volatile.Read` of a `bool`
        guards the call — after the first request of the process it is a single predicted branch on the hot
        path. `EnsureLoaded()` is idempotent and takes the registry's lock; a second thread arriving during the
        load waits rather than loading twice.
  - [x] **Applying a loaded entry to a gate that already exists.** `For(id)` may have handed out a closed gate
        before the first `TryEnter`; the load must then apply the file's state to the **existing instances**,
        not create fresh ones. Write `EnsureLoaded` so it seeds both: every gate already in the map, and every
        gate created afterwards.
  - [x] **"Off the UI thread" — the honest answer, to be stated in the PR.** `TryEnter` is synchronous, so the
        read happens on whatever thread issues the first translation request. **E2.S5's `HttpProviderCore` is
        what makes that a pool thread** (it `ConfigureAwait(false)`s its awaits); if E2.S5 lands after this
        story, the first read may land on the dispatcher. That is acceptable and must be *recorded*, not hidden:
        it is a single ≤ 1 KB read of a directory `SettingsService` has already created, on a user-initiated
        action, long after first paint — which is exactly what I10 protects. **Explicitly rejected alternative:**
        warming the store from `OnWindowLoaded` (`MainWindow.xaml.cs:130`), which already does background work.
        It would put `ProviderGates` on a startup path and fail TP-START-02's source scan, which is this story's
        DoD.
  - [x] **Do not add a warm-up call "to avoid a first-use hitch"** (E2.S2 T5 already says so). The hitch is one
        file read on a request that is about to spend 12 s of network timeout budget.
- [x] **T3 — Transition-only, debounced, coalesced saves** (AC: 1)
  - [x] Saved on **state transitions only**: `Closed → Open`, `Open → HalfOpen`, `HalfOpen → Closed`,
        `HalfOpen → Open`, and a strike reset (`CleanResetMinutes` elapsed clean). **A `TryEnter` that is merely
        refused writes nothing** — TP-GATE-23 asserts 50 refusals cost **zero** writes, and a 30-minute open
        window would otherwise write thousands of times.
  - [x] **A soft cooldown is not a transition** (`Unavailable`/`Timeout`/`Network`/`Unknown`, §5.3): the breaker
        stays `Closed`, the state is worth 5 seconds, and a DNS blip on every LIVE tick would write the file
        every 700 ms. State the rule in a comment; **E2.S6 must make the same call for its log lines** and the
        two must agree.
  - [x] Debounce 1 s and coalesce: the timer is `System.Threading.Timer` (or a simple "pending + last-write"
        pair), **never** a `DispatcherTimer` — `Services/` is UI-free (I2). N transitions inside the window
        produce **one** write, of the state at flush time.
  - [x] **Flush on `OnClosing`.** `internal static void Flush()` on `ProviderGates`, called from
        `MainWindow.OnClosing` (`MainWindow.xaml.cs:229-231`) beside the existing `SettingsService.Save`. It is
        the **only** UI wiring in the whole of Epic 2 — one call, no control, so `_restoringSettings`
        (`MainWindow.xaml.cs:35`, cleared at `:201`) is not engaged and no clobber test is owed. It must not
        throw and must not block the close: best-effort, like everything else on that path.
  - [x] **`ResetForTests()` cancels the pending save** — **IS-4's second half**, which E2.S2 stubbed and this
        story fills in. Without it a queued write from one case lands during the next one, in the *next* case's
        temp directory or, worse, after `PathOverride` has gone back to null. That is the failure mode the whole
        `Gates` collection exists to prevent.
- [x] **T4 — The clock-skew clamp, and the one row it collides with** (AC: 4)
  - [x] On load, `blockedUntil > now + OpenCapMinutes` ⇒ clamp to `now + OpenCapMinutes`. §5.7: "a machine whose
        clock jumped cannot pause the app for a week". `now` is E2.S2's shared `Clock` (IS-6) — the registry and
        every gate share one, or a persisted absolute instant is compared against a different "now".
  - [x] **A `blockedUntil` in the past is simply expired** — it does not need clamping; the gate loads open and
        the very first `TryEnter` half-opens it. Do not "helpfully" drop it: the probe is the correct recovery.
  - [x] **The collision the ACs do not mention, and the dev must decide and record: `AuthFailed` persists
        `blockedUntil = DateTimeOffset.MaxValue`** (§5.3, E2.S1 T4), which is by definition more than
        `OpenCapMinutes` in the future. Taken literally, AC 4 turns a permanent auth block into a 30-minute one
        on every restart. **Recommended resolution: clamp it like any other value, and keep `lastKind =
        AuthFailed`.** Rationale: the key may have been changed while the app was closed, the key is re-read from
        settings at startup anyway, and a *file* is the wrong thing to let block a provider forever — R-01 is the
        risk this epic is judged on. Alternative worth naming in the PR: drop `AuthFailed` entries entirely on
        load. **Do not** special-case `MaxValue` past the clamp without saying so — that is a permanently paused
        provider one corrupt byte away.
  - [x] Serialising `DateTimeOffset.MaxValue` and reading it back must not throw (it round-trips through
        ISO-8601, but assert it).
- [x] **T5 — `TempGateState` and the real-`%AppData%` guard** (IS-3, completing E2.S2's T4)
  - [x] `tests/PWRUHelper.Tests/TempGateState.cs` mirrors `TempSettings` (`StaTestHost.cs:82-101`) exactly:
        `Directory.CreateTempSubdirectory` in the ctor, set `ProviderGates.PathOverride`, null it and delete the
        directory in `Dispose`. E2.S2 lands the shape; this story is where it finally has a file to point at.
  - [x] The guard case, in the shape of `LoggingTests.cs:93-102`
        (`The_test_run_never_writes_to_the_real_AppData_log`): assert the gate path in use is **not**
        `%AppData%\PWRUHelper\provider-state.json`. That test is what stops the suite from rewriting a
        developer's own state — the trap this repo has been bitten by twice
        (`SettingsService.cs:95`, `Logging.cs:31`).
- [x] **T6 — TP-START-02: keep `ProviderGates` off every startup path** (AC: 2) — the story's DoD
  - [x] A source-scan case, in the style `PublishFlagsTests` already uses (it reads files and asserts on them):
        no `ProviderGates` reference in the `MainWindow` constructor, `ApplySettings`
        (`MainWindow.xaml.cs:151-201`) or `OnWindowLoaded` (`:130`). `OnClosing` (`:229`) is the **one**
        permitted reference — carve it out explicitly so T3's `Flush()` does not fail the guard, and say in the
        assertion message why.
  - [x] The STA half (a static flag showing the initialiser has not run at first paint) may wait for
        **E7/E9's** window-level cases; the source scan is what this story owes and is what makes the guard
        cheap enough to keep.
  - [x] `ProviderGates`' **static initialiser must do no I/O** (E2.S2 T5). Merely *touching* the type from a
        startup path would then be harmless — but the scan stays, because the next person's convenience call is
        the one that loads the file.
- [x] **T7 — Tests** (AC: 1–5)
  - [x] **TP-GATE-19** round-trip: open a gate → let the debounce flush → `ResetForTests()` → load through
        `PathOverride` → still `Open`, `blockedUntil` preserved **to the millisecond**, `strikes` preserved.
  - [x] **TP-GATE-20** corrupt / missing / future-version: truncated JSON, absent file, `"version": 99`, a root
        that is an array — each yields an empty registry, **no throw**, and a subsequent `TryEnter` is `Allow`.
  - [x] **TP-GATE-21** clock-skew clamp: a saved `blockedUntil` one week ahead loads clamped to
        `OpenCapMinutes`. Plus the T4 decision's own case (`AuthFailed`'s `MaxValue`).
  - [x] **TP-GATE-22** unknown ids: a file containing `"future-provider"` still contains it, unchanged, after a

  - [x] **TP-GATE-23** transition-only and coalesced: 50 `TryEnter` on an open gate ⇒ **zero** writes; one open

## Dev Notes

### What this story changes in files that already exist

- **`Services/ProviderGates.cs`** (created by E2.S2). Current state: a lazily-initialised `id → ProviderGate`
  map, `ProviderIds`, `PathOverride`, `Clock`, `ResetForTests()`, `ClearAuthBlock(id)`, no I/O anywhere. This
  story adds `EnsureLoaded()`, the debounced save, `Flush()`, and fills in `ResetForTests`' pending-save half.
  What must be preserved: `For(id)` returning the same instance for the same id, the shared `Clock` held **by
  reference** (IS-6), no I/O in the static initialiser, and no event of any kind.
- **`Services/ProviderGate.cs`** (E2.S1 + E2.S3). This story touches it only to (a) call `ensureLoaded` at the
  top of `TryEnter` and (b) notify the registry on a transition so a save can be queued. **Do not add an event**
  (R-2/OQ-c) — an `Action` handed in at construction by the registry is not an event on `ProviderGate`'s public
  surface and is what keeps `Services/` passive. The gate must also expose enough to be *seeded* from a loaded
  record without going through `ReportFailure` (which would escalate strikes and log a transition).
- **`MainWindow.xaml.cs`** — one line in `OnClosing` (`:229-231`). No XAML, no control, no binding.

### Invariants this story must keep

- **I9 — gate state is process-global and persisted.** E2.S2 landed "process-global"; this is "persisted", and
  the pair is what stops the Translator tab from hammering a provider LIVE was told to leave alone across a
  restart.
- **I10 — nothing new touches disk or network before the window is visible.** The whole of T2 and T6. This is
  also **R-10** (startup regression) and it is the one invariant this story can break invisibly.
- **I2** — `ProviderStateStore` and `ProviderGates` stay UI-free and headless-testable. `System.Text.Json` and
  `System.IO` only; no WPF type, no `DispatcherTimer`.
- **I3** — nothing here catches an `OperationCanceledException`. The save is synchronous and best-effort. If a
  future refactor makes it async, **the OCE trap applies**: an `HttpClient` timeout is a `TaskCanceledException`
  with the token *not* cancelled, and every OCE catch in this pipeline is filtered with
  `when (ct.IsCancellationRequested)`. Do not open that door for a file write.
- **I11** — the file and any log line this story produces carry provider ids, timings and kinds. **No user text,
  no URL, no key.** `provider-state.json` sits next to `settings.json` in a folder users are told to zip and
  send; it must be readable and boring.
- **I16** — the LIVE loop is untouched.

### Rulings and decisions that apply — the rulings win over the older documents

- **R-2 / OQ-c (binding):** no state-change event out of `Services/`. The save is queued by the registry itself,
  not by a subscriber. `readiness-report.md` R-2 asks for `ProviderGates.StateChanged`; the architect's ruling
  overrides it (sprint-plan note 1).
- **R-3 (binding, but E3.S3's):** `ChainTranslator.LastOutcome` is where "which provider answered / why a tier
  was skipped" lives. Nothing about it is persisted and nothing about it belongs in this file.
- **U9 / E2.S7:** `OpenCapMinutes` (the clamp bound) is [ASSUMED]. Assert **relationships** ("a week ahead loads
  clamped to the cap"), not the literal 30.
- **§5.7 vs §5.5 — cite the right section.** §5.7 is the persisted-state schema this story implements; **§5.5 is
  `Retry-After`** and belongs to E2.S5. `epics.md` E2.S4 says "§5.7" and is right.
- **The two clamps share a bound and nothing else.** This story's clamp is the **clock-skew** clamp applied on
  load to a persisted `blockedUntil`. E2.S5's is the **`Retry-After`** clamp `[1 s, OpenCapMinutes]`, owned by
  the first reader of the header and applied inside the gate (E2.S1 T7 / TP-GATE-13/14/15). One shared private
  helper is fine; one shared *test* is not.

### Repo traps

- **The static-facade pattern exists twice in this repo, both times after a real incident.**
  `SettingsService.PathOverride` (`SettingsService.cs:95`) after the suite rewrote a developer's own
  `settings.json`; `Logging.DirectoryOverride` (`Logging.cs:31-39`) after the suite seeded a real error report
  with fixture failures. This is the third file the suite could poison. Copy the shape **including the guard
  test**.
- **`TestLogRedirect` sets `Logging.DirectoryOverride` process-wide from a `[ModuleInitializer]`**
  (`TestLogRedirect.cs:24-26`). There is no equivalent for gate state and there should not be: IS-3's explicit
  `TempGateState` disposable is what the plan asks for, and an implicit override would hide a test that forgot it.
- **R-08 / R4 — static state across xUnit's parallel collections.** Everything here joins the `Gates` collection
  (IS-5). **Do not change the runner's default parallelism to work around it**; two non-parallel collections
  (`WPF`, `Gates`) is the accepted, bounded cost of two static facades (CI-5).
- **Footprint is a product requirement.** The file is a few hundred bytes and is written a handful of times per
  session by construction. Do not add a periodic save, a file watcher, or a second serializer options object.
- `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) and the `tests\**` `DefaultItemExcludes` (`:18`)
  intact. **No `.sln`.** `dotnet test tests/PWRUHelper.Tests` green, headless, no real `%AppData%` write.
- **Release checklist:** a new state file under `%AppData%\PWRUHelper\` is exactly what **E9.S11** extends the
  checklist for. Nothing to do here beyond naming it in the PR.

## How to verify manually

1. Run `dotnet test tests/PWRUHelper.Tests` several times in a row. Then open your real
   `%AppData%\PWRUHelper\` **by hand**: there must be no `provider-state.json` and no new `.tmp` file. That
   folder check is the failure mode this story exists to prevent, and no assertion can do it for you.
2. With the A.1 build (E2.S5 landed, so gates are actually consulted): force a provider open — a `Retry-After`
   or a simulated 429 — confirm `%AppData%\PWRUHelper\provider-state.json` appears within a second or two with
   `"strikes": 1` and a `blockedUntil` about 60 s ahead, **close the app**, reopen it, and confirm the provider
   is still paused with the remaining countdown rather than sending a request. Then wait out the window and
   confirm exactly one probe goes out.
3. Set the machine clock a week forward, restart, and confirm the pause is at most 30 minutes — then set it back.
4. Add `"future-provider": { … }` to the file by hand, trigger any transition, and confirm the entry survives.

**The file, as written.** `{ "version": 1, "providers": { "<id>": { "blockedUntil", "keyBlockedUntil", "strikes",
"lastKind", "lastAt", "cleanSince" } } }` — absolute UTC ISO-8601 or `null` for the four instants, an int for the
strikes, the `TranslationErrorKind` **member name** for the kind. Pinned by
`The_file_on_disk_is_the_5_7_shape`, because a rename here silently discards every user's state on their next
upgrade and nothing else would notice.

**Deviation from §5.7, deliberate and the one to review first: `keyBlockedUntil` is an addition.** E2.S2's review
gave the gate two independent block timelines (ruling E2-i: a key save lifts the account-scoped one and never the
IP-scoped 429 window underneath it), and §5.7 predates them. Collapsing the two into one persisted field loses
E2-i across a restart — a key save would either lift a `RateLimited` window it must not touch, or fail to lift the
quota it must. A file without the field simply has no account-scoped block, so old and new files read either way
inside `version 1` and no bump was needed. `A_quota_block_survives_a_restart_and_a_key_save_still_lifts_only_it`
is the case.

**T4's collision, resolved by the ruling and not by the story's recommendation.** The story recommends persisting
`AuthFailed`'s `MaxValue` and clamping it; ruling **E2-a** (later, binding) says `AuthFailed` **is never persisted
in A.1** — in-memory only, a restart resets it. E2-a won. `ExportState` (`ProviderGate.cs:758`) drops both halves:
the `MaxValue` sentinel from the account-scoped timeline and `AuthFailed` from `lastKind`. `TrySeedState` (`:788`)
drops an `AuthFailed` kind on the way *in* too, so the invariant is total in both directions and a hand-edited or
downgraded file cannot bring one back. The accepted cost, stated: a `QuotaExhausted` window that a later 401
covered on the same timeline is lost with it. The clamps still apply to everything that *is* read, which is what
makes a hand-written `MaxValue` a 60-minute pause and not a permanent one
(`A_hand_written_MaxValue_cannot_pause_a_provider_for_ever`).

**The two clamps (T4).** On load, and on load only: the IP-scoped timeline to `now + OpenCapMinutes`, the
account-scoped one to `now + QuotaOpenMinutes` — its own longest window (§15 R9), since clamping it to the cap
would silently halve the one block §5.3 says lasts an hour. `now` is the gate's own clock, which is the
registry's (IS-6). A `blockedUntil` in the past is **not** clamped and **not** dropped: it is expired, the gate
loads open and the first `TryEnter` half-opens it, which is the correct recovery
(`A_blocked_until_in_the_past_is_simply_expired_and_the_first_caller_probes_it`). This clamp is the clock-skew
one; E2.S5's `Retry-After` clamp is a different rule that happens to share a bound, and they share no test.

**When the load happens (T2 / AC 2).** At the top of `ProviderGate.TryEnter` (`ProviderGate.cs:334`), through an
`Action` the registry hands each gate it builds — **not** `For(id)`, which runs inside `MainWindow`'s field
initializer (`MainWindow.xaml.cs:43`), before first paint. One `Volatile.Read` guards it, so after the first
request of the process it is a single predicted branch. `EnsureLoaded` seeds through `For(id)`, so a gate the
chain already holds is the one that gets the state — and `TrySeedState` declines a gate that has already recorded
something in this process, so live evidence always beats a file. Synchronous under `Sync` (a few hundred bytes;
a second thread waits rather than translating against a gate about to be seeded under it). **"Off the UI thread"
is honest, not claimed:** `TryEnter` is synchronous, so the read lands on whichever thread issues the first
translation request — a pool thread once E2.S5's `HttpProviderCore` `ConfigureAwait(false)`s, and possibly the
dispatcher until then. That is one sub-kilobyte read of a directory `SettingsService` has already created, on a
user-initiated action, long after first paint. Warming it from `OnWindowLoaded` was rejected: it would put
`ProviderGates` on a startup path and fail TP-START-02.

**When the save happens (T3 / AC 1).** On transitions only, announced by the gate *outside* its own lock (a
callback raised under it would put the two lock orders back to back against the flush, which walks every gate).
The set: `Closed → Open`, `Open → HalfOpen` (the probe grant), `HalfOpen → Closed`, `HalfOpen → Open`, a strike
reset, a window that moved while the gate was already open (a second 429 escalating the ladder — a restart must
not hand back the shorter pause), and `ClearAuthBlock` clearing an account-scoped block. **Not** a refusal
(TP-GATE-23: 50 of them cost zero writes), **not** a soft cooldown — `Unavailable`/`Timeout`/`Network`/`Unknown`
are worth five seconds and a DNS blip on every LIVE tick would otherwise rewrite the file every 700 ms — and
**not** `Cancelled`, which by §5.3 changes not one byte. E2.S6 must make the same call for its log lines; ruling
E2-b already does, and where the two differ (a strike reset is persisted but not logged) the notification carries
`from == to.State` so E2.S6 can filter it without a second seam. The save is queued **by the registry itself** in
`NoteTransition` and not by a subscriber of `TransitionHook` (ruling R-2/OQ-c): hanging it off the hook would mean
E2.S6's log line replaces persistence the day it installs one.

Debounce 1 s, coalesced, on a `System.Threading.Timer` (never a `DispatcherTimer` — I2). The window is fixed from
the first pending transition rather than restarted by each one, so a busy minute cannot postpone the write
indefinitely. `Flush()` is both the `OnClosing` call and the tests' seam — one method, not a `Flush`/`FlushNow`
pair, since they would do the same thing. **`Flush()` with nothing pending writes nothing**, and that is a
decision, not an omission: the file already says what the gates say, and rewriting it on every close would create
a `provider-state.json` in `%AppData%` for every session that never saw a failure. AC 1's "once on `OnClosing`" is
met by content.

**`MainWindow.xaml.cs:239`** — `ProviderGates.Flush();` in `OnClosing`, above the settings `try` so neither save
can be skipped because the other threw. One line, no control, no binding: `_restoringSettings` is not engaged and
no clobber test is owed. It is the only UI wiring in the whole of Epic 2 and the one permitted `ProviderGates`
reference outside `Services/` (ruling E2-e).
