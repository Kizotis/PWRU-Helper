# Story E7.S4: Paused state and a frozen heartbeat on both windows

Status: **ready-for-dev (Phase 4 — owner's go given)**

_Epic E7 (G) — Degraded-mode UX · increment 6 · **Release B.2** · the owner's Phase-4 go was given 2026-09-06
(`README.md` § Phase 4)._

> **This closes risk R-02, and R-02 is the owner's original complaint wearing its technical name.** *"Zombie
> LIVE indicator. The heartbeat blinks, the loop is paused or dead, the user waits forever. **Today's confirmed
> behaviour through a whole 429 storm.**"* (`analyse-implementation-actuelle.md` §1.5.) A blinking dot over a
> stopped pipe is a lie, and it is the lie the app has been telling for every release so far.
>
> **Half of it is already done, and half of it is not, and the split is exact.** E5.S1 froze the **main window's**
> heartbeat by not advancing `_liveTicks` on a skipped tick — the comment says so:
> *"the ● / ○ heartbeat freezes … the fuller `○  LIVE (paused)` form and **the overlay's own 600 ms blink timer
> are E7.S4's** — this loop does not reach into `CompactOverlay`."* So the main window stops **alternating** but
> still reads `●  LIVE` or `○  LIVE` depending on parity, and **the overlay's `_beat` timer keeps blinking
> regardless**, because it is driven by its own `DispatcherTimer` (`CompactOverlay.xaml.cs:20,47`) and knows
> nothing about the pause.
>
> **And the payoff is the one Sally wrote down:** *"the degraded state costs **less** CPU than the healthy one."*
> Stopping a 600 ms timer is the cheapest UX improvement in this epic.

## Story

As a player,
I want the blinking dot to stop when nothing is being sent,
So that the app stops telling me it is working while it is waiting.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E7.S4. Do not weaken._

1. **Given** UX-DR6 and the confirmed behaviour that the dot keeps blinking through a whole 429 storm
   (`analyse…` §1.5)
   **When** the path is paused (S3 with nothing below serving, S5, S6)
   **Then** `UpdateLiveIndicator` (`CompactOverlay.xaml.cs:77-83`) **freezes on `○`** instead of blinking, and the
   main window's `LiveIndicator` (`MainWindow.xaml:299`) switches from `●  LIVE` to `○  LIVE (paused)`.
2. **Given** the 600 ms heartbeat (`CompactOverlay.xaml.cs:20`)
   **When** the pause begins
   **Then** it **stops**, so the degraded state costs *less* CPU than the healthy one (UX-DR18).
3. **Given** the per-surface table of §2.2
   **When** each of S1–S8 is entered
   **Then** the Translator status line (`MainWindow.xaml:278`), the Screen-OCR status line
   (`MainWindow.xaml:394`), the read-feed header (`MainWindow.xaml:308`) and the overlay status
   (`CompactOverlay.xaml:44`) show exactly the strings of that table, through their existing setters
   (`MainWindow.Translate.cs:106-109`, `MainWindow.Live.cs:157-161`, `:163-175`, `CompactOverlay.xaml.cs:67-72`).
4. **Given** principle 1, "one state, one voice"
   **When** a state is entered
   **Then** the sentence is written **once** into the status line and left there until the next change — never
   repeated per message, never phrased two different ways on two surfaces.
5. **Given** UX-DR17 flow (f) step 4
   **When** the app starts with a persisted pause still active
   **Then** the chip shows it **before the user presses anything** — this is the fix for the owner's original
   "it appears at launch" complaint.

## Tasks / Subtasks

- [ ] **T1 — Freeze the overlay's heartbeat (AC 1, AC 2).** `CompactOverlay.xaml.cs`:
  - [ ] Add `internal void SetPaused(bool paused)`: when `paused`, `_beat.Stop()` and set
        `LiveDot.Text = "  ○  LIVE"` **once**; when not, `_beat.Start()` if the overlay is visible and LIVE is
        running, and let `UpdateLiveIndicator` resume.
  - [ ] `UpdateLiveIndicator` (`:77-83`) must **not** re-blink while paused. It is the `_beat.Tick` handler
        (`:47`) **and** is called from `SetStatus`-adjacent paths (`:94`) and on visibility change (`:50`) — so
        stopping the timer alone is not enough; the method itself needs the guard. **Read all four call sites
        before you change it.**
  - [ ] `_blink` (the alternator) must be **left in a known state** so resuming does not start on the wrong
        glyph. Reset it when the pause begins.
  - [ ] **The overlay never asks anything.** `MainWindow` tells it, the way it already does with `SetStatus`.
        E5.S1's comment states the boundary — *"this loop does not reach into `CompactOverlay`"* — and this
        story is where the reach becomes a one-way call, not a dependency.
- [ ] **T2 — The main window's paused indicator (AC 1).** `MainWindow.Live.cs`:
  - [ ] `LiveIndicator.Text` becomes `"○  LIVE (paused)"` on entering the paused state and returns to the
        heartbeat on leaving. Today the paused branch simply **does not touch it** (E5.S1: `_liveTicks` is not
        advanced, so `:289`'s alternation never runs) — which freezes it on whatever parity it had. **AC 1 wants
        a different string, not a frozen one.**
  - [ ] `SetLiveUi(bool)` (`:201-210`) hard-sets `LiveIndicator.Text = "●  LIVE"` at `:203` on every call.
        Anything that calls `SetLiveUi(true)` while paused would undo the paused text. Check its call sites
        (`:129`, `:187`) and make the paused write authoritative.
  - [ ] **`LiveIndicator` is `Collapsed` unless LIVE is running** (`MainWindow.xaml:300`). A pause with LIVE
        stopped shows nothing there — correct, and it is why the **chip** (E7.S3) is the always-on indicator and
        this is not.
- [ ] **T3 — Who decides "paused", and it must be one thing (AC 1).** `_readChain.PauseNow()`
      (`ChainTranslator.cs:305`) returns `ChainPause(AllPaused, RetryAt, Now)` — already the LIVE loop's own
      test (`MainWindow.Live.cs:244-245`). **Use the same call**, so the indicator cannot disagree with the loop
      that owns the tick.
  - [ ] **AC 1's states are S3-with-nothing-below-serving, S5 and S6.** S3 *with* something below serving is
        **not** paused — requests really are flowing, and the heartbeat should keep blinking (flow (a).1 says so
        explicitly: *"The heartbeat keeps blinking, because requests really are flowing"*). `PauseNow().AllPaused`
        is exactly that distinction, and it is why re-deriving it from a single gate would be wrong.
  - [ ] **S6 (no network) is a pause too — ruling GAP-3**: *"Full pause is universal (owner's OQ-B). S6 behaves
        like S3/S5: no capture, no OCR, countdown / 'no network' status. Sally's S6 text is amended accordingly
        in the stories."* `ux` flow (e).3's *"LIVE keeps reading the screen"* is **superseded — do not implement
        it.**
  - [ ] Paused means **`BlockedUntil > Now()`** (ruling **E3-a**), never `State == Open`; `PauseNow()` already
        implements it.
  - [ ] **A rate-ceiling `Wait` is not a pause** (rulings **E5-a/E5-b**): it sets no `BlockedUntil`, so
        `PauseNow()` cannot see it, and the heartbeat must keep blinking through it. `MainWindow.Live.cs:240-243`
        already carries the comment.
- [ ] **T4 — The §2.2 strings on four surfaces (AC 3, AC 4).**
  - [ ] The four setters, unchanged as **setters**: `TranslateStatus` via `MainWindow.Translate.cs:106-109`
        (the failure branch of `RunTranslation`); `ScreenReadStatus` **and** the overlay via
        `SetScreenStatus` (`MainWindow.Live.cs:194-198` — it writes **both**); `LiveStatus` via `SetLiveUi`
        (`:201-210`).
  - [ ] **AC 4 is the hard one and it is about write frequency, not wording.** Today `LiveLoop` writes
        `SetScreenStatus` on **every tick** (`:338`, `:342`, `:348-349`) — that is the *healthy* narration
        ("check #n") and it stays. What must **not** happen is a degraded sentence re-written per tick or per
        message. **Implement it as an explicit state transition**: keep the last rendered state, and write the
        degraded sentence only when the state **changes**. E7.S2's `SetIfChanged` is the mechanical half; the
        state memory is this story's.
  - [ ] **All the sentences come from the deck** (E7.S1 / GAP-4 / UX-DR19). Do not write a literal in
        `Live.cs`. The paused LIVE sentence already lives in `LivePausedStatus` (`:435-441`) with a comment
        saying *"**E7.S2** owns the final form"* — the final form is §3.2's
        `○ Live — paused, next try in {t}. It resumes on its own; nothing is lost.` and **E7.S5** owns §3.2 as a
        whole. Coordinate: this story owns *when* the line is written and *that the heartbeat matches it*;
        **E7.S5 owns the words.**
- [ ] **T5 — AC 5: a persisted pause is visible before the user presses anything.** Flow (f).4, **TP-START-04**.
      **And this is where the honest limit lives**: `ProviderGates` **does not read `provider-state.json` until
      the first `TryEnter`** (`ProviderGates.cs:166`; `ProviderStateStoreTests:815-834` pins it), because **I10**
      forbids disk I/O before first paint and P1 is the reason I10 exists. E5.S1's review already hit the same
      wall from the other side and fixed it with `EnsureStateLoaded` at **resume**, not at startup.
  - [ ] **Recommended reading of AC 5:** the chip shows the persisted pause **before the user sees a failure** —
        i.e. on the first countdown tick after the first request, and without the user having had to *press*
        anything (the LIVE loop or a background call gets there first). That satisfies the owner's actual
        complaint ("the error appears at launch") without loading a file ahead of the window.
  - [ ] **The alternative — an explicit `EnsureStateLoaded()` after first paint** (from `OnWindowLoaded`,
        `MainWindow.xaml.cs:187-203`, which already runs off the UI thread and after the window is up) — is
        cheap (a few KB, once, E2-e) and makes AC 5 literally true. **It costs one more `ProviderGates` reference
        outside `Services/`**, i.e. a third entry in TP-START-02's allow-list, so it must be routed through
        `Services/` like E7.S3's snapshot facade. **Winston to choose; recommend the second, via the facade** —
        it is the only version that is true on a launch where the user never translates anything.
- [ ] **T6 — Tests (TP-LIVE-17, TP-RENDER-03, TP-START-04).**
- [ ] **T7 — `dotnet test tests/PWRUHelper.Tests`.** Green, headless, nothing sleeps.

## Dev Notes

### Invariants this story must keep

- **NFR7 / UX-DR18 — repaint budget.** AC 2 makes the degraded state *cheaper*: the 600 ms timer stops. Do not
  replace it with a slower blink; **stop** it.
- **I2** — `Services/` never formats the countdown; `MainWindow` does (E7.S2) and hands the overlay a finished
  string through `SetStatus`.
- **NFR11 — never colour alone.** `○  LIVE (paused)` carries the word. Good as written.
- **NFR12 — no modal from a background path.** Nothing here opens a dialog. The S5 nudge of flow (b).4
  (*"You can add an offline engine in About"*) is a **status line**, never a toast or a dialog — and it belongs
  to **E7.S5** with the rest of §3.

### Rulings that apply

- **GAP-3** — the full pause is universal; **S6 behaves like S3/S5.** Sally's S6 text is amended.
- **OQ-B** (owner) — a paused LIVE loop does **not** keep capturing/OCR-ing. Already shipped (E5.S1); this
  story makes the *indicator* agree with it.
- **E3-a** — `BlockedUntil > Now()`, never `State == Open`.
- **E5-a / E5-b** — a rate-ceiling wait is not a pause.
- **E5-c / E5-d** — a pause or a gate refusal is **never an error** and never feeds the auto-stop. Relevant
  here because AC 1's paused indicator must not read like a failure: `○ LIVE (paused)` and
  `Live stopped after repeated errors` are different states and E5.S2 made them different code paths.
- **R-2 / OQ-c** — poll at 1 Hz from E7.S2's timer; no events out of `Services/`.

### Repo traps

- **`SetScreenStatus` writes BOTH windows** (`MainWindow.Live.cs:194-198`) and the comment says why: *"in compact
  mode `ScreenReadStatus` lives on a hidden window, so writing only there left 'Reading…' and every OCR error
  invisible."* Use it for every new sentence — E5.S4's review had to patch a status that landed on a hidden tab.
- **`UpdateLiveIndicator` has four entry points** (`CompactOverlay.xaml.cs:47`, `:50`, `:81`, `:94`). Guarding
  only the timer leaves three.
- **`_beat` starts on `IsVisibleChanged`** (`:50`) — so toggling to compact mode while paused would restart it
  unless `SetPaused`'s state is remembered on the overlay, not just applied. Store the flag.
- **`SetLiveUi(true)` hard-sets `"●  LIVE"`** (`:203`). Any paused text written before it is silently reverted.
- **E5.S1 deliberately does not advance `_liveTicks` while paused.** Do not "fix" that to make the indicator
  update — the frozen tick count is also what stops "check #n" counting checks that never happened.
- **The overlay is 360 px wide.** §3.4 asks for ~60 characters. A paused sentence that wraps is not a bug but it
  is a smell — E7.S5 owns the short forms.
- **`MainTabs_SelectionChanged` keeps its `e.Source is TabControl` filter**; the **dark `ToolTip` style** is
  load-bearing. Epic DoD.
- No `.sln`; `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact.

## Testing

- **TP-IDs landed:** **TP-LIVE-17** — *"Heartbeat frozen while paused: `LiveIndicator.Text` is the paused form
  and does not alternate across ticks; the overlay's `UpdateLiveIndicator` freezes on `○`"* (L3, text across N
  ticks; maps **R-02**, `ux` §2.2, **hint 3**) — plus **TP-RENDER-03** (the chip in the paused states, shared
  with E7.S3) and **TP-START-04** (AC 5).
- **TP-LIVE-17 is the R-02 regression guard.** Assert the text **across N ticks**, driving the tick handler
  directly — **never by waiting** (CI-3). Both surfaces: `LiveIndicator.Text` and `LiveDot.Text`.
- **AC 2 is about the timer, not the text:** assert `_beat.IsEnabled == false` while paused and `true` again on
  resume, and that a visibility toggle **while paused** does not restart it (the `:50` trap).
- **AC 4 (one state, one voice):** drive ten paused ticks and assert the degraded sentence was **assigned once**
  — count assignments, not renders. This is the same shape as E7.S2's repaint-guard test and it is the only way
  the rule is testable.
- **AC 3:** one case per state per surface is 32 assertions; write it as a **table-driven** L3 case over
  §2.2's rows, not 32 methods. **CI-4**: the `WPF` collection's budget is **< 15 s** total.
- **Isolation:** IS-6 (injected clock) for the pause windows; prefer **local** `ProviderGate`s over the registry
  so no `Gates` collection is needed (`ReadOnceStatusTests`' precedent); `TempSettings` for any case that
  constructs a `MainWindow`. **CI-3: nothing sleeps** — a heartbeat test that waits 600 ms is the exact test
  this suite must not grow.
- **Must keep passing unchanged:** `LivePauseTests` (E5.S1's paused-tick behaviour — this story must not change
  *when* the loop pauses, only what the indicator says), `LiveDefaultsTests`, `TemplateRenderTests`,
  `ReadOnceStatusTests`, `DefaultsAndResizeTests` (the overlay's `ResizeHitTest` geometry is untouched).

## Size, dependencies, risk

**Size:** M · **Depends on:** **E7.S2** (the countdown the paused sentences carry) and **E5.S1** (done — the
pause seam and the already-frozen tick counter) · **Risk:** **low-medium.** The code is small; the traps are all
"a second call site re-enabled it": `UpdateLiveIndicator`'s four entry points, `IsVisibleChanged` restarting
`_beat`, and `SetLiveUi`'s unconditional `"●  LIVE"`. Each of the three would produce a *partially* frozen
heartbeat — which is R-02 again, harder to see ·
**DoD:** the heartbeat provably does not blink while paused.

## How to verify manually

1. `dotnet test tests/PWRUHelper.Tests` — green.
2. **The headline, and it is the owner's complaint.** Start LIVE, block every read provider (edit
   `provider-state.json` 10 minutes out, or pull the cable): within one tick the main window reads
   `○  LIVE (paused)`, the overlay's dot **stops moving**, and the status line says when it will retry — once.
3. **AC 2, with Task Manager open.** The paused app uses **less** CPU than the running one. If it uses the same,
   `_beat` is still ticking.
4. **The `IsVisibleChanged` trap.** While paused, toggle to compact mode and back (Ctrl+Alt+M ×2): the dot is
   still frozen.
5. **AC 4.** Sit in the paused state for a minute watching the status line: the sentence is written once and
   left there; only the countdown inside it steps, at 1 Hz.
6. **Not-paused-with-a-fallback (flow (a).1).** Block **only** Google: the heartbeat **keeps blinking**, because
   requests really are flowing. If it freezes, `PauseNow().AllPaused` was replaced by a single-gate test.
7. **AC 5.** Leave a pause active, close the app, reopen: the chip shows the pause without your pressing
   anything.
