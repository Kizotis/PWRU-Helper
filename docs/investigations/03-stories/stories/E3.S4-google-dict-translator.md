# Story E3.S4: `GoogleDictTranslator` as the new default free provider

Status: **ready-for-dev (Phase 4 — owner's go given)**

_Epic E3 (C) — Provider chain and the new default endpoint · increment 2 · **Release A.1: E2 and E3 are separate
PRs but ONE release** · the owner's Phase-4 go was given 2026-09-06 (`README.md` § Phase 4)._

> **This is the story the owner said yes to.** Decision 2, 2026-09-06: *"Endpoint switch to
> `clients5.google.com/translate_a/t?client=dict-chrome-ex` — **yes, coupled with the hardening**."* Everything in
> E1 and E2 exists so that this switch is a relief that fails legibly rather than a second rented endpoint with no
> brakes.

> **Why this is `ready-for-dev` while U1 is owner-blocked.** The **single-line** contract is already measured:
> `benchmark…` §3.2 records both response shapes verbatim, from 20/20 HTTP 200s at ~2.5 req/s on the exact network
> where `gtx` was 429. Only the **multi-line batch** behaviour is [UNKNOWN] (U1), and OQ-A is already settled: **one
> request per line.** So this story ships the safe default — *per-line unless a batch is proven* — and E3.S1's
> fixture, if it ever arrives, turns the batch path on as an optimisation. No request leaves the dev box for this
> story: every test drives a `FakeHandler` over fixtures written by hand from §3.2's recorded shapes.

## Story

As a player on a connection where the old endpoint is throttled,
I want translations to work again today,
So that the feature is usable while the structural work continues.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E3.S4. Do not weaken._

1. **Given** §7.1
   **When** the provider sends a request
   **Then** it is
   `GET https://clients5.google.com/translate_a/t?client=dict-chrome-ex&sl={src}&tl={tgt}&q={UrlEncode(text)}`
   with the existing Chrome User-Agent unchanged and `MaxQueryBytes = 1500` UTF-8.
2. **Given** the two response shapes
   **When** the root array's first element is a string
   **Then** shape A is parsed as `root[0]`; when it is an array, shape B is parsed as `root[0][0]`; anything else
   is `BadResponse`.
3. **Given** E3.S1's answer
   **When** a multi-line group is translated
   **Then** it is sent as one `\n`-joined `q` **if** newlines survive, and as one request per line **if** they do
   not (OQ-A, settled: per line).
4. **Given** the error mapping of §7.1
   **Then** 429 → `RateLimited`; 403 → `Blocked`; HTML on any status → §4.3; 5xx → `Unavailable`; unparseable JSON
   → `BadResponse`.
5. **Given** the provider id
   **Then** it is `google-dict` and its gate is `ProviderGates.For("google-dict")`.

## Tasks / Subtasks

- [ ] **T1 — `Services/GoogleDictTranslator.cs`, on `HttpProviderCore` (AC 1, AC 5).** Model it on
      `Services/TranslationService.cs` as it stands *after* E2.S5 — that file is now exactly "a URL, a payload and
      a parser", which is the shape a new provider is supposed to be.
  - [ ] `private const string ProviderId = ProviderIds.GoogleDict;` — **never** a second spelling of the literal
        (`ProviderGates.cs:15-22`; a second spelling is a silently duplicated gate, not a loud typo).
  - [ ] `private const string ClientId = "dict-chrome-ex";` — **one place**, as R1's own mitigation says: *"the
        client id is a `const` in one place, one edit from a change."* Do not inline it in the URL string.
  - [ ] The frozen Chrome User-Agent, **byte-identical** to `TranslationService.cs:41-42`. §7.0: keep, freeze, do
        not rotate; `benchmark…` §3.1 measured 429 *with and without* it, and `mecanismes…` Q2 records that an
        absent or `curl`-style UA does produce a 403.
  - [ ] `private static readonly HttpClient Http = CreateClient();` and
        `private readonly HttpClient _http;` — the field **names** matter: `HttpSeamGuardTests.ClientOf` /
        `SharedClientOf` (`:86-90`) find them by reflection.
  - [ ] `public GoogleDictTranslator() : this((HttpMessageHandler?)null) { }` **and**
        `internal GoogleDictTranslator(HttpMessageHandler? handler = null, ProviderGate? gate = null)` — IS-8/IS-10
        and `HttpSeamGuardTests.Every_http_provider_accepts_a_test_handler` (`:53-82`) require *both*: an internal
        handler ctor (a test seam, never public API) and, on a public type, at least one public ctor.
  - [ ] `private static readonly ProviderOptions Options = new(ProviderId, KeyWasSent: false, …, UserAgent: …)` —
        `KeyWasSent: false` is what makes a 403 a `Blocked` and not an `AuthFailed` (§4.2 rows 5–8, ruling E2-g).
- [ ] **T2 — The URL and the request (AC 1).** One `RequestAsync(text, source, target, priority, ct)` that owns
      the URL and hands everything else to `_core.SendAsync`:
      `https://clients5.google.com/translate_a/t?client={ClientId}&sl={source}&tl={target}&q={HttpUtility.UrlEncode(text)}`.
  - [ ] Pass the `Uri` to `SendAsync`: `RequestLog` renders host + path and **cannot** render a query (I11) —
        the `q=` never reaches the log.
  - [ ] The `text` argument to `SendAsync` is handed over to be **measured**, never kept.
  - [ ] `MaxQueryBytes = 1500` (`TranslationPolicy.cs:43`), unchanged, checked on the UTF-8 byte count exactly as
        `GoogleGtxTranslator.TranslateAsync` (`:111`) does, chunking through `TextChunker` (E3.S6, landed)
        above it. Call `TextChunker.ChunkText` only — `HardSplit` is private on purpose: it is the path
        `ChunkText` already takes when one sentence is longer than the whole budget.
- [ ] **T3 — The parser (AC 2).** `internal static string Parse(string json)`, run **inside** the core (passed in
      as the `Func<string, T>`), so a body that is not this shape reaches the gate as the `BadResponse` it is
      (§5.3 counts three in a row).
  - [ ] Root must be an array. `root[0]` `ValueKind == String` ⇒ shape A ⇒ `root[0].GetString()`.
  - [ ] `root[0]` `ValueKind == Array` ⇒ shape B ⇒ `root[0][0].GetString()` (the second element is the detected
        source, and this provider **discards** it — I7's source choice is the caller's, per message).
  - [ ] Anything else, and every `JsonException` / `IndexOutOfRangeException` / `InvalidOperationException` ⇒
        `TranslationException(BadResponse, …)`. Mirror `TranslationService.Parse` (`:196-220`) — including its
        comment that an HTML block page can no longer arrive here, because the core's §4.3 sniff classifies it
        first.
- [ ] **T4 — Batching: per-line unless a batch is proven (AC 3, OQ-A).**
  - [ ] `TranslateLinesAsync` sends **one request per line**. Keep the shape of
        `TranslationService.TranslateLinesAsync`'s per-line loop (`:148-163`): translate as many as possible,
        **keep the successes** when a later line is refused, and keep the `rateLimited` latch (I16).
  - [ ] Guard the join path behind the fixture, not behind a comment:
        `private static readonly bool BatchProven = <the fixture exists / a const set by E3.S1>;` with a comment

  - [ ] **Do not implement multi-`q=`.** Declined non-feature (`project-context.md`), re-confirmed by the owner's

## Dev Notes

### Invariants this story must keep

- **I1** — `ITranslator` unchanged; hence T6's per-instance priority.
- **I2** — `Services/`, UI-free, headless-testable.
- **I3** — the OCE trap. This provider adds **no** OCE catch: the core's is the only one on the request path. If
  you find yourself writing `catch (OperationCanceledException)` in this file, the design has been misread.
- **I4** — only successes are cached; the `(`-prefixed placeholders are never stored. Unchanged here, but the
  per-line loop is what *produces* those placeholders (E2-d: their wording is E7.S1's, the policy is E3.S8's).
- **I5** — this is a join/split provider, so a count mismatch falls through to per-line **and only up to
  `PerLineCap`** — E3.S8's bound. Never pad.
- **I6 / I7** — slang expansion stays upstream (`MainWindow.Live.cs:302`) and the source is chosen per message by
  the caller (`:304-310`). This provider receives `"ru"` or `"auto"` and must not second-guess either. Shape B's
  detected-language element is **discarded** for exactly that reason.
- **I11** — no `q=`, no user text, no key in the log. Enforced by handing `SendAsync` a `Uri` it renders as host +
  path.
- **I16** — the `rateLimited` latch behaviour is preserved on the per-line path.

### Rulings and evidence

- **Owner's decision 2:** the endpoint switch ships **coupled with** the hardening, never instead of it.
- **OQ-A (binding):** per line if newlines are lost. Multi-`q=` is not on the table.
- **ToS posture, stated once so nobody has to re-derive it:** `clients5.google.com/robots.txt` has **no**
  `Disallow: /translate_a/`, unlike `translate.googleapis.com` line 162 — *strictly better than today, still not
  clean*. That sentence belongs in the PR description.
- **R1 is this story's own risk:** an undocumented, rented endpoint that could be blocked next. The mitigations
  are structural and already built — three free tiers from two vendors (E3.S5/S6), a gate that fails legibly
  (E2), and `ClientId` as a `const` in one place.

### Repo traps

- **`HttpSeamGuardTests` finds providers by reflection** (`:28-33`: any non-abstract `ITranslator` with an
  `HttpClient` field, base classes walked). A new provider joins that list automatically. Get the ctor shape and
  the field names right the first time and the guard is free; get them wrong and it fails with a message about
  the *seam*, not about your parser.
- **`FakeHandler` repeats its last step past the end of the script** (`FakeHandler.cs:103`) — so "429 forever" is
  one `Respond`, and a per-line test that wants N different answers must script N steps.
- **The `Gates` collection is non-parallel and resets state** (IS-5). Any class naming `ProviderGates` must join
  it — `ProviderGatesTests.Every_test_class_that_touches_the_registry_joins_this_collection` (`:319-360`) scans
  for it.
- **`TranslationPolicy` has a grade scan.** If you add a constant there (you should not need to in this story —
  `PerLineCap` is E3.S8's), it needs a `[CONFIRMED]`/`[ASSUMED]`/`[REPORTED]` grade or the scan fails.
- No settings control is touched: `_restoringSettings` is not engaged. No `MainWindow` change at all in this
  story — wiring the provider into a chain is **E3.S7's**.
- `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact. **No `.sln`.**

## Size, dependencies, risk

**Size:** M · **Depends on:** **E3.S6** (`TextChunker` — hard, and it inverts `epics.md`'s numbering), E3.S3 (the
chain this tier plugs into), E2.S5 (`HttpProviderCore`); **E3.S1 is an optimisation, not a dependency** ·
**Risk:** **medium — R1.** An undocumented and rented endpoint. Secondary: this provider is the one that will
carry the LIVE loop's whole volume, so a parser that is subtly wrong shows up as a feed of `BadResponse` rows
rather than as a build error ·
**DoD:** `epics.md`' own sentence — *a translation succeeds through `dict-chrome-ex` on a network where `gtx`
429s.* Until E3.S7 wires the chains, verify it with the manual step below.

## How to verify manually

1. `dotnet test tests/PWRUHelper.Tests` — green, and `HttpSeamGuardTests` now holds three providers.
2. **The DoD check, and it needs a network where `gtx` is throttled.** Because E3.S7 has not wired the chain yet,
   the honest way to do this without a scratch harness is to run the app *after* E3.S7 lands. If the owner wants
   evidence earlier, a `tools/diagnostics/` script that constructs `new GoogleDictTranslator()` and translates one
   line is acceptable **only with a fresh go for that request** (ground rule 2) — it is one request to the same
   endpoint E3.S1 targets.
3. Read `%AppData%\PWRUHelper\logs\log.txt` after a forced failure: the `tr` line says `provider=google-dict`,
   carries no `q=`, and shows exactly one attempt on a 429.
4. Read the diff for the client id: it must appear **once**.
