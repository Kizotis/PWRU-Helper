# Story E3.S4: `GoogleDictTranslator` as the new default free provider

Status: **done**

_Epic E3 (C) — Provider chain and the new default endpoint · increment 2 · **Release A.1: E2 and E3 are separate
PRs but ONE release** · the owner's Phase-4 go was given 2026-09-06 (`README.md` § Phase 4)._

> **This is the story the owner said yes to.** Decision 2, 2026-09-06: *"Endpoint switch to
> `clients5.google.com/translate_a/t?client=dict-chrome-ex` — **yes, coupled with the hardening**."* Everything in
> E1 and E2 exists so that this switch is a relief that fails legibly rather than a second rented endpoint with no
> brakes.

> **Why this is `ready-for-dev` while U1 is owner-blocked.** The **single-line** contract is already measured:
> `benchmark…` §3.2 records both response shapes verbatim, from 20/20 HTTP 200s at ~2.5 req/s on the exact network
> where `gtx` was 429. Only the **multi-line batch** behaviour is [UNKNOWN] (U1), and OQ-A is already settled: **one
> request per line.** So this story ships the safe default — *per-line unless a batch is proven* — and E3.S1's
> fixture, if it ever arrives, turns the batch path on as an optimisation. No request leaves the dev box for this
> story: every test drives a `FakeHandler` over fixtures written by hand from §3.2's recorded shapes.

## Story

As a player on a connection where the old endpoint is throttled,
I want translations to work again today,
So that the feature is usable while the structural work continues.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E3.S4. Do not weaken._

1. **Given** §7.1
   **When** the provider sends a request
   **Then** it is
   `GET https://clients5.google.com/translate_a/t?client=dict-chrome-ex&sl={src}&tl={tgt}&q={UrlEncode(text)}`
   with the existing Chrome User-Agent unchanged and `MaxQueryBytes = 1500` UTF-8.
2. **Given** the two response shapes
   **When** the root array's first element is a string
   **Then** shape A is parsed as `root[0]`; when it is an array, shape B is parsed as `root[0][0]`; anything else
   is `BadResponse`.
3. **Given** E3.S1's answer
   **When** a multi-line group is translated
   **Then** it is sent as one `\n`-joined `q` **if** newlines survive, and as one request per line **if** they do
   not (OQ-A, settled: per line).
4. **Given** the error mapping of §7.1
   **Then** 429 → `RateLimited`; 403 → `Blocked`; HTML on any status → §4.3; 5xx → `Unavailable`; unparseable JSON
   → `BadResponse`.
5. **Given** the provider id
   **Then** it is `google-dict` and its gate is `ProviderGates.For("google-dict")`.

### Invariants this story must keep

- **I1** — `ITranslator` unchanged; hence T6's per-instance priority.
- **I2** — `Services/`, UI-free, headless-testable.
- **I3** — the OCE trap. **Corrected at review (2026-09-07): as written, this bullet contradicted T4.** It said
  "this provider adds **no** OCE catch", but T4 orders the per-line loop kept in `GoogleGtxTranslator`'s shape,
  and that loop carries three of them. What I3 actually means, and what the code does: **no OCE catch on the
  REQUEST path** — the core's single filtered catch (`HttpProviderCore.cs:281`) is the only one that sees a
  transport failure. The three in this file (`:190`, `:208`, `:232`) are on the **orchestration** path — which
  line of a group failed, and whether to keep going — and every one is filtered
  `when (ct.IsCancellationRequested)`, which is the rule the trap is actually about: an `HttpClient` timeout is
  an OCE whose token is **not** cancelled, and an unfiltered catch would rethrow it as a user cancel and throw
  away every line already translated. An **unfiltered** `catch (OperationCanceledException)` in this file is the
  thing that means the design has been misread.
- **I4** — only successes are cached; the `(`-prefixed placeholders are never stored. Unchanged here, but the
  per-line loop is what *produces* those placeholders (E2-d: their wording is E7.S1's, the policy is E3.S8's).
- **I5** — this is a join/split provider, so a count mismatch falls through to per-line **and only up to
  `PerLineCap`** — E3.S8's bound. Never pad.
- **I6 / I7** — slang expansion stays upstream (`MainWindow.Live.cs:302`) and the source is chosen per message by
  the caller (`:304-310`). This provider receives `"ru"` or `"auto"` and must not second-guess either. Shape B's
  detected-language element is **discarded** for exactly that reason.
- **I11** — no `q=`, no user text, no key in the log. Enforced by handing `SendAsync` a `Uri` it renders as host +
  path.
- **I16** — the `rateLimited` latch behaviour is preserved on the per-line path.

### Rulings and evidence

- **Owner's decision 2:** the endpoint switch ships **coupled with** the hardening, never instead of it.
- **OQ-A (binding):** per line if newlines are lost. Multi-`q=` is not on the table.
- **ToS posture, stated once so nobody has to re-derive it:** `clients5.google.com/robots.txt` has **no**
  `Disallow: /translate_a/`, unlike `translate.googleapis.com` line 162 — *strictly better than today, still not

- **R1 is this story's own risk:** an undocumented, rented endpoint that could be blocked next. The mitigations
  are structural and already built — three free tiers from two vendors (E3.S5/S6), a gate that fails legibly
  (E2), and `ClientId` as a `const` in one place.

### Repo traps

- **`HttpSeamGuardTests` finds providers by reflection** (`:28-33`: any non-abstract `ITranslator` with an
  `HttpClient` field, base classes walked). A new provider joins that list automatically. Get the ctor shape and
  the field names right the first time and the guard is free; get them wrong and it fails with a message about
  the *seam*, not about your parser.
- **`FakeHandler` repeats its last step past the end of the script** (`FakeHandler.cs:103`) — so "429 forever" is
  one `Respond`, and a per-line test that wants N different answers must script N steps.
- **The `Gates` collection is non-parallel and resets state** (IS-5). Any class naming `ProviderGates` must join
  it — `ProviderGatesTests.Every_test_class_that_touches_the_registry_joins_this_collection` (`:319-360`) scans
  for it.
- **`TranslationPolicy` has a grade scan.** A constant added there needs a grade or the scan fails. The
  vocabulary is `[CONFIRMED]`/`[MEASURED]`/`[ASSUMED]` — **this bullet said `[REPORTED]`, which the code has
  never used** (pre-existing story error, corrected at review). This story *did* add one after all —
  `GoogleDictBatchJoinEnabled`, graded `[UNKNOWN]`, a fourth word added to the vocabulary — **which is Winston's
  ruling 1 and not a drive-by**: it is the flag's better home (a graded table a test can pin beats a field
  inside a request path), and no existing grade is honest about a value that ships at the safe end of an open
  question. The scan is still exactly one-of; `PerLineCap` remains E3.S8's.
- No settings control is touched: `_restoringSettings` is not engaged. No `MainWindow` change at all in this
  story — wiring the provider into a chain is **E3.S7's**.
- `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact. **No `.sln`.**

- **`Services/TextChunker.cs` — the surrogate-pair fix (`:59-105`), in scope because this story is the
  splitter's second caller.** `HardSplit` walked UTF-16 code units, so a budget that ran out between the halves
  of a surrogate pair cut it: one chunk ended in a lone high surrogate, the next began with the lone low one, and
  both encode to U+FFFD in the query string — a user's emoji silently became two replacement characters
  mid-message, on the path the whole chat feed travels. It now advances a code point at a time and accumulates
  the byte count instead of re-encoding the buffer per character (the old loop was quadratic). **Deliberately not

  chunker test rests on — the chunks concatenate back to the input. A second case pins that ill-formed input
  still travels through byte for byte.
