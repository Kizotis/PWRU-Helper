# Story E7.S8: README and About copy for the new key slot and the offline option

Status: **review** · _two claims in it are gated on spikes U4/U5; see AC 2_

_Epic E7 (G) — Degraded-mode UX · increment 6 · **Release B.2** · the owner's Phase-4 go was given 2026-09-06
(`README.md` § Phase 4)._

> **Docs only, and the whole story is one rule: no claim in the copy outruns its evidence grade.** That is the
> DoD, verbatim. Two of the claims this copy wants to make are ungraded today — **U4** (is Azure F0's 2 M
> chars/month permanent, or a trial?) and **U5** (do existing DeepL `:fx` keys still work?) — and both are
> `blocked-owner` spikes. **The story is not blocked**; it is *bounded*: it writes what is known, and it does not
> write what is not.
>
> **And the README currently contains a sentence that release B makes false.** It presents translation as
> Google-with-an-optional-DeepL-key and OCR as always-Google — which was true through v0.14.0 and stops being
> true the moment E6.S4's read-path opt-in ships. Correcting that is the substance of this story; the new key
> slot and the offline option are the additions around it.

## Story

As a prospective user reading the README,
I want to know that keys are optional and what each one buys,
So that the free path stays obviously the default.

**The two flaky cases: root cause, measured, and fixed.** E7.S7's review saw
`PerLineFallbackTests.E3_g…` and `TemplateRenderTests`' I10 gate-file case fail in 2 of 7 full runs.
They are **one file and two independent races**, and neither is what the repo believed.

1. **The `Gates` collection was never serialised against the STA one.**
   `[CollectionDefinition("Gates", DisableParallelization = true)]` does not stop *other* collections
   running beside it — measured (see Debug Log): with only `TemplateRenderTests` and
   `PerLineFallbackTests` selected, a widened window in the I10 case failed on a **30-minute pause a
   `PerLineFallbackTests` case had just opened**. The same overlap is what let the gate cases read
   that case's `blockedUntil: 2099` file and refuse a provider they expected to try — the `E3_g`
   failures. **Fix: the nine STA classes join the `Gates` collection**, which is the serialisation.
   They belonged there anyway: a real `MainWindow` reaches `ProviderGates` through
   `TranslationChains` whether or not the test file names it. `WpfCollection` is gone.
   `ProviderGatesTests`' membership scan — which could not see `TemplateRenderTests`, because that
   file writes the gate-state **file** without naming the registry — now triggers on
   `TestGateStateRedirect.` and on `StaTestHost.` as well, and asserts non-vacuously that it finds
   `TemplateRenderTests.cs`.
2. **`OnWindowLoaded`'s warm-up escapes the case that starts it.** Laying any part of a real window
   out makes WPF queue that window's `Loaded`, and `Loaded` is raised by a **dispatcher operation** —
   so `OnWindowLoaded` runs whenever a later layout pass completes (on this STA thread, a leftover
   1 Hz countdown tick, seconds later, inside somebody else's case). Its answer is
   `Task.Run(() => TranslationChains.EnsureGateStateLoaded(chain))`, which reads
   `provider-state.json` — the I10 case's own poisoned file. **Nothing in a test can join that task**
   without a production change to hold it, and this story changes no production behaviour. **Fix: the
   I10 case resets the registry and retries up to five times** — a constructor that really reads the
   file fails every attempt, a stray warm-up can only ever spoil one. Pumping the dispatcher was tried
   first and does *not* work; that is written down where the next reader will look.

No `SettingsVersion` change, no new setting, no new NuGet, no new brush and no new `Run.Text` binding.
