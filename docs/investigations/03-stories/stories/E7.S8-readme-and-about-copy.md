# Story E7.S8: README and About copy for the new key slot and the offline option

Status: **ready-for-dev (Phase 4 — owner's go given)** · _two claims in it are gated on spikes U4/U5; see AC 2_

_Epic E7 (G) — Degraded-mode UX · increment 6 · **Release B.2** · the owner's Phase-4 go was given 2026-09-06
(`README.md` § Phase 4)._

> **Docs only, and the whole story is one rule: no claim in the copy outruns its evidence grade.** That is the
> DoD, verbatim. Two of the claims this copy wants to make are ungraded today — **U4** (is Azure F0's 2 M
> chars/month permanent, or a trial?) and **U5** (do existing DeepL `:fx` keys still work?) — and both are
> `blocked-owner` spikes. **The story is not blocked**; it is *bounded*: it writes what is known, and it does not
> write what is not.
>
> **And the README currently contains a sentence that release B makes false.** It presents translation as
> Google-with-an-optional-DeepL-key and OCR as always-Google — which was true through v0.14.0 and stops being
> true the moment E6.S4's read-path opt-in ships. Correcting that is the substance of this story; the new key
> slot and the offline option are the additions around it.

## Story

As a prospective user reading the README,
I want to know that keys are optional and what each one buys,
So that the free path stays obviously the default.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E7.S8. Do not weaken._

   **Then** the README describes the free-by-default chain, the two optional key slots and the optional offline

   **When** the offline option is described
   **Then** the About tab declares MPL-2.0 for the engine, the models and the wrapper, and the application's own
   licence is stated as MIT.

### Invariants and rules this story must keep

- **The UI is English-only, by decision** (`project-context.md`: *"a decision, not an oversight"*). No i18n, no
  `.resx` — a **deliberate non-feature**; do not propose translating the README's in-app copy.
- **UX-DR19 / GAP-4** — a sentence that also appears in the app exists **once** in
  `Services/UserMessages.cs`; the README quotes it rather than re-wording it. Two spellings of the same promise
  across the README and the About tab is the same failure the copy deck exists to prevent.
- **AC 1's register** — no HTTP codes, no provider internals, no exclamation marks (§3's rules).
- **NFR10** — the licence declaration (AC 3).
- **Release checklist** — `project-context.md` §Development Workflow: a release bumps `<Version>` in
  `PWRUHelper.csproj` **and** the hardcoded `VERSION=` in `Build MSI Installer.bat`. Not this story's, but this
  story is the one that touches `README.md`, and the README is where the checklist is easiest to forget.
  **E9.S11** extends the checklist for the new state files (`provider-state.json`, `translation-cache.json`).

### Repo traps

- **`README.md` is the public face of a public repo** and is rendered on GitHub. Keep tables narrow, keep the
  download instructions above the new material, and do not push `⬇️ Download & use` below the fold.
- **`PublishFlagsTests` reads `README.md`?** No — it reads the build scripts and
  `packaging/signpath-signing.md` (`:44-79`). But **CI-7** says the SignPath wiring must edit
  `.github/workflows/release.yml` **and** `packaging/signpath-signing.md` in the same PR, and that
  `-p:EnableCompressionInSingleFile` must never appear in either **even as an example**. If the README ever
  quotes a build command, the same rule applies to it.
- **The About tab's prose lives in XAML with `Hyperlink`s** (`MainWindow.xaml:613-619`, `:642-670`) and
  `RequestNavigate="OpenLink"`. New links follow that pattern; `UpdateService`'s URL allow-list
  (`github.com`/`githubusercontent.com`) is about **downloads**, not about documentation links — do not confuse
  them, and do not widen it.
- No `.sln`; changing the README changes nothing about the build.
