# Story E3.S3: `ChainTranslator` replacing `FallbackTranslator`

Status: **ready-for-dev (Phase 4 — owner's go given)**

_Epic E3 (C) — Provider chain and the new default endpoint · increment 2 · **Release A.1: E2 and E3 are separate
PRs but ONE release** · the owner's Phase-4 go was given 2026-09-06 ("go pour la Phase 4, ne t'arrête pas",
`README.md` § Phase 4)._

> **Release rule, non-negotiable.** E2 shipped a breaker in front of an endpoint that 429s on request #1. This
> story is the first half of the answer: a paused tier is *skipped*, not *fatal*. It must ship in the same release
> as E2 (`architecture-cible.md` R7, owner's decision 2).
>
> **This is the first story of E3 and nothing else in the epic can start before it.** E3.S4, E3.S5 and E3.S7 all
> depend on the chain existing.

## Story

As a player,
I want a paused provider to be skipped instead of called,
So that the app stops spending requests on servers that have already refused.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E3.S3. Do not weaken._

1. **Given** the algorithm of §6.2, identical for `TranslateAsync` and `TranslateLinesAsync`
   **When** a tier's gate returns `Open(retryAt)`
   **Then** the tier is skipped, its `retryAt` is remembered, and **no HTTP request and no measurable delay** are
   spent on it.
2. **Given** a tier's gate returns `Wait(t)`
   **When** `t <= MaxSpacingWaitMs`
   **Then** the chain awaits `t`; when `t` is larger, the tier is skipped with `now + t` remembered.
3. **Given** every tier was skipped
   **When** the chain finishes
   **Then** it throws exactly one `TranslationException(AllProvidersPaused, …)` whose `RetryAt` is the
   **earliest** remembered `retryAt` — not the latest, not the first tier's.
4. **Given** at least one tier actually tried and failed
   **When** the chain finishes
   **Then** it throws that tier's most specific failure, not `AllProvidersPaused`.
5. **Given** I3
   **When** a real user cancel occurs mid-chain
   **Then** the `OperationCanceledException` propagates (`catch … when (ct.IsCancellationRequested) throw;`), and
   a `TaskCanceledException` from an `HttpClient` timeout falls through to the next tier instead.
6. **Given** I1
   **When** `ChainTranslator` is introduced
   **Then** `ITranslator` is unchanged; `ChainTier` is `(ProviderGate Gate, ITranslator Translator)`;
   `Services/FallbackTranslator.cs` is deleted.

## The three collisions with the shipped E2 code, settled before the tasks

`epics.md` E3.S3 and `architecture-cible.md` §6 were written **before** E2.S5 landed `HttpProviderCore`. Three
things they assume are no longer true in this worktree. Each is settled here, with the reasoning, and each is
flagged for Winston in the Dev Agent Record.

### D-1 — the chain must **not** call `TryEnter`. `HttpProviderCore` already does.

§6.2's pseudocode opens with `decision = tier.Gate.TryEnter(priority)`. But since `b592800`, **every request
already consults the gate** — `HttpProviderCore.SendAsync` calls `AdmitAsync` before the first attempt
(`HttpProviderCore.cs:169`, `:317-339`) and reports the outcome exactly once after (`:363-375`). If the chain also
called `TryEnter`, two things break, both of them in the "permanently paused app" risk class (R-01):

| | What breaks |
|---|---|
| **The rate ceiling** | `BucketCapacity = 2`. Two `TryEnter`s per logical request halves the effective ceiling: the *second* request in a burst would find an empty bucket where today the third does. `TP-RET`'s ceiling case and E2.S3's whole reserve model assume one token per request. |
| **The half-open probe (E2-h)** | A `TryEnter` on an elapsed open window returns `Probe(token)` and **latches the gate half-open**. The chain has no way to report that token — `ITranslator` has no channel for it (I1) — so the probe would be granted to the chain, spent by the core's *second* `TryEnter` (which now sees `HalfOpen` and refuses), and never reported. The gate stays half-open until `ProbeTimeout`, and the tier is dead for the window. This is exactly the failure E2-h's probe token exists to prevent, re-introduced from above. |

**Ruling adopted here: the chain reads `Gate.Snapshot()`, never `TryEnter`.** `Snapshot()` is side-effect free by
contract (`ProviderGate.cs:718-723` — "no clock advanced, no probe taken, no token spent"), which is precisely
what a *skip decision* needs. Admission, waiting, the probe and the report stay inside `HttpProviderCore`, once.

**And the skip predicate is `BlockedUntil`, not `State`.** This is the single most dangerous line in the story.
`GateState.Open` deliberately covers the whole window **including the moment it has elapsed** — the gate becomes
`HalfOpen` only when a caller actually *takes* the probe (`ProviderGate.cs:734-738`, and the comment there says
so). A chain that skipped on `State == Open` would skip the tier *forever*: nobody would ever call `TryEnter`, so
nobody would ever take the probe, so the gate would never close. **R-01, shipped.** The correct predicate is:

```csharp
var snap = tier.Gate.Snapshot();
if (snap.BlockedUntil is { } until && until > tier.Gate.Now())
{ skipped.Add((tier.ProviderId, until)); continue; }      // skip: the window is still running
// window elapsed, or never opened → let the core's TryEnter decide (it may take the probe)
```

### D-2 — "skipped" and "tried and failed" must be distinguishable, and today they are not

AC 2's *"`Wait(t)` larger than `MaxSpacingWaitMs` ⇒ the tier is skipped with `now + t` remembered"* and AC 4's
*"a tier that really tried"* need the chain to tell the two apart. With D-1, a tier refused by the ceiling raises
from inside the core (`HttpProviderCore.cs:333` → `Paused(...)`) as an ordinary `TranslationException` carrying
the gate's `LastKind` — indistinguishable from a real 429 the provider actually received.

**Minimal mechanism adopted: `TranslationException` gains `internal bool NotSent { get; init; }`**, set only by
`HttpProviderCore.Paused()`. One bool, no public surface change, no new type. The chain then reads:

```csharp
catch (TranslationException tex) when (tex.NotSent) { skipped.Add((id, tex.RetryAt ?? now)); continue; }
catch (TranslationException tex) { lastFailure = tex; continue; }
```

That makes **TP-CHN-04** (all paused ⇒ `AllProvidersPaused` with the earliest `retryAt` and **zero** requests),
**TP-CHN-05** (a real 403 wins over `AllProvidersPaused`) and **TP-CHN-06** (short `Wait` awaited and the tier
used; long `Wait` ⇒ skipped, `now + t` in the set) all literally true, with the wait itself still owned by the
core — which is where the injectable delay (IS-7) and `TestBackoffRedirect` already live, so no test sleeps.

### D-3 — `ProviderGate` has **no** `Id`

§6.1 says *"the tier carries its gate … the gate already has `Id` for logging"*. It does not:
`ProviderGates.For` closes over the id precisely **because** "a gate does not know its own"
(`ProviderGates.cs:118-128`, comment verbatim). But R-3 requires `LastOutcome.ProviderId` and
`LastOutcome.Skipped: [(ProviderId, Reason)]`, and AC 1's per-tier `Logging.Warn` line wants a name too.

**Adopted: `ChainTier` is `(string ProviderId, ProviderGate Gate, ITranslator Translator)`.** AC 6 names the
two-member shape; the third member is a superset that makes R-3 implementable and is recorded as a deliberate
deviation. Do not add `Id` to `ProviderGate` — the registry is the only thing that knows an id, on purpose.

## How to verify manually

1. `dotnet test tests/PWRUHelper.Tests` — green, and **no slower**: if it got slower, something is sleeping.
2. `git grep FallbackTranslator` returns nothing but this story file and the older investigation documents.
3. Run the app with a DeepL key set, no network: the Translator tab shows **one** sentence, not a cascade, and the
   log shows one `tr` line per tier that actually tried and none for a tier that was skipped.
4. Force a 429 on `gtx` (or hand-edit `%AppData%\PWRUHelper\provider-state.json` to a future `blockedUntil`),
   restart, and translate: **no `tr` line at all** for that provider, and the gate log's `OPEN` line explains it.
5. Then wait past the `blockedUntil` and translate again: the request **must** go out (the half-open probe). If it
   does not, the D-1 predicate is wrong and R-01 is shipped.
