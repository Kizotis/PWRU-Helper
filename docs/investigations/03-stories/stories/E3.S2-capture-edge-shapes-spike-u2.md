## Story

As the architect,
I want the real Edge contract before a line of `EdgeTranslator` exists,
So that a "second vendor" does not become a second way to fail.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E3.S2. Do not weaken._

1. **Given** the request body, the response shape and the required headers of
   `edge.microsoft.com/translate/translatetext` are all **[UNKNOWN]** (§7.2)
   **When** one successful live request/response pair is captured on a branch
   **Then** the exact body, the exact response JSON and the exact required headers are recorded and frozen as a
   fixture.
2. **Exit criterion (measurable).** One HTTP 200 with a usable translation, and a written statement of which
   headers were necessary (established by removing one at a time within the same short session, or explicitly
   marked "not narrowed").
3. **Go / no-go.** **Go:** the capture succeeds ⇒ E3.S5 may start. **No-go:** the route is dead, needs a token, or
   cannot be made to answer ⇒ **`EdgeTranslator` is not written**, the chain ships as GoogleDict → GoogleGtx, and
   the loss of the independent second vendor is recorded as an increase in risk R1.
4. **Given** §7.2 states "no `EdgeTranslator` code is written before that capture exists"
   **When** this story is not done
   **Then** E3.S5 is blocked and may not be started.

## Dev Notes

### This story writes no production code

Branch only. Its output is two fixtures and a recorded contract.

### Why the "no code before the capture" rule is absolute

The three [UNKNOWN]s are not cosmetic. A wrong body shape yields a 400 that `ProviderErrorMapper` classifies as
`Unknown`, the gate takes a strike, and after three of them the tier is open for a minute — so a guessed
`EdgeTranslator` does not fail loudly at build time, it fails *quietly in the field* as a tier that is always
paused. That is worse than not having the tier at all, because it also spends requests and log lines saying so.

### What A.1 ships if this is a no-go

Read chain: `[Azure opt-in] → GoogleDict → GoogleGtx → [Bergamot]`. Write chain: `[DeepL] → [Azure] → GoogleDict →
GoogleGtx → [Bergamot]`. Both still deliver the epic's headline: a working default endpoint on a network where
`gtx` 429s, and a gate that skips a paused tier at zero cost. What is lost is **vendor independence** — every free
tier is then Google, and one vendor decision takes the whole free path away. Record it as R1 increased, and say so
to the owner in the release note rather than in a footnote.

### Route freshness is the real risk

`benchmark…` §5.9/§4 records 40/40 clean in a burst, keyless, no token scraping — but the route is known-good for
**~1 month only**. A capture taken today may not describe the route in November. That is an argument for capturing
soon and for E3.S5's tier being cheap to remove, not for skipping the capture.
