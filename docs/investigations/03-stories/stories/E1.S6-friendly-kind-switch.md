# Story E1.S6: Map `Friendly()` onto `Kind` without changing any wording

Status: **ready-for-dev (Phase 4 — owner's go required)**

_Epic E1 (A) — Diagnosable translation pipeline · increment 0 · Release A.0 · ⛔ no production code until the
owner's explicit go. **This is the last story of the increment** — it is the mitigation for E1.S3's risk._

## Story

As a player,
I want this increment to be invisible,
So that a refactor cannot be blamed for a message I have never seen before.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E1.S6. Do not weaken._

1. **Given** `MainWindow.xaml.cs:404-410` builds its message from exception types
   **When** it becomes a `Kind` switch in the shape of §4.4
   **Then** each `Kind` returns **one of today's existing strings**, chosen so that every string a user can
   currently reach is still reachable, and **no new string is introduced in this increment**.
2. **Given** the parenthesised feed-row wrapper `$"({Friendly(ex)})"` at `MainWindow.Live.cs:281` and
   `MainWindow.Ocr.cs:298`
   **When** this story lands
   **Then** those two call sites are untouched.
3. **Given** a diff of the user-visible strings before and after
   **When** it is taken
   **Then** it is empty.

## Tasks / Subtasks

- [ ] **T1 — Turn `Friendly` into a `Kind` switch** (AC: 1) — `MainWindow.xaml.cs:404-410` **only**
  - [ ] Today: `TranslationException te => te.Message`, `HttpRequestException => "no Internet connection"`,
        `TaskCanceledException => "the request timed out"`, `_ => ex.Message`.
  - [ ] After: the §4.4 shape — `TranslationException te => te.Kind switch { … }` with the two non-`TranslationException`
        arms and the `_ => ex.Message` default **kept exactly as they are**.
  - [ ] **Every arm returns a string that exists in the product today.** The natural mapping, since E1.S2/E1.S3
        preserved the messages at the throw sites, is `te.Message` for the kinds whose sentence is already correct
        — that is a legitimate arm and it keeps AC 3 trivially true. Where an arm needs a literal (a `Kind` no
        current site produces), use the sentence the user reaches today for the nearest current path; **do not
        invent one**.
  - [ ] `Cancelled` is unreachable by contract (E1.S2) but the switch must stay **total** — no
        `ArgumentOutOfRangeException` arm that a future `Kind` could hit at run time.
  - [ ] `AllProvidersPaused` is declared but not yet reachable (nothing raises it until **E3.S3**). Give it a
        current-wording arm and a `// E7.S1 replaces this` marker.
- [ ] **T2 — Do not touch the two feed-row call sites** (AC: 2)
  - [ ] `MainWindow.Live.cs:281` and `MainWindow.Ocr.cs:298` both do
        `foreach (var it in items) it.TranslationBody = $"({Friendly(ex)})";`. **Unchanged.** The parentheses are
        load-bearing twice over: they are what the owner's screenshot shows (`README.md`, owner's answer (b)), and
        the `(`-prefix is the **I4** rule that keeps failures out of the cache (`CachingTranslator.cs:82-85`).
  - [ ] The other four call sites — `MainWindow.Translate.cs:41`, `:106`, `MainWindow.Live.cs:235`, `:238`,
        `MainWindow.Ocr.cs:248` — are also untouched by this story.
- [ ] **T3 — Make it testable without restructuring `MainWindow`** (AC: 1)
  - [ ] `Friendly` is `private static`. Expose it as `internal static` (the suite already reaches internals via
        `InternalsVisibleTo`, `PWRUHelper.csproj:28`) **or** test it through a thin wrapper. **Do not restructure
        `MainWindow` for it** — `epics.md` says so explicitly, and the code-behind shape is a deliberate project
        decision (no MVVM).
  - [ ] Keep it a **pure function of `Kind`** — no reads of settings, no timers, no `RetryAt` formatting. `{countdown}`
        is rendered from `RetryAt` **at display time by `MainWindow`**, never by `Services/` (I2, §4.4), and that
        arrives in E7.S1/E7.S2.
- [ ] **T4 — The empty-diff proof** (AC: 3)
  - [ ] A unit case per `Kind` asserting the returned sentence equals the string the product ships today (list them
        explicitly in the test, so a future edit to the wording fails here first).
  - [ ] Take a literal diff of the user-visible strings before and after the change (grep the string literals in
        `MainWindow*.cs`, `Services/*.cs` and `MainWindow.xaml`) and paste the result — **empty** — into the PR.
        That paste is the DoD.

## Dev Notes

### Invariants this story must keep

- **I4** — the `(`-prefix contract. `Friendly` returns the *inner* sentence; the parentheses are added by the two
  feed-row call sites, and `CachingTranslator.IsCacheable` (`CachingTranslator.cs:82-85`) refuses to cache anything
  starting with `(`. Never return a string that already starts with `(`, and never remove the wrapper.
- **I2** — no formatting logic moves into `Services/`.
- **I14** — no new copy path; the WPF `Clipboard` ban is untouched (all clipboard writes stay in
  `Services/ClipboardService`).
- **I16** — the LIVE loop is untouched.

### Rulings and decisions that apply

- **GAP-4 ruling (binding):** the copy deck becomes **`Services/UserMessages.cs`**, a UI-free static class holding
  every user-facing sentence keyed by error kind / state; tests assert on it and XAML/code-behind reads it.
  **That file is E7.S1's to create, not this story's** — increment 0 introduces no new string and no new file the
  copy has to move through twice. What this story owes E7.S1 is that the switch is a **pure function of `Kind`
  with one sentence per arm**, so the later move is mechanical (sprint-plan note 3).
- `architecture-cible.md` §4.4's `«Sally: …»` placeholders are **not** to be written into the code here. They are
  Sally's copy, landing in **E7.S1** together with the countdown.
- This story is deliberately last in the increment: it is the mitigation for E1.S3's "a mis-classification changes
  a user-visible string by accident" risk. If T4's diff is not empty, **E1.S3 has a bug** — fix the classification,
  not the wording.

### Repo traps

- `MainWindow.xaml.cs` is the core partial (fields, ctor, lifecycle, hotkeys, shared helpers). `Friendly` lives
  there with the other shared helpers; leave it there.
- Do not touch `_restoringSettings` (`MainWindow.xaml.cs:35`, cleared at `:201`) or `ApplySettings` — this story
  persists nothing and adds no control.
- `dotnet test tests/PWRUHelper.Tests` green and headless. **No `.sln`.** `InternalsVisibleTo` and the `tests\**`
  `DefaultItemExcludes` intact.

### Current state of the code being modified

```csharp
// MainWindow.xaml.cs:403-410 at the baseline
/// <summary>Turn an exception into a short, non-technical message for the user.</summary>
private static string Friendly(Exception ex) => ex switch
{
    TranslationException te => te.Message,
    System.Net.Http.HttpRequestException => "no Internet connection",
    TaskCanceledException => "the request timed out",
    _ => ex.Message,
};
```
