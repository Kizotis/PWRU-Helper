# Story E1.S3: Classify every provider outcome in one `ProviderErrorMapper`

Status: **review**

_Epic E1 (A) — Diagnosable translation pipeline · increment 0 · Release A.0 · ⛔ no production code until the
owner's explicit go._

## Story

As the maintainer,
I want one function that turns a raw HTTP outcome into a kind,
So that a bot block stops reading like a bug and no second place can ever disagree about what a 403 means.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E1.S3. Do not weaken._

1. **Given** the ordered rules of `architecture-cible.md` §4.2 (first match wins)
   **When** `ProviderErrorMapper.Classify(resp, bodyHead, transport, keyWasSent, ct)` is called
   **Then** it returns `Cancelled` only when `ct.IsCancellationRequested`; `Timeout` for an OCE with the token
   **not** cancelled; `Network` for `HttpRequestException`; `RateLimited` for 429; `AuthFailed` for 401;
   `QuotaExhausted` for 403 with a key and a quota envelope; `AuthFailed` for 403 with a key; `Blocked` for 403
   with no key; `QuotaExhausted` for 456; `Unavailable` for ≥500; `BadResponse` for an unparseable success;
   `Unknown` for anything else non-success.
2. **Given** today's `TranslationService.cs:138-143` folds 403 with 400/404 into
   `Translation service error (HTTP {code})`
   **When** the mapper lands
   **Then** a 403 with no key classifies as `Blocked` and a 400 classifies as `Unknown` — they are no longer the
   same outcome.
3. **Given** the mapper is a total function
   **When** it is handed an outcome no rule matches
   **Then** it returns `Unknown` and never throws, never guesses.

## Dev Notes

### Invariants this story must keep

- **I3 — the OCE filter.** Row 2 of the table *is* I3 written down. A `TaskCanceledException` with an uncancelled
  token is a **timeout**, never a cancel. Getting this wrong silently disabled the DeepL→Google fallback and left a
  zombie LIVE indicator once already.
- **I2** — the mapper is pure and headless: no `Logging`, no WPF, no I/O. It takes an `HttpResponseMessage` and
  returns an enum value.
- **I11** — the mapper never puts a body, a URL or a key anywhere. It *reads* `bodyHead`; **E1.S5** is the only
  story that writes anything to the log.
- **I1**, **I16** — no interface change, no LIVE change.

### Rulings and decisions that apply

- **The mapper is the single classification point.** After this story, no second place in the codebase may decide
  what a status code means. `HttpProviderCore` (E2.S5) becomes its only caller; until then the two existing
  providers call it directly (`plan-migration.md` increment 0, `epics.md` technical notes).
- Row 11 (HTML on any status) is **E1.S4's**, and it must sit **before** the success/parse path. Do not implement
  it here; do not reorder the table so that E1.S4 has to.
- `Unknown` must never become common. It is the total-function escape hatch, and its appearance in a field log is
  a defect report against this file.

### Repo traps

- `TranslationService` has **one** `GetAsync` call site (`:131`); `DeepLTranslator` has **one** `SendAsync`
  (`:78`). If a second appears, the mapper has been bypassed.
- Reading the body to produce `bodyHead` must not consume the stream twice. Read once
  (`resp.Content.ReadAsStringAsync(ct)`), keep the first ~400 chars for classification and hand the same string to
  the parser. Today the success path reads it at `TranslationService.cs:134`.
- `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) + `tests\**` exclusion (`:18`) intact.
  **No `.sln`.** `dotnet test tests/PWRUHelper.Tests` green and headless.

### Current state of the code being modified

- `TranslationService.cs:132-148` — success ⇒ read body and break; otherwise `code = (int)resp.StatusCode`,
  `transient = 429 || >= 500`, non-transient ⇒ throw `HTTP {code}` (this is the fold this story breaks up), a 429
  on the third attempt ⇒ the "wait a minute" string, any other transient on the third ⇒ "unavailable".
- `TranslationService.cs:151` catches `HttpRequestException` **and retries** — that behaviour is E2.S5's to change
  (`Network` will stop being retried); leave it alone here.
- `DeepLTranslator.cs:96-106` — the status switch that already distinguishes 401/403, 456 and 429.
