# Story E3.S6: Demote `gtx` — rename to `GoogleGtxTranslator`, extract `TextChunker`

Status: **ready-for-dev (Phase 4 — owner's go given)**

_Epic E3 (C) — Provider chain and the new default endpoint · increment 2 · **Release A.1: E2 and E3 are separate
PRs but ONE release** · the owner's Phase-4 go was given 2026-09-06 (`README.md` § Phase 4)._

> **Scheduling note — this story moves.** `epics.md` lists it sixth. **E3.S4 depends on `TextChunker`**, which
> only exists after this story, so the implementation order is **E3.S3 → E3.S6 → E3.S4 → E3.S8 → E3.S7** (E3.S5
> slots before E3.S7 if U2 lands). Same shape as E1, where E1.S7 was pulled forward because E1.S4 needed it.
>
> **This is a rename plus a move. It is mechanical, it is wide, and its whole risk is documentation drift.** 52
> references across 8 test files, 6 comment references in `Services/`, 3 production call sites, and one line of
> `project-context.md`. Nothing about the endpoint's behaviour changes.

## Story

As the maintainer,
I want the old endpoint kept but last,
So that a `client=` id that may come back costs nothing to keep while it stops being the default.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E3.S6. Do not weaken._

1. **Given** `Services/TranslationService.cs`
   **When** it is renamed to `Services/GoogleGtxTranslator.cs` with provider id `google-gtx`
   **Then** the endpoint, the User-Agent, the chunking and the batch/per-line shape are otherwise untouched; only
   typed errors, 2 attempts with jitter, gate admission and logging change.
2. **Given** two providers now need chunking
   **When** `ChunkText` and `HardSplit` move to `Services/TextChunker.cs`
   **Then** `tests/PWRUHelper.Tests/ServicesTests.cs:80,91` are re-pointed and the byte-budget and
   content-preservation assertions pass unchanged.
3. **Given** R5 (the rename breaks docs and muscle memory)
   **When** this story lands
   **Then** the **same PR** updates the "Translation Pipeline Rules" section of `project-context.md`, which names
   `TranslationService` today.
4. **Given** the existing `rateLimited` latch (`TranslationService.cs:99-105`)
   **When** the provider is ported
   **Then** the latch is **kept** (I16) and now latches specifically on a `RateLimited`/`Blocked` `Kind` rather
   than on any `TranslationException`.

## What has already happened, so this story does less than `epics.md` thinks

AC 1's *"only typed errors, 2 attempts with jitter, gate admission and logging change"* describes work that
**E1 and E2 already did**. In this worktree at `b592800`, `TranslationService` is already:

- typed (E1.S2/S3 — `TranslationException(kind, …)`, `ProviderErrorMapper`),
- on 2 attempts with full jitter, gate-admitted and logged (E2.S5 — everything runs through
  `HttpProviderCore`, `TranslationService.cs:62`, `:182-191`),
- carrying provider id `ProviderIds.GoogleGtx` **already** (`TranslationService.cs:34`, and E2.S2's comment at
  `ProviderGates.cs:11` says it was spelled `google-gtx` from the start *precisely* so a field report from before
  the rename still reads correctly).

**So this story is exactly two things: a rename, and a move of two static methods.** Plus AC 4, which is the one
behaviour change left in it.

## Dev Notes

### Invariants this story must keep

- **I1** — `ITranslator` unchanged and **not moved out of the renamed file** (T2).
- **I3** — the three OCE filters in `TranslateLinesAsync` stay. AC 4 edits the `TranslationException` catch that
  sits *between* them; do not disturb the filters while doing it.
- **I5** — the batch/per-line shape is untouched here. `PerLineCap` is E3.S8's.
- **I16 — the eleven LIVE behaviours are kept**, and the `rateLimited` latch is one of them. AC 4 narrows *what
  latches it*; it does not remove it, and it does not change what a latched line says.
- **I11** — `RequestLog` already writes `provider=google-gtx`. The rename must not change a single logged byte:
  a field report from before this release must still be readable against the code after it. That is why E2.S2
  spelled the id `google-gtx` from day one.

### Rulings that apply

- **E2-d:** the three per-line placeholder strings belong to E3.S8 (policy) and E7.S1 (copy). Not here.
- **R5 (risk):** the rename breaks docs and muscle memory; the mitigation is the `project-context.md` edit **in
  the same PR** plus the two `ServicesTests` references and the glossary. There is nothing else that names the
  type — T4 and T5 are the full list, verified by grep, not by memory.
- **Why keep `gtx` at all** (`architecture-cible.md` §7.3, worth one line in the PR): it costs nothing to keep,
  it is the only tier proven against this app's real traffic for two years, and the block is keyed on the
  `client=` id — an id can come back.

### Repo traps

- **`git mv`, not delete-and-create.** A 260-line file recreated is a 260-line diff nobody can review, and the
  review is the only thing standing between "rename" and "rename plus an accidental edit".
- **`HttpSeamGuardTests`'s anti-vacuity asserts** (`:59-60`, `:100-104`) name provider types **literally**. They
  will fail loudly on the rename, which is correct. Re-point; do not delete.
- **`ProviderStateStore.cs:219`** already carries a comment anticipating this rename ("`For(string)` takes any id
  and validates none, so E3.S6's `google-gtx` rename is one …"). Nothing to do, but read it: it is the reason no
  persisted state migration is needed.
- **`TranslationPolicy` has a grade scan** and a comment-format scan tolerant of formatting but not of missing
  grades (E1.S7's review). Editing `:43`'s comment is safe; deleting the grade is not.
- No settings control is touched: `_restoringSettings` is not engaged.
- `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact. **No `.sln`.**

## How to verify manually

1. `git diff --stat` shows a **rename**, not a delete plus an add.
2. `git grep TranslationService` returns nothing outside this docs folder and the historical investigation files.
3. `git diff` on the renamed file, filtered to non-comment lines, shows **only**: the type name, the removed
   `ChunkText`/`HardSplit`, and AC 4's `when (tex.Kind is …)` filter. Nothing in the URL, the UA, the timeout or
   the batch loop.
4. Run the app and translate one line: identical behaviour, and `%AppData%\PWRUHelper\logs\log.txt` still says
   `provider=google-gtx` — the same string as before the rename.
5. Read `project-context.md` §"Translation Pipeline Rules" out loud against the code. If it does not describe
   what is there, R5 has fired.
