# Story E1.S4: Detect the HTML abuse page before parsing, never after

Status: **done**

_Epic E1 (A) — Diagnosable translation pipeline · increment 0 · Release A.0 · ⛔ no production code until the
owner's explicit go._

## Story

As a player,
I want a Google block page to be reported as a block,
So that I stop being told the service "returned an unexpected response" when it plainly told us to stop.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E1.S4. Do not weaken._

1. **Given** today an HTML block page served with a 200 becomes an "unexpected response" only by accident, through
   the JSON parser at `TranslationService.cs:172-177`
   **When** the §4.3 sniffing lands
   **Then** the body is classified **before** it is parsed: content-type `text/html` or a non-JSON media type takes
   the HTML path; otherwise the first non-whitespace character being `<` in the first 200 characters takes the HTML
   path; only a body that survives both is handed to `JsonDocument.Parse`.
2. **Given** the HTML path
   **When** the first ~400 characters are de-tagged and lower-cased
   **Then** a marker from `TranslationPolicy.RateLimitMarkers` (`"automated queries"`, `"unusual traffic"`) yields
   `RateLimited`; a marker from `BlockMarkers` (`"we're sorry"`, `"captcha"`, `"recaptcha"`) yields `Blocked`; no
   marker yields `Blocked` with the de-tagged 120-character head recorded in the log line.
3. **Given** the body measured on 2026-09-06 (`benchmark…` §3.1): *"Sorry... We're sorry... but your computer or
   network may be sending automated queries."*
   **When** it arrives on **any** status, 200 included
   **Then** it classifies as `RateLimited`.

### Rulings and decisions that apply

- `benchmark-fournisseurs.md` §11.4 item 1 names "parse-then-guess" as **the single most common bug across every
  project surveyed**. The rule is therefore stated as an ordering rule, not as a heuristic: *the body is classified
  before it is parsed, never after.*
- The markers live in `TranslationPolicy` (E1.S7) precisely so a re-phrasing by Google is **one edit**, in a file
  where the constant carries its evidence grade.
- Wording is unchanged in this increment. A body that now classifies as `RateLimited` instead of reaching the JSON
  parser must still produce the **same sentence the user sees today** for that path — E1.S3's T3 rule applies here
  too, and E1.S6 is the seam that makes E7.S1's real copy a one-file change.

### Repo traps

- The captured 429 body is **evidence**. Copy it byte-for-byte from `benchmark-fournisseurs.md` §3.1; a paraphrase
  makes the regression guard worthless and the DoD explicitly forbids it.
- Read the response body **once**. `TranslationService.cs:134` already reads it on the success path; the sniff must
  reuse that string rather than re-reading a consumed stream.
- `dotnet test tests/PWRUHelper.Tests` stays green and **headless** — fixtures are files on disk, not network.
- `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and the `tests\**` exclusion (`:18`) intact. **No `.sln`.**

### Completion Notes List

- **T1 — the sniffing rule, at E1.S3's seam** (`Services/ProviderErrorMapper.cs:116-149`). Row 11 sits exactly
  where E1.S3 left the comment: after row 10, before the success branch, inside the `resp != null` block.
  **Nothing above it was reordered or edited.** It is not gated behind `!IsSuccessStatusCode`, so it applies on
  any status, 200 included.
- **The precedence rule, chosen and pinned** (`:184`, `A_declared_non_JSON_content_type_takes_the_HTML_path_…`).
  A **declared** media type that is not JSON (`text/html`, `text/plain`, anything but `application/json`,
  `text/json`, `*+json`) takes the HTML path **even when the body would have parsed** — "never parse-then-guess"
  means the body's parseability may not be the tie-breaker. The body sniff then wins over a content-type that
  claims JSON (TP-MAP-14), so the two signals are an OR, checked in §4.3's order.
  **One case §4.3 does not name: an ABSENT content-type**, and it is read the other way — nothing was declared,
  so the '<' sniff answers alone. Reading "no JSON media type" as "including none at all" would turn an
  unlabelled healthy 200 into a `Blocked` with an empty log head — the wrong guess row 13 exists to avoid — and
  it would buy nothing, because an unlabelled HTML page still starts with '<'. Both halves are pinned.
- **T2 — the de-tagger** (`:218`), a hand-written single pass, no regex, `internal static`, in the mapper's own
  file. Tag boundaries become one space (`<div>We're</div><div>sorry</div>` still reads as two words), whitespace
  collapses, and the CONTENT of `<script>` / `<style>` is dropped — it sits *between* tags rather than inside
  one, so a naive de-tagger keeps it. The head keeps the page's own casing (§10.1's example does); only the
  matching text is lower-cased, against the marker lists that `TranslationPolicy` guarantees are lower-case. The
  arrays are read with a `foreach` and never sorted, copied or rewritten in place.
- **DEVIATION, and the one number this story changed from the letter of the task.** T2 says "a bounded,
  single-pass scan over ≤ 400 chars". The scan is bounded at **both** ends — at most 400 characters *produced*,
  at most 8192 *read* (`:61`) — because 400 **input** characters would have broken AC 3 on the very body the
  story exists for: in the recorded page the first RateLimitMarker sits at raw offset **779** (`We're sorry` at
  709), behind a `<style>` block and a six-tag logo. De-tagged, it is at offset **93** — comfortably inside the
  400-character head. A 400-char input scan would have classified the measured P2 page as an unrecognised HTML
  page. Both bounds are asserted (`The_de_tagger_is_bounded_in_both_directions`): a 5 MB body yields a 400-char
  head, and a needle buried behind 100 000 padding tags is not reached.
- **Both marker lists are read** (`:132`, `:139`), and the two `Blocked` returns are deliberately not merged.
  They are two different §4.3 outcomes that share a Kind: a captcha we recognise, and a page nobody has a phrase
  for. Rows 6/7/8 set the precedent one screen above — the table's order written out line by line so a reviewer
  can diff it. Merging them would also leave `TranslationPolicy.BlockMarkers` unread in production, which is a
  graded constant nobody exercises and a re-phrasing that would be a silent no-op.
- **The 120-char head** travels as `out string? htmlHead` on a six-argument `Classify` overload (`:75`); the
  five-argument one (`:65`) forwards to it, so **every E1.S3 call site compiles unchanged**. It is `null`
  whenever the HTML path was not taken, so a caller cannot log a head for a body that was never sniffed. I11
  holds: it is the *server's* page, de-tagged and capped, and today every caller discards it — **E1.S5 is the
