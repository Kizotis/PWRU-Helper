# Story E1.S4: Detect the HTML abuse page before parsing, never after

Status: **ready-for-dev (Phase 4 — owner's go required)**

_Epic E1 (A) — Diagnosable translation pipeline · increment 0 · Release A.0 · ⛔ no production code until the
owner's explicit go._

## Story

As a player,
I want a Google block page to be reported as a block,
So that I stop being told the service "returned an unexpected response" when it plainly told us to stop.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E1.S4. Do not weaken._

1. **Given** today an HTML block page served with a 200 becomes an "unexpected response" only by accident, through
   the JSON parser at `TranslationService.cs:172-177`
   **When** the §4.3 sniffing lands
   **Then** the body is classified **before** it is parsed: content-type `text/html` or a non-JSON media type takes
   the HTML path; otherwise the first non-whitespace character being `<` in the first 200 characters takes the HTML
   path; only a body that survives both is handed to `JsonDocument.Parse`.
2. **Given** the HTML path
   **When** the first ~400 characters are de-tagged and lower-cased
   **Then** a marker from `TranslationPolicy.RateLimitMarkers` (`"automated queries"`, `"unusual traffic"`) yields
   `RateLimited`; a marker from `BlockMarkers` (`"we're sorry"`, `"captcha"`, `"recaptcha"`) yields `Blocked`; no
   marker yields `Blocked` with the de-tagged 120-character head recorded in the log line.
3. **Given** the body measured on 2026-09-06 (`benchmark…` §3.1): *"Sorry... We're sorry... but your computer or
   network may be sending automated queries."*
   **When** it arrives on **any** status, 200 included
   **Then** it classifies as `RateLimited`.

## Tasks / Subtasks

- [ ] **T1 — The sniffing rule, in `ProviderErrorMapper`** (AC: 1) — at the `// E1.S4` seam E1.S3 left
  - [ ] Step 1: read `Content-Type`. `text/html`, or **any** non-JSON media type, ⇒ the HTML path.
  - [ ] Step 2: otherwise read **at most the first 200 characters**; if the first non-whitespace character is `<`
        ⇒ the HTML path. **The sniff wins over a content-type that claims JSON** (TP-MAP-14).
  - [ ] Step 4: only a body that survived steps 1–3 reaches `JsonDocument.Parse`. The ordering is the story: today
        the block page reaches the parser and becomes a `JsonException`
        (`TranslationService.cs:172-177`) — after this story it can never get there.
  - [ ] This applies on **any status, 200 included** (§4.2 row 11). Do not gate it behind `!IsSuccessStatusCode`.

## Dev Notes

### Invariants this story must keep

- **I11** — the 120-character head is **de-tagged and whitespace-collapsed**, and it is the *server's* page, never
  the user's text. Nothing else from the body may travel anywhere. E1.S5 is the story that actually writes it.
- **I2** — pure, headless, no `Logging` call from the mapper.
- **I1**, **I16** — untouched.

### Rulings and decisions that apply

- `benchmark-fournisseurs.md` §11.4 item 1 names "parse-then-guess" as **the single most common bug across every
  project surveyed**. The rule is therefore stated as an ordering rule, not as a heuristic: *the body is classified
  before it is parsed, never after.*
- The markers live in `TranslationPolicy` (E1.S7) precisely so a re-phrasing by Google is **one edit**, in a file
  where the constant carries its evidence grade.
- Wording is unchanged in this increment. A body that now classifies as `RateLimited` instead of reaching the JSON
  parser must still produce the **same sentence the user sees today** for that path — E1.S3's T3 rule applies here
  too, and E1.S6 is the seam that makes E7.S1's real copy a one-file change.

### Repo traps

- The captured 429 body is **evidence**. Copy it byte-for-byte from `benchmark-fournisseurs.md` §3.1; a paraphrase
  makes the regression guard worthless and the DoD explicitly forbids it.
- Read the response body **once**. `TranslationService.cs:134` already reads it on the success path; the sniff must
  reuse that string rather than re-reading a consumed stream.
- `dotnet test tests/PWRUHelper.Tests` stays green and **headless** — fixtures are files on disk, not network.
- `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and the `tests\**` exclusion (`:18`) intact. **No `.sln`.**

head, and the classification must read `RateLimited`.
