# Story E6.S2: `AzureTranslator` over raw `HttpClient`

Status: **review**

_Epic E6 (F) — Bring your own key: Azure · increment 5 · **Release B.1** · the owner's Phase-4 go was given
2026-09-06 (`README.md` § Phase 4). Owner's decision 5, Phase 2: **"Azure AI Translator F0 as a second user-key
slot — Yes, alongside DeepL."**_

> **This is the cheapest provider story this project will ever write, and it is worth saying why.** E1, E2 and E3
> built the whole pipeline around a provider: `HttpProviderCore` owns the gate, the two attempts, the full
> jitter, the `Retry-After` floor, the redacted §10.1 log line and the OCE filter; `ProviderErrorMapper` owns the
> classification — **including Azure's 403-quota envelope, which already ships** (`ProviderErrorMapper.cs:118`,
> `QuotaMarkers` at `:44`). What is left in this file is what `DeepLTranslator.cs` has left in it: **the URL, the
> two headers, the body, the parser and the count-mismatch throw.** Everything else is a `ProviderOptions` record
> and one `_core.SendAsync` call.
>
> **And Azure is the only tier with a true 1:1 array contract** (§7.5). Google needs `\n`-joins and per-line
> fallbacks; Azure returns one element per input, in order, up to 1,000 of them. That makes it not merely the
> fastest tier a keyed user gets but the **safest** — which is the sentence the epic asks you to keep in mind
> while writing the never-pad throw.

## Story

As a player with a key,
I want the fastest and most reliable tier when I have paid nothing for it,
So that my own quota gives me a better result than the shared free door.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E6.S2. Do not weaken._

1. **Given** §7.5
   **When** the provider sends a request
   **Then** it is
   `POST https://api.cognitive.microsofttranslator.com/translate?api-version=3.0&from={src}&to={tgt}` with
   `Ocp-Apim-Subscription-Key`, `Ocp-Apim-Subscription-Region` and `Content-Type: application/json; charset=utf-8`,
   body `[{"Text":"line 1"},{"Text":"line 2"}]`, and `from` omitted for auto-detect.
2. **Given** the response `[{"translations":[{"text":…,"to":…}]}, …]`
   **When** the element count does not match the input count
   **Then** it is a `BadResponse` and **never padded** (I5) — Azure is the only tier with a true 1:1 array contract
   and is therefore the safest, not merely the fastest.
3. **Given** the error mapping of §7.5
   **Then** 401 → `AuthFailed`; 403 with a quota/limit envelope → `QuotaExhausted`, else `AuthFailed`; 429 →
   `RateLimited`; 5xx → `Unavailable`. The Azure error `code` is logged; the `message` is never shown raw.
4. **Given** NFR6
   **When** the provider is written
   **Then** it uses a raw `HttpClient` and **not** `Azure.AI.Translation.Text` — the SDK brings its own retries and
   timeouts that would fight `HttpProviderCore`, plus ~3.0–3.2 MB of assemblies of which ~1.3 MB is an MSAL stack
   this app never calls (§7.5, A5).

## The contract, in one table (`architecture-cible.md` §7.5)

| | |
|---|---|
| Provider id | `azure` — **already spelled**, `ProviderGates.cs:21`, and listed in `ProviderIds.All` at `:31` |
| Endpoint | `POST https://api.cognitive.microsofttranslator.com/translate?api-version=3.0&from={src}&to={tgt}` |
| `from` omitted | auto-detect; the response then carries `detectedLanguage` — **which is discarded (I7)** |
| Headers | `Ocp-Apim-Subscription-Key: {AzureApiKey}`, `Ocp-Apim-Subscription-Region: {AzureRegion}`, `Content-Type: application/json; charset=utf-8` |
| Body | `[{"Text":"line 1"},{"Text":"line 2"}]` — native batching, **up to 1,000 elements** |
| Response | `[{"translations":[{"text":"…","to":"en"}]}, …]`, one element per input, in order |
| Limits | 50,000 characters per request across all targets; F0 **2 M chars/month** and **2 M chars/hour** (~33,300/min); documented latency 150–300 ms under 100 characters; no concurrency limit |
| Measured | **93 ms RTT** from the owner's network — the fastest of the three official APIs probed (`benchmark…` §3.3) |
| Errors | `{"error":{"code":…,"message":…}}` — the **code** is logged, the **message** is never shown raw |

        — the **exact** shape of `DeepLTranslator.cs:32,39` widened with `GoogleDictTranslator.cs:79-80`'s

        — **no User-Agent.** `DeepLTranslator.cs:56` states the rule for a vendor path: *"a shared factory that

        path. `HttpSeamGuardTests` pins that the Chrome UA is Google's only.
  - [x] Static shared `HttpClient` field + private client only when a handler is passed — `DeepLTranslator.cs:21,45`.
- [x] **T2 — `ProviderOptions` (AC 3, and this is where the whole error mapping comes from).**
  - [x] **`KeyWasSent: true`.** This one flag is what makes 401 → `AuthFailed` and 403+quota-envelope →
        `QuotaExhausted` instead of `Blocked` (ruling **E2-g**; `ProviderErrorMapper.cs:108,118-121`). Get it
        wrong and a rejected Azure key reads as "your connection is blocked".
  - [x] **`Secret: key`.** The core scrubs it out of any body head before the §10.1 line is built —
        `RequestLog` cannot, because it is UI-free and does not know a key's value (I11,
        `DeepLTranslator.cs:49-54`). **Two I11 gaps were closed in the E2.S5 review over exactly this path**;
        do not ship a keyed provider without it.
  - [x] `StatusMessage` / `TransportMessage` / `PausedMessage` are the **log's** account, not the player's:
        since E1.S6 what the player reads is `UserMessages.Sentence(kind)` (`MainWindow.xaml.cs:502` →
        `UserMessages.For`). Write them plainly, name Azure, and put **no key** in them.
  - [x] Never interpolate the `ProviderOptions` record itself — its `ToString()` is overridden for that reason
        (`HttpProviderCore.cs:582-587`).
- [x] **T3 — The request (AC 1).**
  - [x] Query: `api-version=3.0`, `to={tgt}`, and **`from={src}` only when the source is not `auto`/empty** —
        `DeepLTranslator.ToDeepLSource` (`:182-186`) is the shape; Azure's version is simpler (no upper-casing,
        no regional variants: `to=en`, not `EN-US`).
  - [x] Body: `JsonSerializer.Serialize` of an array of `{ Text = line }`. **`Text` with a capital T** — Azure's
        request schema is case-sensitive on the property name.
  - [x] `Content-Type: application/json; charset=utf-8` — set it on the `StringContent`, not by hand-adding a
        header.
  - [x] `req.Headers.TryAddWithoutValidation("Ocp-Apim-Subscription-Key", _key);` and the same for
        `Ocp-Apim-Subscription-Region` — `TryAddWithoutValidation` for the same reason
        `DeepLTranslator.cs:139` uses it.
  - [x] **A fresh `HttpRequestMessage` per attempt.** `_core.SendAsync` takes a `Func<HttpRequestMessage>`
        precisely because a message may not be sent twice and this provider now has a second attempt
        (`DeepLTranslator.cs:130-141`).
  - [x] Hand the joined text to `_core.SendAsync` **to be measured, never kept** (I11,
        `DeepLTranslator.cs:143-146`).
- [x] **T4 — The parser and the never-pad throw (AC 2).**
  - [x] `internal static List<string> Parse(string json)` — walk the root array, take
        `[i].translations[0].text`. Wrap in the same
        `catch (Exception ex) when (ex is JsonException or KeyNotFoundException or InvalidOperationException)`
        → `throw new TranslationException(TranslationErrorKind.BadResponse, …)` as
        `DeepLTranslator.cs:161-169`, and for the same documented reason: the **parser** detects a 200 whose body
        is not the provider's shape (§4.2 row 12); the mapper only names it.
  - [x] `TranslateLinesAsync`: `if (outp.Count == lines.Count) return outp;` else **throw `BadResponse`**.
        Copy `DeepLTranslator.cs:104-112` including its comment. **I5. Never pad.** The comment there records
        what padding cost: *"it bypassed the fallback AND cached raw Russian source as if it were a
        translation."*
  - [x] `detectedLanguage` is **read past, not read** (I7): the source is the caller's choice per message
        (`GoogleDictTranslator.cs:116-119` says it in as many words). TP-PRV-10 asserts the auto-detect shape
        still parses 1:1 — it does not ask you to surface the detection.
  - [x] **No `TextChunker`.** Azure's cap is 50,000 characters per request; the app's `MaxQueryBytes` chunking
        exists for Google's URL budget. A chat line is never near either.
- [x] **T5 — Empty-key / empty-region guard.**
      `if (string.IsNullOrEmpty(_key)) throw new TranslationException(AuthFailed, "No Azure API key set.");` —
      `DeepLTranslator.cs:121-122`'s exact shape, extended to the region, because **a key without a region is a
      guaranteed 401** (§12). Throwing before the send costs the user nothing and spends no gate strike; a real
      401 would open the gate for a mistake the UI can prevent (E6.S3 AC 5 prevents it at the Save button).
- [x] **T6 — Do NOT wire Azure into a chain here.** `TranslationChains.cs:162-164` and `:216` hold the two
      commented Azure slots, and both name the story that fills them: `BuildWrite` is **E6.S3**'s and
      `BuildRead` is **E6.S4**'s. This story ends at a provider that a test can drive. Keeping the wiring out is
      what lets E6.S3's settings work land against a provider that is already green.
- [x] **T7 — Tests (TP-PRV-07..10) + fixtures.**
- [x] **T8 — `dotnet test tests/PWRUHelper.Tests`.** Green, headless, no network, no `%AppData%` write, **no new

## Dev Notes

### Invariants this story must keep

- **I5 — a batch count mismatch is never padded.** For a 1:1 contract (DeepL, Azure) it is a `BadResponse`, full
  stop. This is the invariant with the most expensive history in the repo (`project-context.md`: *"padding once
  bypassed the fallback and poisoned the cache"*).
- **I7 — per-message source.** `detectedLanguage` is discarded.
- **I11 — keys never logged.** `Secret: key` in the options; nothing else. The error report
  (`MainWindow.xaml.cs:312-322`) is E6.S3's half of I11.
- **I1 — `ITranslator` is unchanged.** Two members. The priority is a **constructor** parameter, never a call
  parameter (`GoogleDictTranslator.cs:65-71` explains why, and E3.S7 depends on it).
- **I3 — the OCE trap.** You do not write a single OCE catch in this file: `HttpProviderCore` owns every one of
  them and every one is filtered (`README.md`, E1.S3 row: *"every OCE catch filtered — the August-accepted bug is
  gone"*). **Do not add one.** If you find yourself writing `catch (OperationCanceledException)` in
  `AzureTranslator.cs`, stop and read `HttpProviderCore.SendAsync`.
- **NFR6 / A5 — no SDK.** AC 4. `benchmark…` §7 is explicit that exe size alone is not a valid argument; the
  **dependency surface** is: the SDK brings its own timeouts and retries, and they would fight the core.

### Rulings that apply

- **E2-g** — 401 is guarded on `keyWasSent` exactly like 403. Landed in E2.S2; you consume it by setting
  `KeyWasSent: true`.
- **E2-a** — `AuthFailed` is **never persisted** in A.1 (in-memory only; restart resets it), and *"E6 adds 'key
  saved → that provider's gate resets'"*. That reset is **E6.S3**'s `ClearAuthBlock("azure")`, not this story's.
- **E2-f** — `Retry-After` is a floor, never a shortcut. Azure sends one on 429; the core already honours it.
  Nothing to do here, listed so you do not add a second handling.
- **E2-i** — a new key clears only `AuthFailed`/`QuotaExhausted` (account-scoped), never `RateLimited`/`Blocked`.
  E6.S3's concern; it constrains the sentence E6.S5 may write.

### Repo traps

- **`ProviderIds.Azure` already exists** (`ProviderGates.cs:21`) and is already in `All` (`:31`). Do not add a
  second constant, and do not add a literal `"azure"` anywhere — `ProviderGatesTests` pins the set.
- **`ProviderErrorMapper` needs no change.** Row 6's quota-envelope test (`:37-44`, `NamesAQuota`) was written
  **for Azure's shape**: `{"error":{"code":403,…,"message":"… quota …"}}`, `QuotaMarkers = { "quota", "out of
  credit", "limit exceeded" }`, matched over a **bounded body head** (`:175-183` explains why unbounded would
  turn any long vendor error page into a 60-minute `QuotaExhausted`). Verify with a fixture; do not re-implement.
- **`HttpProviderCore.CreateClient(handler, userAgent)`** is the one factory (`:77`). A test client must differ
  from the production one **by its handler and nothing else** (`DeepLTranslator.cs:82-84`).
- **`ConfigureAwait(false)`** on every await in `Services/` — E2.S5 added a source scan for it.
- **No `.sln`**; `InternalsVisibleTo` (`PWRUHelper.csproj:28`) and `DefaultItemExcludes` (`:18`) intact.
- **`ProviderStateStoreTests.No_startup_path_mentions_ProviderGates`** (TP-START-02, `:837-866`) — this story adds
  no reference outside `Services/`, so the assert at `:865` is untouched. **E6.S3 is the story that changes it**,
  deliberately.
