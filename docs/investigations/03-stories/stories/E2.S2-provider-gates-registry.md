# Story E2.S2: `ProviderGates` registry, process-global and reset-able

Status: **ready-for-dev (Phase 4 — owner's go required)**

_Epic E2 (B) — Provider gate · increment 1 · **Release A.1: E2 and E3 are separate PRs but ONE release** · ⛔ no
production code until the owner's explicit go._

## Story

As the maintainer,
I want one gate per provider id shared by both chains,
So that the Translator tab cannot keep hammering a provider that LIVE has already been told to leave alone.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E2.S2. Do not weaken._

1. **Given** the read chain is a field initializer (`MainWindow.xaml.cs:43`) and the write chain is rebuilt on every
   key save (`MainWindow.Translate.cs:239`) — two independent instances today
   **When** `ProviderGates.For(id)` is introduced
   **Then** both chains obtain the **same** `ProviderGate` instance for the same id, and `ProviderIds` declares
   `google-dict`, `edge`, `google-gtx`, `deepl`, `azure`, `bergamot`.
2. **Given** the discipline already used twice in this repo (`SettingsService.cs:95`, `Logging.cs:31-39`)
   **When** the registry lands
   **Then** it exposes `internal static string? PathOverride`, `internal static Func<DateTimeOffset> Clock`,
   `internal static void ResetForTests()` and `internal static void ClearAuthBlock(string id)`.
3. **Given** R4 (static state leaks between parallel xUnit collections)
   **When** the gate tests are written
   **Then** they live in **one non-parallel xUnit collection** whose fixture calls `ResetForTests()`, and no gate
   test touches the real `%AppData%`.

## Tasks / Subtasks

- [ ] **T1 — Create `Services/ProviderGates.cs`** (AC: 1) — the glossary §16 target file
  - [ ] `internal static class ProviderGates` with `ProviderGate For(string providerId)` — a lazily-initialised
        map `id → ProviderGate`, returning the **same instance** for the same id for the life of the process.
  - [ ] Thread-safe: both chains, the LIVE loop and the Translator tab call `For` concurrently. A
        `ConcurrentDictionary` with `GetOrAdd`, or a `lock`ed dictionary — house style, no cleverness.
  - [ ] `internal static class ProviderIds` **in the same file** (glossary §16) declaring the six ids as `const`
        strings: `google-dict`, `edge`, `google-gtx`, `deepl`, `azure`, `bergamot`. Nothing else may spell an id as
        a literal — that is how a typo becomes two gates.
  - [ ] **Why static, restated so no story re-opens it** (§5.1): the state mirrors an *external,
        process-independent* condition (an IP-scoped counter on Google's side); the alternative would have to be
        threaded through a field initializer that runs **before** `_settings` is even loaded
        (`MainWindow.xaml.cs:43` vs `:50`) and through `BuildTranslator()`, which runs again on every key save.
- [ ] **T2 — The three test seams and the auth clear** (AC: 2) — the discipline this repo already uses twice
  - [ ] `internal static string? PathOverride` — mirrors `SettingsService.cs:95` and `Logging.cs:31-39`. The
        registry owns load/save of `provider-state.json`; the actual store is **E2.S4**. In this story the property
        exists and is honoured by whatever load/save stub lands, so no test can be written that touches the real
        `%AppData%` later.
  - [ ] `internal static Func<DateTimeOffset> Clock` — **IS-6: the registry and every gate it hands out must share
        one clock**, or a persisted `blockedUntil` is compared against a different "now". `For` injects this clock
        into each `ProviderGate` it creates; changing `Clock` after gates exist must be honoured (hold the
        `Func<>` by reference, do not copy the value at construction).
  - [ ] `internal static void ResetForTests()` — **IS-4: clears the registry AND any pending debounced save.** The
        second half matters even though the save lands in E2.S4: without it a queued write from one test lands
        during the next. Land the hook now so E2.S4 only fills it in.
  - [ ] `internal static void ClearAuthBlock(string id)` — closes an `AuthFailed` gate
        (`blockedUntil = DateTimeOffset.MaxValue`). Called from the key-save handlers (DeepL today,
        `MainWindow.Translate.cs:235-244`; Azure in **E6.S3**, §12). Wiring the call sites is **not** this story —
        the entry point is.
- [ ] **T3 — The non-parallel `Gates` collection** (AC: 3) — **IS-5**
  - [ ] `[CollectionDefinition("Gates")]` in the test project, mirroring `WpfCollection`
        (`tests/PWRUHelper.Tests/StaTestHost.cs:73-74`), with a fixture that calls `ResetForTests()` **before and
        after every case**. Anything touching `ProviderGates` joins it.
  - [ ] Move E2.S1's `ProviderGateTests` into it if they now go through the registry; pure-`ProviderGate` cases may
        stay outside (they hold no static state).
  - [ ] xUnit parallelises **collections** by default and static state does not tolerate it — this is risk R-08 /
        `architecture-cible.md` R4, and two non-parallel collections (`WPF`, `Gates`) is the accepted, bounded cost
        of two static facades (CI-5). **Do not change the runner's default parallelism to work around it.**
- [ ] **T4 — `TempGateState`, the test disposable** (AC: 3) — **IS-3**
  - [ ] Mirror `TempSettings` (`tests/PWRUHelper.Tests/StaTestHost.cs:82-101`) exactly: create a temp
        subdirectory in the ctor, set `ProviderGates.PathOverride`, null it and delete the directory in `Dispose`.
        One place that can never be forgotten.
  - [ ] Add the real-`%AppData%` guard in the same shape as `LoggingTests.cs:89`
        (`The_test_run_never_writes_to_the_real_AppData_log`): a case asserting the gate path in use is **not** the
        real `%AppData%\PWRUHelper` path. That test is what stops the suite from rewriting a developer's own state
        — the trap this repo has already been bitten by twice.
- [ ] **T5 — Keep it off the startup path** (I10)
  - [ ] `ProviderGates` must not be referenced from the `MainWindow` constructor, `ApplySettings`
        (`MainWindow.xaml.cs:151-201`) or `OnWindowLoaded`. Its static initialiser must do **no I/O** — the file
        loads lazily on the first `TryEnter` of the process, off the UI thread (**E2.S4**).
  - [ ] **TP-START-02**'s source scan (no `ProviderGates` reference in the ctor / `ApplySettings` / `OnWindowLoaded`
        chain) is E2.S4's DoD, but this story must not be what breaks it. Do not add a warm-up call "to avoid a
        first-use hitch".
- [ ] **T6 — Tests** (AC: 1, 2, 3)
  - [ ] Two `For(id)` calls return the **same** instance; two different ids return different instances.
  - [ ] `ResetForTests()` clears the registry (a `For` after it returns a fresh, closed gate).
  - [ ] `ClearAuthBlock(id)` closes a gate opened with `AuthFailed`, and does nothing to a gate opened with
        `RateLimited` (TP-GATE-09's second half).
  - [ ] The collection is declared non-parallel and the suite is green **with the test runner's default
        parallelism unchanged** — that is the DoD.
  - [ ] The `%AppData%` guard from T4.

## Dev Notes

### Invariants this story must keep

- **I9 — gate state is process-global and persisted.** This story is the "process-global" half; **E2.S4** is the
  "persisted" half. Today the two chains are separate instances (`MainWindow.xaml.cs:43` vs
  `MainWindow.Translate.cs:229-232`, rebuilt at `:239`), which is exactly why the Translator tab can keep hammering
  a provider LIVE has been told to leave alone.
- **I10 — nothing new before the window is visible.** No I/O in the static initialiser, no reference from any
  startup path.
- **I2** — UI-free, headless-testable. **I3** — nothing here catches an OCE. **I11** — the registry logs nothing in
  this story (transition logging is **E2.S6**).
- **I16** — the LIVE loop is untouched.

### Rulings and decisions that apply

- **R-2 / OQ-c (binding): no event on the registry either.** `readiness-report.md` R-2 proposes
  `ProviderGates.StateChanged` and says to add it to E2.S1/E2.S2's scope. The architect's ruling overrides it:
  **poll `ProviderGate.Snapshot()` at 1 Hz from the countdown timer; no events out of `Services/`.** Do not add
  `StateChanged`, `INotifyPropertyChanged`, or a callback list. (Sprint-plan note 1.)
- **`ProviderIds` is the vocabulary of the whole rebuild.** `google-gtx` is the id for today's endpoint **before**
  the rename in E3.S6 — E1.S5's log line already uses it, so the field stays stable across the rename.
- `bergamot` is declared here even though **E8** may never merge. An id costs nothing; a second spelling of it
  would cost a silently duplicated gate.

### Repo traps

- **The static-facade pattern exists twice in this repo and both times for the same reason**:
  `SettingsService.PathOverride` (`SettingsService.cs:95`) after the suite rewrote a developer's own
  `settings.json`, and `Logging.DirectoryOverride` (`Logging.cs:31-39`) after the suite seeded a real error report
  with fixture failures ("deepl down"). Copy the shape, including the guard test.
- `tests/PWRUHelper.Tests/TestLogRedirect.cs:24-26` shows the other half of that lesson: a `[ModuleInitializer]`
  that catches everything, including the tests that never mention the facade. If a gate equivalent is ever needed,
  that is the pattern — but prefer the explicit `TempGateState` disposable, which is what IS-3 asks for.
- `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) and the `tests\**` `DefaultItemExcludes` (`:18`)
  intact. **No `.sln`.** `dotnet test tests/PWRUHelper.Tests` green, headless, default parallelism unchanged.
- No settings control is touched in this story, so `_restoringSettings` (`MainWindow.xaml.cs:35`, cleared at
  `:201`) is not engaged. The first story of this rebuild that adds a persisted control is **E6.S3**, and it must
  follow that pattern with one clobber test **per control**.

## Testing

- **TP-IDs landed:** the registry-identity and `ResetForTests` cases (no numbered id of their own — they are the
  enabler for the whole `TP-GATE-*` family), plus the second half of **TP-GATE-09** (`ClearAuthBlock`).
  **TP-GATE-19…23** (persistence round-trip, corrupt/missing/future-version file, clock-skew clamp, unknown ids
  preserved, transition-only coalesced saves) ⇒ **E2.S4**. **TP-START-02** ⇒ **E2.S4**.
- **Fixtures:** none.
- **Isolation items landed:** **IS-1** (`PathOverride` declared), **IS-3** (`TempGateState`), **IS-4**
  (`ResetForTests`, registry half — the pending-save half completes in E2.S4), **IS-5** (the non-parallel `Gates`
  collection), **IS-6** (one shared `Clock`, with E2.S1).
- **Must keep passing unchanged:** the whole existing suite, with the runner's default parallelism unchanged.
  `StartupSettingsTests` in particular — it is the neighbour that already needs this discipline.

## How to verify manually

Nothing user-visible changes: no provider consults a gate until **E2.S5**. Verify by running
`dotnet test tests/PWRUHelper.Tests` several times in a row — the gate cases must pass every time and in any order,
and no `provider-state.json` may appear under your real `%AppData%\PWRUHelper\`. Check that folder by hand after
the run; it is the failure mode this story exists to prevent.
