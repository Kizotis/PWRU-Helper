# Story E8.S3: The model store, and one-click Download / Remove from the About tab ⛔ Phase 4 (prototype branch)

Status: **blocked-dep · ⛔ Phase 4 · prototype branch only — needs E8.S2's provider and E8.S1's go**

_Epic E8 (H) — Offline fallback prototype · increment 7 · **Release C** · prototype branch, merges only on a go._

> **A 50 MB download is a decision the user makes, not something an error message does to them.** That sentence
> is the whole story, and it has a specific enemy: `ux-mode-degrade.md` §3.6 is a *deliberate divergence from the
> brief's own flow* — the consent dialog is **never** raised by a background failure, because a `MessageBox` over
> a fullscreen game, opened by a LIVE loop the player forgot was running, is the single worst thing this app
> could do (principle 3, NFR12).
>
> **Two things this story owns that `epics.md` § E8.S3 assumed rather than specified**: the **model store**
> itself — where files live, how they are verified, what `Remove` deletes — and the fact that nothing about it
> may touch disk before the window is visible (I10).

## Story

As a player,
I want to add the offline engine with one click and remove it with another,
So that a 50 MB download is a decision I make, not something an error message does to me.

## Acceptance Criteria

_AC 1–5 are copied **verbatim** from `epics.md` § Story E8.S3. AC 6 is copied **verbatim** from `epics.md`
§ Story E8.S2's fifth Given (the model-mirror AC, which belongs to the download and not to the provider).
AC 7–9 are `[DERIVED]` and cover the store `epics.md` left implicit. Do not weaken._

1. **Given** amendment A-1(a) and UX-DR12 / §3.6
   **When** the user clicks **Download the offline engine** in About
   **Then** and **only then** a consent dialog appears — `MessageBox.Show(this, …)` with an owner, title
   `Add the offline engine?` — stating the download size (~22 MB engine + ~30 MB per language pair), the memory
   cost (130–310 MB while translating, freed when idle), the storage location (`%AppData%\PWRUHelper\models`)
   and how to remove it. `Not now` is the safe default and closes with no trace.
   _`[FLAG E8-b — the storage location is contradicted by Winston's Release-C direction and must be settled
   before the copy ships.]` See "The store, and where it lives" below. If the ruling lands on `%LocalAppData%`,
   this AC's parenthetical and `ux-mode-degrade.md` §3.6 / §4.2 change **in the same commit**, with Sally's
   sign-off — the copy and the code may never disagree about where a user's 50 MB went._

2. **Given** principle 3 and NFR12
   **When** any background failure occurs
   **Then** **no dialog is ever raised** — a `MessageBox` over a fullscreen game opened by a LIVE loop is the
   single worst thing this app could do. The failure path may only **nudge**, in the status line:
   `All engines are paused — you can add an offline engine in About.`

3. **Given** the download
   **When** it runs
   **Then** the About row shows `Downloading the offline engine… {p}%` with a `Cancel` button and the app stays
   fully usable; on completion it shows
   `● Offline engine ready — used only when everything else is unavailable.`; on failure,
   `Download failed — {reason}. Nothing was installed.`

4. **Given** OQ-9 (is the download progress observable?) is unanswered
   **When** the mirror does not report a total size
   **Then** the copy degrades to `Downloading…` without a percentage rather than inventing one.

5. **Given** OQ-11, resolved here: **downloaded ⇒ enabled**
   **When** the install completes
   **Then** `OfflineFallbackEnabled` becomes true and **Remove** is the only off switch — there is no second
   checkbox. `Remove` asks for confirmation with `MessageBox.Show(this, …)` and states that it deletes the files.

6. **Given** §5 of the model download
   **Then** models are fetched from a **`github.com` mirror**; the `UpdateService` allowlist
   (`github.com` / `githubusercontent.com`) is **not widened**.

7. `[DERIVED — I10, G6]` **Given** I10
   **When** the app starts
   **Then** **nothing about the model store touches the disk before the window is visible** — not a
   `Directory.Exists`, not a file enumeration, not a size sum. The About tab's state is computed on first paint
   of that tab or later, off the UI thread, in the shape ruling **E6-a** already established for the gate state
   (`TranslationChains.EnsureGateStateLoaded` from `OnWindowLoaded`, on a pool thread).

8. `[DERIVED — §7.6 constraint 6, UpdateService's existing discipline]` **Given** a completed download
   **When** the files are installed
   **Then** each one's **size** is checked against the manifest and its **SHA-256** against a published digest
   before it is moved into place; a mismatch deletes the partial download and reports
   `Download failed — {reason}. Nothing was installed.` A half-written 22 MB DLL that the app then P/Invokes is
   the one failure mode here that is worse than no feature at all.

9. `[DERIVED — I12, ux §4.3's `_restoringSettings` contract]` **Given** I12
   **When** the About controls are added
   **Then** every one of them obeys `_restoringSettings` and `ApplySettings` applies their side effects
   explicitly.
   _(This is `epics.md` § E8.S3's own sixth Given, restated as its own AC because it is the invariant that has
   already cost this project two migration steps and two releases.)_

## Dev Notes

### The store, and where it lives — flag **E8-b**, unresolved, and it changes shipping copy

| Source | Says |
|---|---|
| `ux-mode-degrade.md` §3.6 (consent dialog) and §4.2 (mockup) | `%AppData%\PWRUHelper\models` |
| `epics.md` § E8.S3 AC 1 (verbatim above) | `%AppData%\PWRUHelper\models` |
| `architecture-cible.md` §7.6 amendment A-1(a) | *"per `ux-mode-degrade.md` §4"* — inherits the above |
| **Winston, Release-C direction (2026-09-07)** | **`%LocalAppData%\PWRUHelper\models\` — not Roaming** |

**Recommendation: `%LocalAppData%`, and the reasoning is the app's own investigation.** Roaming profiles copy
their contents at logon; `%AppData%` is where `settings.json`, `provider-state.json`, `translation-cache.json`
and the log live, and all four are kilobytes. This directory is **22 MB of native DLL plus 22–37 MB per model**,
and on a roaming or OneDrive-synced profile that is a logon cost — the exact class of machine-dependent startup
cause P1 spent a whole phase hunting. It is also the Windows convention: machine-local, re-downloadable binary
data belongs in Local.

**But it is a copy change**, in a consent dialog whose whole job is to tell the user where their 50 MB went.
So: **Winston or the owner rules; then the code, `ux-mode-degrade.md` §3.6, §4.2 and this AC change together, in
one commit, with Sally's sign-off.** Do not ship code and copy that disagree, and do not silently "fix" the
copy — a divergence between the dialog and the directory is a support ticket that reads *"where did my 50 MB
go?"*.

### Why `Download` is a button and not a checkbox — OQ-11, resolved here

§4.3's table gives the one-line reason: *"the two actions have very different weight"*. A checkbox implies a
free, reversible toggle; one of these two actions costs 50 MB of somebody's connection and the other deletes it
from their disk. And a second control would mean two ways to express one decision — **ruling R-4** settles it:
the setting exists, the buttons are its only writers, there is no separate toggle.

### Invariants this story must keep

- **I2** — `OfflineModelStore` is headless and unit-testable. The dialog is the code-behind's.
- **I3** — every catch on the download path filters `when (ct.IsCancellationRequested)`.
- **I10** — AC 7. Nothing about this store is asked before first paint, and the answer arrives on a pool thread
  the way ruling **E6-a** arranged for the gate state.
- **I11** — no URL, no path, no user text in the log. The download's failures log a **kind**, not a URL.
- **I12** — AC 9. `_restoringSettings` is not borrowed; `UpdateOfflineEngineUi()` is called explicitly from
  `ApplySettings`.
- **I13** — no default changes, so no version bump. Stated so nobody adds one "to be safe".
- **NFR12 / principle 3** — no dialog from a background path, ever. AC 2 is the whole story's reason to exist.

### Repo traps

- **The WPF `Clipboard` class is banned** (`project-context.md`, I14). Nothing here needs it; stated because a
  "copy the model path" convenience is exactly the shape that would sneak one in. `Services/ClipboardService` is
  the only route.
- **`MessageBox.Show(this, …)`** — with an owner. A parentless dialog behind a fullscreen game is unfindable.
- **`MainTabs_SelectionChanged` must filter `e.Source is TabControl`** (`project-context.md`) — if this story
  computes the About tab's state on tab selection, that filter is why the handler does not fire for every inner
  selector.
- **Tag-driven combos use `SelectTag`/`SelectedTag`** (`MainWindow.xaml.cs:359-370`) — irrelevant unless a
  language-pair picker appears; §4.2's `[ Add a language pair ]` is **out of scope** for the prototype
  (RU→EN only), and adding one would double the RAM (flag E8-a's 310 MiB ceiling).
- **IS-2/IS-3** — a test that writes to the developer's real `%AppData%` is the failure this suite has explicit
  machinery to prevent (`TempCache`, `PathOverride`). This class writes **50 MB**; give it its override on day
  one and assert the real directory is untouched, as `CacheLoadSpike` does.
- **E7.S7 owns the About restructure and is `ready-for-dev`.** Coordinate; do not decorate a region that is
  about to be rewritten (`MainWindow.xaml:670-673` says so in the file).

## Size, dependencies, risk

**Size:** **M** · **Depends on:** **E8.S2** (there is nothing to enable without a provider) and **E8.S1**'s go;
the owner for the mirror release (T2, T8) · **Blocks:** E8.S5 (the chain reads "is the model present?") ·
**Risk:** **medium — a modal on the wrong thread is the failure this story exists to prevent.** Second risk: a
partial or corrupt 22 MB DLL that the app then P/Invokes, which AC 8 is the whole answer to ·
**DoD:** no background path can open a dialog, and a verified install/remove round-trips with the network
disabled afterwards.

## How to verify manually

1. Open About with nothing installed: `○ Not installed — about 50 MB to download, works with no internet at all.`
2. Click **Download the offline engine**: the consent dialog appears, owned by the main window, with the four
   labelled lines of §3.6. Press `Not now`: **nothing** changed, nothing was written, no trace.
3. Click again, accept: the row shows a percentage, `Cancel` is present, and the app stays fully usable —
   switch tabs, translate something, drag the window.
4. Cancel: the row returns to `○ Not installed` and the directory is as it was.
5. Download to completion: the row reads `● Offline engine ready — …`, `settings.json` shows
   `OfflineFallbackEnabled: true`, and the model directory holds exactly what the manifest listed.
6. **Force the failure path**: unplug the network mid-download ⇒ `Download failed — …. Nothing was installed.`,
   **not** a cancel message (this is the I3 check, and it is the one to do by hand).
7. Start LIVE, let every engine pause: the status line nudges **once**; **no dialog appears**. This is AC 2 and
   it is the one that would be caught by a player mid-raid rather than by a test.
8. `Remove`: a confirmation dialog that says it deletes the files; accept; the directory is gone and
   `OfflineFallbackEnabled` is false.
9. Restart with the engine installed: the window paints with **no** read under the models directory before it
   is visible (Process Monitor) — AC 7.
