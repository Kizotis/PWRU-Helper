# Story E2.S6: Log gate transitions

Status: **ready-for-dev (Phase 4 — owner's go given)**

_Epic E2 (B) — Provider gate · increment 1 · **Release A.1: E2 and E3 are separate PRs but ONE release** · the
owner's Phase-4 go was given 2026-09-06 (`README.md` § Phase 4)._

> **Release rule, non-negotiable.** This epic must not reach users without Epic 3 (`architecture-cible.md` R7,
> owner's decision 2). This story is also the epic's evidence: without it, "the gate opens and never clears" is a
> feeling; with it, it is a timeline in a paste.

## Story

As the owner reading a pasted error report,
I want the open/half-open/closed history with its strike escalation,
So that "it never clears" becomes a timeline instead of a feeling.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E2.S6. Do not weaken._

1. **Given** §10.2
   **When** a gate changes state
   **Then** exactly one line is logged per **transition** — never per skipped request, or a 30-minute open window
   would fill the log — in the shape
   `gate google-dict OPEN kind=RateLimited strikes=1 for=60s until=13:30:02`, then `HALF-OPEN probe`, then
   `CLOSED after probe ok, strikes reset`.
2. **Given** I11
   **When** the lines are written
   **Then** they contain a provider id and timings only: no user text, no URL, no key.
3. **Given** "Copy error report" (`MainWindow.xaml.cs:312-322`)
   **When** it is copied after an incident
   **Then** it contains the full gate history alongside the per-request lines (§10.3).

## Tasks / Subtasks

- [ ] **T1 — One pure line builder** (AC: 1, 2) — `Services/ProviderGate.cs`
  - [ ] `internal static string TransitionLine(...)` — pure, no clock, no I/O, everything it renders decided by
        its caller. Same discipline as `RequestLog.Line` (`Services/RequestLog.cs:201-203`), and for the same
        reason: a builder that is a function is testable without a file and movable without a rewrite.
  - [ ] The three §10.2 shapes, verbatim:
        ```
        gate google-dict OPEN kind=RateLimited strikes=1 for=60s until=13:30:02
        gate google-dict HALF-OPEN probe
        gate google-dict CLOSED after probe ok, strikes reset
        ```
        `Logging` already prefixes the timestamp and the level (`Services/Logging.cs:88`, with milliseconds since
        E1.S5), so the builder emits from `gate ` onwards and nothing more.
  - [ ] **Levels:** `OPEN` ⇒ `Logging.Warn` (`Logging.cs:44`); `HALF-OPEN` and `CLOSED` ⇒ `Logging.Info`
        (`:43`). That is exactly what §10.2's example shows.
  - [ ] **`until=` is local `HH:mm:ss`** in §10.2's example, beside a local timestamp from `LogWriter`
        (`Logging.cs:88` uses `DateTime.Now`). Render it the same way so the two are comparable by eye — a UTC
        `until=` next to a local timestamp is a report that reads as a bug.
  - [ ] **Edge case the AC does not cover: `AuthFailed` opens with `blockedUntil = DateTimeOffset.MaxValue`**
        (§5.3). `for=` would render an eight-digit number of seconds and `until=` a year nobody will see. Render
        `for=until-key-change until=-` (or an equivalent both a human and a `grep` can read) and give it a case.
        Pick one spelling and keep it — E2.S7 and the owner will grep for it.
  - [ ] Everything a value could carry must be bounded and single-line. The only inputs are a provider id from
        `ProviderIds`, a `TranslationErrorKind` name, an int and two instants — none of them server-controlled —
        so a full `RequestLog.Ascii`-style sanitiser is over-engineering. Say so in a comment rather than leaving
        the reader to wonder, and keep the id rendering to `ProviderIds`' constants.
- [ ] **T2 — Emit on transitions, and only on transitions** (AC: 1)
  - [ ] The **exactly four** §5.2 state-machine edges get a line:
        `Closed → Open` (OPEN, with `kind`, `strikes`, `for`, `until`), `Open → HalfOpen` (HALF-OPEN probe),
        `HalfOpen → Closed` (CLOSED after probe ok, strikes reset), `HalfOpen → Open` (OPEN again, escalated).
  - [ ] **What deliberately gets no line, and why — decide it here so E2.S4's save rule and this agree:**
        - a `TryEnter` **refused** while open — that is the whole point of AC 1, and TP-LOG-07 asserts it;
        - a **soft cooldown** (`Unavailable`/`Timeout`/`Network`/`Unknown`, §5.3) — the breaker stays `Closed`,
          it is not a state-machine edge, and a DNS blip on every LIVE tick would write a line every 700 ms.
          The per-request line (E1.S5) already records the failure that caused it;
        - a **`BadResponse` soft strike** that does not reach 3 — same reason; the third one opens the gate and
          gets the OPEN line;
        - a **`CleanResetMinutes` strike reset** — §5.7 makes it a *save* trigger but it is not a state edge and
          it happens silently while nothing is wrong. **If Winston wants it, it is one `Info` line and one case;
          record the choice either way rather than leaving it undecided.**
        - a `Wait` from the rate ceiling (E2.S3) — sub-second, invisible, and there is one per request.
  - [ ] **A `Cancelled` report touches nothing and therefore logs nothing** (§5.3, TP-GATE-12). Assert it on the
        line count, not only on the state.
  - [ ] Emission happens **inside** the transition, under the gate's existing single `lock`, so two threads
        cannot interleave a transition and its line. `Logging`'s writer is itself thread-safe and never throws
        (`Logging.cs:77-92`), so this is cheap — but keep the *build* outside anything expensive: transitions are
        rare by construction (a handful per session), so simplicity wins over cleverness here.
- [ ] **T3 — The HALF-OPEN line comes from `TryEnter`, and that is not a contradiction** (AC: 1)
  - [ ] E2.S1's repo-trap note says *"no logging from `TryEnter`"*. That ban is on logging **per call**. The
        `Open → HalfOpen` edge happens **inside** `TryEnter` — it is the only place it can happen — and it is a
        transition, so it gets exactly one line per probe grant. Write the guard so the line is emitted on the
        same code path that takes the probe latch: one latch, one line, by construction.
  - [ ] A `Background` caller **deferred** by `ProbeDeferMs` (E2.S3) has **not** transitioned — no line. A probe
        that could not afford a token (E2.S3's T4 edge) has **not** transitioned — no line. Both are cases.
- [ ] **T4 — "Copy error report" carries the history** (AC: 3)
  - [ ] Nothing to build: `CopyErrorReport_Click` (`MainWindow.xaml.cs:312-322`) copies
        `Logging.ReadRecent()` (`Logging.cs:50`, default 30 000 chars), so gate lines are in the report the
        moment they are in the log. **Verify it rather than assume it** — the assertion is what makes §10.3's
        claim true, and V1.2 of the validation plan is "evidenceable from one paste".
  - [ ] The 30 000-char window and the 1 MB / one-rollover cap (`Logging.cs:69`, `:98-107`) are what a long incident
        competes with. Transition lines are ~70 characters and there are a handful per session; per-request lines
        are ~300 and are already valved by `RequestLog.Suppression` (`RequestLog.cs:339`). **Gate lines need no
        suppressor** — that is what "one per transition" buys — and adding one would hide the very escalation
        E2.S7 needs. Say so in a comment.
- [ ] **T5 — Tests** (AC: 1, 2, 3) — through `Logging.DirectoryOverride`
  - [ ] **TP-LOG-07** (the AC-1 pin): one open + **200 skipped calls** + one close ⇒ exactly **3** gate lines
        (OPEN, HALF-OPEN, CLOSED), not 202. Drive the whole thing on E2.S1's injected clock.
  - [ ] Escalation reads correctly: three successive opening failures produce three OPEN lines with
        `strikes=1/2/3` and `for=60s/120s/240s`. Assert the **relationship** (`strikes` increments, `for`
        doubles), not the literals — U9 means E2.S7 may tune them (E2.S1's rule).
  - [ ] The §5.3 rows that must produce **no** line: the four soft-cooldown kinds, a `BadResponse` below 3, a
        `Cancelled`, a deferred `Background` probe.
  - [ ] The `AuthFailed` / `MaxValue` rendering of T1.
  - [ ] **AC 2 / I11, as negative assertions:** translate a distinctive sentinel string that fails, set a DeepL
        key, and assert the sentinel, the key, `q=`, `http://` and `https://` appear in **no gate line**. Cheap,
        and it is the load-bearing test of AC 2.
  - [ ] **AC 3:** after a scripted open/probe/close, `Logging.ReadRecent()` contains all three lines. That plus
        E1.S5's per-request lines is **TP-LOG-09** (the report evidences a whole 429 episode, §10.3, V1.6),
        which E1.S5 deferred here — **complete it**.
  - [ ] **The `TestLogRedirect` caveat (sprint-plan note 10):** `Logging.DirectoryOverride` is already set
        process-wide by a `[ModuleInitializer]` (`tests/PWRUHelper.Tests/TestLogRedirect.cs:24-26`) and
        `LoggingTests.cs:92-102` asserts it. A test that counts lines must set **its own** override and restore
        the previous value in a `finally`, exactly like `LoggingTests.cs:105-110` — never assume a clean file.
  - [ ] **No `Task.Delay`** (CI-3). Every window, escalation and probe assertion drives the injected clock.
  - [ ] Cases join the non-parallel **`Gates`** collection (IS-5) — they touch `ProviderGates` **and** a
        process-wide logging facade, which is two reasons.

## Dev Notes

### What this story changes in files that already exist

`Services/ProviderGate.cs` (E2.S1 + E2.S3 + E2.S4) and possibly `Services/ProviderGates.cs`. Read both before
touching them and record in the PR:

- **Current state** — the breaker and its four state edges, the token bucket, the injected clock, the
  transition notification E2.S4 added for its debounced save.
- **What this story changes** — those same four edges gain one `Logging` call each. Nothing else.
- **What must be preserved** — `TryEnter`'s hot path (no allocation, no logging, no I/O on a refusal),
  `Snapshot()`'s side-effect freedom, TP-GATE-12's whole-state equality for `Cancelled`, and E2.S4's
  transition-only save rule, which this story's emit points should sit **beside** rather than duplicate.
- **The obvious refactor, and whether to take it:** E2.S4 already needs "tell me when a transition happened" for
  its save. If one internal `OnTransition(from, to, kind, strikes, blockedUntil)` serves both the save and the
  line, take it — one definition of "a transition" is the whole point of T2. **It is still not an event on
  `ProviderGate`'s surface** (R-2/OQ-c): a private method or a constructor-injected `Action`, never a public
  `event`, never `INotifyPropertyChanged`.

### Invariants this story must keep

- **I11 is the point of AC 2.** The log is pasted to Discord **by design** (`MainWindow.xaml.cs:312-322`). Gate
  lines carry a provider id, a `Kind` name, an int and two instants — nothing else may enter, ever. The negative
  assertions in T5 are the load-bearing tests of this story; if they are weak, the story is worse than not
  doing it.
- **I2** — `ProviderGate` stays UI-free. `Logging` is itself UI-free (`Services/Logging.cs`), so calling it
  keeps the class headless-testable; it does mean gate tests now depend on `Logging.DirectoryOverride`, which is
  what T5's caveat is about.
- **I3** — nothing here catches an `OperationCanceledException`. `Cancelled` never touches the gate and
  therefore never logs.
- **I9 / I10** — no new state, no new file, no startup path. Logging is best-effort and already bounded.
- **I16** — the LIVE loop is untouched.

### Rulings and decisions that apply — the rulings win over the older documents

- **R-2 / OQ-c (binding): no event out of `Services/`.** A transition line is a *write to a log*, not a
  notification. The UI learns about a gate by polling `ProviderGate.Snapshot()` at 1 Hz from the countdown timer
  (E7.S2/E7.S3). `readiness-report.md` R-2 proposes `ProviderGates.StateChanged`; the architect's ruling
  overrides it (sprint-plan note 1). Do not let "I need to know when it changes, for the log" become the
  back door that adds it.
- **U9 / E2.S7 depends on this story.** The spike's exit criterion is *"median open-window count per LIVE hour
  and the maximum strike level reached, over ≥ 3 reports covering ≥ 6 LIVE hours"* — those numbers are read out
  of **these lines**. `strikes=`, `for=` and `until=` must be greppable and consistently spelled, or the spike
  has no data. That is a design constraint, not a nicety.
- **§10.3** is what "Copy error report" then contains: both attempt lines with their jittered spacing, every
  status, `Retry-After` presence and value, the content-type, the de-tagged body head, `burst60`, `ipv`, **and
  the full open/half-open/closed history with the strike escalation** — *"from a single user paste, with no user
  text leaving the machine. This is what makes P2 provable instead of arguable."*

### Repo traps

- **`Logging` swallows its own errors by design** (`Logging.cs:92`, `:107`, `:129`) — logging must never be the
  thing that breaks a feature. A failure to build or write a gate line must not fail a transition, and must not
  fail the request that caused it.
- **The log is capped at 1 MB with one rollover** (`Logging.cs:69`, `:98-107`). One line per transition is what
  keeps the evidence in the file; per-skip logging would evict E1.S5's per-request lines, which are the other
  half of §10.3.
- **`Logging.DirectoryOverride` is set process-wide by `TestLogRedirect`'s `[ModuleInitializer]`**
  (`TestLogRedirect.cs:24-26`), after the suite once seeded a developer's real error report with fixture
  failures ("deepl down"). `LoggingTests.cs:92-102` guards it. Set your own, restore it in a `finally`.
- **R-08 / R4** — static state across xUnit's parallel collections: the `Gates` collection (IS-5), default
  runner parallelism unchanged (CI-5).
- No settings control is touched, so `_restoringSettings` (`MainWindow.xaml.cs:35`, cleared at `:201`) is not
  engaged. Epic 2's only code-behind change is E2.S4's `Flush()` in `OnClosing` (`:229-231`).
- `InternalsVisibleTo PWRUHelper.Tests` (`PWRUHelper.csproj:28`) and the `tests\**` `DefaultItemExcludes` (`:18`)
  intact. **No `.sln`.** `dotnet test tests/PWRUHelper.Tests` green and headless.

## How to verify manually

1. Run `dotnet test tests/PWRUHelper.Tests`; then delete your real `%AppData%\PWRUHelper\logs\log.txt`, run the
   app, and confirm the suite wrote nothing into it.
2. With the A.1 build (E2.S5 landed): force a provider open — a throttled connection, or a `Retry-After` from a
   test endpoint. In `%AppData%\PWRUHelper\logs\log.txt` you must see **one**
   `gate <id> OPEN kind=RateLimited strikes=1 for=60s until=…` line. Then try to translate **repeatedly** for
   the whole window: **no further gate line appears** (and, thanks to E2.S5, no `tr` line either). When the
   window passes, exactly one `gate <id> HALF-OPEN probe` appears, followed by either
   `gate <id> CLOSED after probe ok, strikes reset` or a second `OPEN` with `strikes=2 for=120s`.
3. Press **Copy error report** in the About tab and paste it somewhere: the whole timeline must be in it, and a
   search for the Russian sentence you translated, for your DeepL key, and for `q=` must find nothing.
