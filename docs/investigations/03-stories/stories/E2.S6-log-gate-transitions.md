# Story E2.S6: Log gate transitions

Status: **review**

_Epic E2 (B) — Provider gate · increment 1 · **Release A.1: E2 and E3 are separate PRs but ONE release** · the
owner's Phase-4 go was given 2026-09-06 (`README.md` § Phase 4)._

> **Release rule, non-negotiable.** This epic must not reach users without Epic 3 (`architecture-cible.md` R7,
> owner's decision 2). This story is also the epic's evidence: without it, "the gate opens and never clears" is a
> feeling; with it, it is a timeline in a paste.

## Story

As the owner reading a pasted error report,
I want the open/half-open/closed history with its strike escalation,
So that "it never clears" becomes a timeline instead of a feeling.

## Acceptance Criteria

_Copied verbatim from `epics.md` § Story E2.S6. Do not weaken._

1. **Given** §10.2
   **When** a gate changes state
   **Then** exactly one line is logged per **transition** — never per skipped request, or a 30-minute open window
   would fill the log — in the shape
   `gate google-dict OPEN kind=RateLimited strikes=1 for=60s until=13:30:02`, then `HALF-OPEN probe`, then
   `CLOSED after probe ok, strikes reset`.
2. **Given** I11
   **When** the lines are written
   **Then** they contain a provider id and timings only: no user text, no URL, no key.
3. **Given** "Copy error report" (`MainWindow.xaml.cs:312-322`)
   **When** it is copied after an incident
   **Then** it contains the full gate history alongside the per-request lines (§10.3).

- [x] **T1 — One pure line builder** (AC: 1, 2) — `Services/ProviderGate.cs`
  - [x] `internal static string TransitionLine(...)` — pure, no clock, no I/O, everything it renders decided by
        its caller. Same discipline as `RequestLog.Line` (`Services/RequestLog.cs:201-203`), and for the same
        reason: a builder that is a function is testable without a file and movable without a rewrite.
  - [x] The three §10.2 shapes, verbatim:
        ```
        gate google-dict OPEN kind=RateLimited strikes=1 for=60s until=13:30:02
        gate google-dict HALF-OPEN probe
        gate google-dict CLOSED after probe ok, strikes reset
        ```
        `Logging` already prefixes the timestamp and the level (`Services/Logging.cs:88`, with milliseconds since
        E1.S5), so the builder emits from `gate ` onwards and nothing more.
  - [x] **Levels:** `OPEN` ⇒ `Logging.Warn` (`Logging.cs:44`); `HALF-OPEN` and `CLOSED` ⇒ `Logging.Info`
        (`:43`). That is exactly what §10.2's example shows.
  - [x] **`until=` is local `HH:mm:ss`** in §10.2's example, beside a local timestamp from `LogWriter`
        (`Logging.cs:88` uses `DateTime.Now`). Render it the same way so the two are comparable by eye — a UTC
        `until=` next to a local timestamp is a report that reads as a bug.
  - [x] **Edge case the AC does not cover: `AuthFailed` opens with `blockedUntil = DateTimeOffset.MaxValue`**
        (§5.3). `for=` would render an eight-digit number of seconds and `until=` a year nobody will see. Render
        `for=until-key-change until=-` (or an equivalent both a human and a `grep` can read) and give it a case.
        Pick one spelling and keep it — E2.S7 and the owner will grep for it.
  - [x] Everything a value could carry must be bounded and single-line. The only inputs are a provider id from
        `ProviderIds`, a `TranslationErrorKind` name, an int and two instants — none of them server-controlled —
        so a full `RequestLog.Ascii`-style sanitiser is over-engineering. Say so in a comment rather than leaving
        the reader to wonder, and keep the id rendering to `ProviderIds`' constants.
- [x] **T2 — Emit on transitions, and only on transitions** (AC: 1)
  - [x] The **exactly four** §5.2 state-machine edges get a line:
        `Closed → Open` (OPEN, with `kind`, `strikes`, `for`, `until`), `Open → HalfOpen` (HALF-OPEN probe),
        `HalfOpen → Closed` (CLOSED after probe ok, strikes reset), `HalfOpen → Open` (OPEN again, escalated).
  - [x] **What deliberately gets no line, and why — decide it here so E2.S4's save rule and this agree:**
        - a `TryEnter` **refused** while open — that is the whole point of AC 1, and TP-LOG-07 asserts it;
        - a **soft cooldown** (`Unavailable`/`Timeout`/`Network`/`Unknown`, §5.3) — the breaker stays `Closed`,
          it is not a state-machine edge, and a DNS blip on every LIVE tick would write a line every 700 ms.
          The per-request line (E1.S5) already records the failure that caused it;
        - a **`BadResponse` soft strike** that does not reach 3 — same reason; the third one opens the gate and
          gets the OPEN line;
        - a **`CleanResetMinutes` strike reset** — §5.7 makes it a *save* trigger but it is not a state edge and
          it happens silently while nothing is wrong. **If Winston wants it, it is one `Info` line and one case;
          record the choice either way rather than leaving it undecided.**
        - a `Wait` from the rate ceiling (E2.S3) — sub-second, invisible, and there is one per request.
  - [x] **A `Cancelled` report touches nothing and therefore logs nothing** (§5.3, TP-GATE-12). Assert it on the
        line count, not only on the state.
  - [x] Emission happens **inside** the transition, under the gate's existing single `lock`, so two threads
        cannot interleave a transition and its line. `Logging`'s writer is itself thread-safe and never throws
        (`Logging.cs:77-92`), so this is cheap — but keep the *build* outside anything expensive: transitions are
        rare by construction (a handful per session), so simplicity wins over cleverness here.
- [x] **T3 — The HALF-OPEN line comes from `TryEnter`, and that is not a contradiction** (AC: 1)
  - [x] E2.S1's repo-trap note says *"no logging from `TryEnter`"*. That ban is on logging **per call**. The
        `Open → HalfOpen` edge happens **inside** `TryEnter` — it is the only place it can happen — and it is a

  - [x] A `Background` caller **deferred** by `ProbeDeferMs` (E2.S3) has **not** transitioned — no line. A probe

### What this story changes in files that already exist

### Rulings and decisions that apply — the rulings win over the older documents

- **R-2 / OQ-c (binding): no event out of `Services/`.** A transition line is a *write to a log*, not a
  notification. The UI learns about a gate by polling `ProviderGate.Snapshot()` at 1 Hz from the countdown timer
  (E7.S2/E7.S3). `readiness-report.md` R-2 proposes `ProviderGates.StateChanged`; the architect's ruling
  overrides it (sprint-plan note 1). Do not let "I need to know when it changes, for the log" become the
  back door that adds it.
- **U9 / E2.S7 depends on this story.** The spike's exit criterion is *"median open-window count per LIVE hour
  and the maximum strike level reached, over ≥ 3 reports covering ≥ 6 LIVE hours"* — those numbers are read out
  of **these lines**. `strikes=`, `for=` and `until=` must be greppable and consistently spelled, or the spike
  has no data. That is a design constraint, not a nicety.
- **§10.3** is what "Copy error report" then contains: both attempt lines with their jittered spacing, every
  status, `Retry-After` presence and value, the content-type, the de-tagged body head, `burst60`, `ipv`, **and

  text leaving the machine. This is what makes P2 provable instead of arguable."*

### Completion Notes List

**Where the code went, and why it is not where the File List first said.** The story proposed
`TransitionLine(...)` plus four emit points on `ProviderGate`, with `ProviderGates` as the alternative "if the
transition hook lives there rather than on the gate — state which in the PR". **The hook lives there.** E2.S4
already built the mechanism (`ProviderGates.NoteTransition`, `ProviderGates.cs:352-368`), so this story adds a
consumer and not a seam; a gate does not know its own id — the registry is the only thing that does — and
`ProviderGate`'s own contract is "no I/O, no logging" (I2/I10). So the line lives in a new sibling,
`Services/GateLog.cs`, and **`Services/ProviderGate.cs` is not touched by this story at all**.

**How the hook is installed without touching disk at startup (I10).** `ProviderGates.TransitionHook` is now a
field initialiser — `internal static Action<...>? TransitionHook = GateLog.Note;` (`ProviderGates.cs:338`).
`GateLog`'s static initialiser allocates one `LogSuppressor` and nothing else: no file, no directory, no clock.
Nothing on a startup path mentions either type — TP-START-02's source scan
(`ProviderStateStoreTests.No_startup_path_mentions_ProviderGates`) is green unchanged and its "one permitted
reference outside `Services/`" list is still exactly `MainWindow.xaml.cs: ProviderGates.Flush();`.
`ResetForTests` restores that **default** rather than nulling the hook (`:400`), so a case that stubs it cannot
leave the app's own observability off for the rest of the run.

**The line, one grammar** (`GateLog.Line`, `GateLog.cs:193-207` — pure: no clock, no I/O, `now` is an argument,
the same discipline as `RequestLog.Line`):

```
gate provider=google-dict CLOSED->OPEN      kind=RateLimited strikes=1 for=60s              until=13:30:02 reason=failure
gate provider=google-dict OPEN->HALF-OPEN   kind=RateLimited strikes=1 for=-                until=13:30:02 reason=probe
gate provider=google-dict HALF-OPEN->CLOSED kind=RateLimited strikes=0 for=-                until=-        reason=success
gate provider=google-dict HALF-OPEN->OPEN   kind=RateLimited strikes=2 for=120s             until=13:32:04 reason=failure
gate provider=deepl       CLOSED->OPEN      kind=AuthFailed  strikes=0 for=until-key-change until=-        reason=failure
gate provider=deepl       OPEN->CLOSED      kind=AuthFailed  strikes=0 for=-                until=-        reason=clear
gate provider=google-dict CLOSED->OPEN      kind=RateLimited strikes=3 for=300s             until=13:35:00 reason=reload
```

(aligned here for reading; the real lines are single-spaced.) Every token §10.2 shows is present — `OPEN`,
`HALF-OPEN`, `CLOSED`, `kind=`, `strikes=`, `for=`, `until=` — inside the `key=value` grammar E1.S5's `tr ` line
uses (`analyse-implementation-actuelle.md` §5.2-5.3: "format consistency with the request line"), with the edge
and `reason=` added so E2.S7's grep can partition the stream without inferring anything. `until=` is **local**
`HH:mm:ss` because `LogWriter` stamps `DateTime.Now` (`Logging.cs:88`); `for=` is whole seconds and `-` once the
window has elapsed — which is exactly the state a probe is granted out of. Levels are §10.2's: landing on `Open`
⇒ `Logging.Warn` (`Logging.cs:44`), everything else ⇒ `Logging.Info` (`:43`).

**Which edges get a line** (`GateLog.ReasonFor`, `GateLog.cs:110-124`) — ruling **E2-b**, written as one `switch`
so the filter reads as a list: `Closed→Open` and `HalfOpen→Open` (`failure`), `Open→HalfOpen` (`probe`),
`HalfOpen→Closed` (`success`), `Open→Closed` (`clear` — the key save of ruling E2-i; a pause *ending* is the
other half of the evidence), and `reload`. **No line** for a strike reset or an `Open→Open` escalation (the state
did not move), for a refusal or a rate-ceiling `Wait` (not transitions; they never reach the hook), or for a
soft cooldown.

**The one judgement call, recorded so a reviewer can disagree with it:** the soft-cooldown suppression covers the
**whole cycle**, not only its first edge — an edge *landing on* `Open` or `HalfOpen` whose `LastKind` is
`Unavailable`/`Timeout`/`Network`/`Unknown` is silent. T2 reasons that a soft cooldown "is not a state-machine
edge"; it is one (it sets a 5-second window and `Snapshot()` reads `Open`), which is why E2.S4's `WorthAWrite`
already had to say so in prose (`ProviderGates.cs:375-395`). Logging only its first edge would still write a
probe-grant line every five seconds for as long as a network is down. Landing on **`Closed` is never filtered**,
whatever the kind, so a soft outage that recovers still says so — "it never clears" may never be unanswerable.
Cost, taken knowingly: a real 429 episode that happens to take a timeout while already open loses its
probe-grant line (the timeout moves `LastKind` without moving the window); the `OPEN` before it and the
`CLOSED` / escalated `OPEN` after it are both still there.

**The storm valve, which T4 argued against and the architect asked for — both are right about different
patterns.** T4's reasoning holds for escalation: the ladder doubles its own window, the edges alternate, and a
`LogSuppressor` keyed by provider+edge can never fire on it, so nothing can hide `strikes=`/`for=` from E2.S7.
**One pattern repeats a single edge without bound and is reachable**: every caller granted the probe is
cancelled before it reports (LIVE switched off mid-probe — by I3 such a caller never reports at all), so the
gate re-arms one `RequestTimeoutSeconds` later and grants another, indefinitely. That is one `OPEN->HALF-OPEN`
line every twelve seconds — the 1 MB rollover evicting the incident that started it. So the valve is in, keyed
by provider+edge, reusing `LogSuppressor` (`GateLog.cs:72`) with two new optional constructor arguments,
`prefix` and `separator` (`RequestLog.cs:495-507`), so its summary is spelled in the family and the grammar of
the lines it replaces (`gate provider=google-dict OPEN->HALF-OPEN suppressed=7 in=60s (identical lines not
written)`) instead of announcing itself as a `tr ` line. E1.S5's behaviour is byte-for-byte unchanged (the
defaults are its old literals) and `RequestLogTests`' regex on the summary passes untouched.

**The fifth edge, `reload`** (E2-b), is written from `ProviderGates.EnsureLoaded` (`ProviderGates.cs:193`) and
deliberately **not** announced through `NoteTransition`: a seed is not a §5.2 transition — nothing moved, the
gate was born in that state — and announcing it as one would queue a debounced **save** on every single start,
which is the churn §5.7 refuses. E2.S4 had already exposed the seam this needed (`TrySeedState`'s return value
tells the registry which ids were really seeded), so nothing was added for it. `from` is `Closed` by
construction: `TrySeedState` only accepts a gate that has recorded nothing in this process.
